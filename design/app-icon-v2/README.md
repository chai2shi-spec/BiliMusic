## 2. 设计系统

### 2.1 两套语言，一条底线

| | 01–03 / 06–09（7 张） | 04 / 05 / 10（3 张） |
|---|---|---|
| 图形 | 纯白 `#FFFFFF` 平涂 | 白色→浅灰渐变机身 + 金属件 + 深色玻璃屏 |
| 体积 | 无（剪影） | 有（渐变 + 投影 + 高光 + 内阴影） |
| 底色 | 纯色平涂 | 同左，**一个都没改** |
| 共同底线 | 单色底 + 大面积白主体，不低于 5:1 对比 | 同左 |

**必须知道**：这两套语言放在同一屏里会「跳」——平涂是剪影，拟物是有厚度的物件。它们能共存，是因为底色与白主体的关系一致；但**不要在同一界面里混用**（例如桌面图标用拟物、设置页图标用平涂）。选一套，用到底。

### 2.2 平涂七张的铁律

| 规则 | 值 |
|---|---|
| 画布 | `1024 × 1024`，`viewBox="0 0 1024 1024"` |
| 安全框 | `192 – 832`（640 见方） |
| 图形色 | `#FFFFFF` 单色，无第二色、无渐变 |
| 结构线 | `72 – 96`，只在结构性细节用线 |
| 圆角 | 端点全圆（`rx = 高度/2`） |
| 镂空 | `mask` 真镂空（黑 = 挖掉），不用同色垫片 |
| 禁用 | 渐变 / 投影 / 描边光晕 / 文字 |

### 2.3 拟物三张的层序（照抄这套，三张才像一套）

```
① 金属件（天线 / 提手）—— 画在机身之下，根部被机身盖住
② 机身 —— 垂直渐变 + feDropShadow（近影 dy7/blur7 + 远影 dy22/blur26）
③ 顶部受光 —— 白色渐变覆盖上 1/3，opacity 0.6
④ 底部内阴影 —— 黑色渐变覆盖下 1/6，opacity 0.09
⑤ 屏幕凹槽 —— 比屏幕大 6~8px 的全黑圆角矩形，opacity 0.30
⑥ 屏幕玻璃 —— 深色渐变（带底色的暗调，不是纯黑）
⑦ 屏内发光内容 —— 品牌粉 + feGaussianBlur(15) 辉光
⑧ 顶部凹陷暗渐变 + 径向暗角 + 斜向柔光（三层叠出玻璃感）
⑨ 控制件（旋钮 / 滑轨 / 格栅 / 指示灯）
```

**四条关键数值**

- **机身的渐变一定要 `#FFFFFF → #CDCDDA`**：纯白到底会像贴纸，灰得太狠会像塑料旧了。
- **屏幕不能是纯黑**，要带底色暗调：04 `#3A2731`（偏紫）、05 `#1E3A40`（偏青）、10 `#2C3A32`（偏绿）。这样屏幕与底色「同一家族」，缩略时不会出现一个突兀的黑洞。
- **玻璃反光只能用「大面积低透明度渐变」**，不能用条状矩形：条状在深屏上会变成两道硬斜杠（第三版踩过）。
- **投影必须两层**：只有远影会「浮」，只有近影会「贴死」。

```
01 #2563EB  电蓝   02 #C2410C  橙红   03 #334155  石板   04 #B45309  琥珀   05 #0E7490  深青
06 #4338CA  靛蓝   07 #7C2D12  深棕   08 #15803D  墨绿   09 #7E22CE  紫     10 #0F766E  墨青绿
```

对比度为「白色主体 : 底色」，按 WCAG 相对亮度计算，全部 ≥ 5.0:1（图形类门槛 3:1，留余量是为了 32px 边缘抗锯齿不掉清晰度）。

**与第一组的关系**：第一组是品牌粉 `#FB7299` 底（带播放三角的加深到 `#C2185B`），本组刻意不用粉作底。要换回品牌粉，把底 `rect` 的 `fill` 换掉即可，图形完全不动。

### 4.1 拟物三张的色板

| Token | 值 | 用在哪 |
|---|---|---|
| 品牌粉 | `#FB7299` | 屏内可视化、指示灯、滑轨把手 |
| 深粉墨 | — | 本版未使用（上一版用它画五官 / 黑键） |
| 机身白 | `#FFFFFF → #CDCDDA` | 机身垂直渐变 |
| 金属灰 | `#9E9FB0 → #FFFFFF → #8C8D9E` | 天线、提手（横向渐变做圆柱反光） |
| 屏幕暗调 | 04 `#3A2731` / 05 `#1E3A40` / 10 `#2C3A32` | 屏幕玻璃，随底色偏色 |
| 玻璃反光 | 白，opacity 0.085 → 0 | 斜向大面积渐变 |

**深色玻璃 + 粉色发光**是这三张的识别核心：屏幕越暗，粉柱越亮。别把屏幕调亮，那样会失去 CRT 的「暗室里发光」感。

**一个取舍**：拟物图标用了 5~6 个色值（白、浅灰、金属灰、深玻璃、品牌粉），比平涂七张的「2 色」复杂得多。这是拟物的代价，也是它好看的原因。若要求极简，回到 §2.2 的平涂方案。

## 6. 已做的校验

- **位图**：`icon-*` = `1024×1024 / colorType 2（RGB）/ 角点 = 底色`；`fg-*` = `1024×1024 / colorType 6（RGBA）/ 角点 α=0`。十张全过。
- **防错位**：同编号的 `icon-*` 白像素数与 `fg-*` 白像素数（α>128 且 RGB 均 >240）逐一比对，最大差 **1.25%**（02 细环抗锯齿），其余 ≤0.8%。真错位会是几十个百分点。
  - ⚠️ **判据必须「两份都数白」**：拟物三张的 fg 里有半透明投影与彩色屏幕，若按「不透明像素」去比会假报错位。
  - ⚠️ **白像素下限要跟着设计改**：拟物图标机身是渐变，只有上半接近纯白，10 只有 2.5 万白像素——沿用平涂时代的 4 万门槛会误判失败。
- **投射**：灰底并排复核三张 `fg-*`，投影是半透明柔影（不是硬黑块、也不是消失），屏幕与粉色内容完全不透明。
- **小尺寸**：`preview.png` 里 176 / 48 / 32 三档并排逐个复核。
- **镂空**：平涂七张的 `mask` 镂空在灰底上全部真透出底色（吉他已移除，现为音箱单元 / 黑胶沟槽与轴孔 / 耳机头梁空心）。

## 7. 接入 HarmonyOS（三层图标）

工程用 `layered_image` 三层体系，只动 `AppScope/resources/base/media/`：

```
app_icon_fg.png   ← fg-XX-*.png（1024，透明）
app_icon_bg.png   ← 纯色底（1024）
layered_image.json ← 不用改
```

- **平涂七张**：`app_icon_bg` 用 SVG 里那个底色平涂即可。
- **拟物三张要特别注意**：`fg-*` 里已经带了**投影**。若 `bg` 是纯色，投影会投在纯色上，效果正确；但**不要**把 `icon-*` 直接当 `bg`（图形叠图形）。
- 系统按桌面圆角遮罩裁切，SVG 里不要自己画圆角外框（本组都没有）。
- 替换后回 DevEco → Project Structure → Signing Configs 重签，否则 `SignHap` 报 `00303074`。

## 8. 使用规范

| 场景 | 尺寸 | 用哪张 |
|---|---|---|
| 桌面 / 应用市场 | 1024（系统缩） | `icon-*` 或 fg + bg |
| 应用内品牌位 / 关于页 | 96 – 176 | `icon-*` |
| 列表 / 设置页图标位 | 48 | `icon-*` |
| 角标 / 状态栏 | 32 | 优先 01 / 02 / 06 / 07 / 08 |

**状态派生**

| 状态 | 平涂七张 | 拟物三张 |
|---|---|---|
| 默认 | 原样 | 原样 |
| 按压 | 底色压暗 8% | 整体亮度降 6%（`filter: brightness(.94)`），别改底色 |
| 选中 | 图形提亮 + 0.5vp 同色描边（深底才加） | 屏幕辉光加强（把 glow 的 blur 减半），别加描边 |
| 禁用 | 去饱和 30% + 透明度 40% | 同左 |

**命名**：`icon-{两位序号}-{kebab-case 语义}.png`，前景加 `fg-`。SVG 内部 `id` 用语义（`bar-1` / `screen-well` / `knob-left` / `antenna-left`），不用 `path1`。

## 9. 已淘汰的十三案（记录原因）

### 9.1 平涂阶段的误读（第一、二轮）

| 曾用方案 | 症状 | 结论 |
|---|---|---|
| 唱盘（唱片 + 唱臂） | 唱臂 + 轴 = **放大镜压在唱片上**，且与黑胶重复 | 淘汰 |
| 磁带（机身 + 两卷盘 + 横槽） | **两个圆孔 + 一道横槽 = 机器人脸** | 淘汰 |
| 心形声波（心 + 折线） | **心形 + 折线 = 心率 / 健康 App** | 淘汰 |
| 耳塞（两版） | 正圆 + 细柄 = **棒棒糖**；收腰 + 粗柄 = **勺子 / 鸡腿** | 淘汰 |
| 唱片封套（三版） | 方 + 圆 = **相机**；放大盘后，靠 stroke 切缝留下**脏缺口** | 淘汰 |

### 9.2 第三轮「小电视 + 屏内乐器」

| 曾用方案 | 症状 | 结论 |
|---|---|---|
| 吉他 + 小电视（把屏 / 双眼 / 天线塞进琴身） | **方屏 + 双眼 + 两根天线 = 兔子头** | 淘汰 |
| 吉他 + 双粉色音孔（当 B 站的眼） | 两个粉椭圆落在琴身中段，整把琴变**动物 / 小人的脸** | 淘汰 |
| 吉他本体（正放 / 斜置 38° / 缩琴头，共六版） | 正放像**葫芦 / 小人**；斜置像**棒棒糖 / 球拍**；缩放不改变结论 | 淘汰（改「小电视 + 屏内吉他」，后又被第四轮推翻） |
| 音叉 + 三条漂浮弹幕 | 三条短横杠与主体无关，读成**散落零件** | 淘汰 |

### 9.3 第四轮「小电视 + 表情」

| 曾用方案 | 症状 | 结论 |
|---|---|---|
| 小电视微笑 / 唱歌 / 眨眼三态 | 五官是「卡通脸」，在 32px 全丢；且三张只差一个嘴形，辨识度靠外形比例硬撑 | 淘汰（用户判定「太丑」） |

### 9.4 本轮（拟物）中间态

| 曾用方案 | 症状 | 结论 |
|---|---|---|
| 04 天线用「金属渐变 + 粉」 | 中段串进粉色，天线像「糖棍」 | 改纯金属三段渐变 |
| 04 屏幕反光用两条斜矩形 | 深屏上变成**两道硬白斜杠**，像屏幕裂了 | 改大面积低透明度渐变 |
| 05 提手用 `stroke` 圆弧 | 像**塑料环 / 提篮把手**，没有厚度 | 改 `evenodd` 实心带（外拱 − 内拱） |
| 05 屏幕用折线波形（5 个尖峰） | 读成**心电图 / K 线** | 改三段平滑贝塞尔 |
| 10 机身 448×528 | 与 04 的 1:1 差别太小，缩略时几乎一样 | 收到 400×520（0.77） |

### 9.5 四条跨轮次的总教训

1. **单色图标的语义由外轮廓决定，内部细节在 32px 全丢。** 「两个圆 + 一条横线」永远先被读成脸；「多层同心圆」永远是靶心；「一圆 + 一柄」永远是糖果或餐具。
2. **在有「身体感」的主体上，任何点状色块都会变成眼睛。** 头 + 细颈 + 圆身 = 一张脸或一个人；想放品牌元素只能放「面」（整块屏、整块外壳），不能放「点」。
3. **拟物不是「加渐变」，是「层序」。** 机身渐变、顶部受光、底部内影、屏幕凹槽、玻璃三层、投影两层——少一层就塌成贴纸。反过来，层数堆错（例如把反光做成硬条）比不做更脏。
4. **屏幕/外框的比例要按内容定。** 横屏塞竖物会被压成一小块；方形屏才能让主体占满 83% 高度。

## 11. 明确不做

- **不做**圆角外框（系统遮罩负责，自己画会双重圆角）
- **不做**深浅两套图标（App 图标不随系统主题变）
- **不做**图标内文字（48px 以下必糊，且不利于本地化）
- **不做** B 站官方 logo 的复刻：本组小电视是原创几何造型（圆角机身 + 双外张天线 + 球头 + 深色玻璃屏 + 旋钮），不使用任何官方素材、字形或红蓝配色
- **不做** PNG 以外的位图导出（要别的尺寸从 SVG 重导，别缩放 PNG）
- **不做**「为拟物三张补齐表情或乐器」——第五轮已经明确砍掉，加回去就退回第三、四轮的失败形态
- **不做**把十张混在同一界面使用（见 §2.1）
