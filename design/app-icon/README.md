## 3. 逐案说明

### ★ 01 · 声波柱 Wave Bars

- **设计依据**：这个 app 的核心不是播视频，而是**从 B 站视频里提取音频**（`extractAudioFromVideo`）。声波是它真实的产品本质。
- **做法**：四根白色圆头竖条，高度 208 / 464 / 512 / 320，重心落在画面中心。
- **配色**：底 `#FB7299`（主粉）／图形 `#FFFFFF`
- **优点**：**小尺寸表现最好**，16px 仍有形；现代、干净；天然适合做启动动画（四根柱依次起伏）。
- **缺点**：与 Spotify / SoundCloud 一路的声波语言接近，辨识度靠颜色而非形状。
- **适合**：**综合推荐**，尤其是要长期在桌面小尺寸出现。

### 02 · 耳机 Headphones

- **设计依据**：收听本身。剪影完整、左右对称，是人眼最敏感的形状之一。
- **做法**：头带半圆弧（r=230，描边 76）+ 两个圆角耳罩（150×250，圆角 75）。
- **配色**：底 `#FB7299`／图形 `#FFFFFF`
- **优点**：**四案里剪影最完整**，任何尺寸都清晰；识别速度最快（耳机是强形状记忆）。
- **缺点**：音乐类 app 最泛滥的符号之一；完全没有 B 站属性。
- **适合**：要最大众化、零学习成本的路线。

### 03 · 音频环 Audio Ring

- **设计依据**：现有图标就是「环」，这是唯一已有用户认知的资产，直接延续，改动成本最低。
- **做法**：环在正下方开一道 30° 的切口（音轨开口），环心放播放三角。
- **配色**：底 `#C2185B`（深粉）／图形 `#FFFFFF`
- **优点**：与现有图标一脉相承，用户不会觉得"换了个 app"；32px 仍可辨认。
- **缺点**：切口让环读作"未闭合"，抽象度仍高，看不出与 B 站相关。
- **适合**：不想动品牌认知、只求补上音乐语义。

### 04 · 黑胶 Vinyl

- **设计依据**：`PlayBar.ets` 里那个 `iterations: -1` 的常驻旋转圆盘 —— app 内已经有"唱片会转"的视觉语言，图标与之一致。
- **做法**：白色唱片 + 三道浅粉沟槽（`#F7B8C9`）+ 粉色中心标签 + 白播放三角。
- **配色**：底 `#C2185B`／盘 `#FFFFFF`／沟槽 `#F7B8C9`／标 `#FB7299`
- **优点**：音乐语义最强，一眼知道是播放器；中心标签恰好是 `lightColor` 主题色的位置，可做变体。
- **缺点**：**48px 以下沟槽开始糊**，32px 退化为"粉点白圆"，桌面小图标不推荐。
- **适合**：应用商店主图、关于页、启动页等大尺寸场景。

⚠️ **04 的底色不能换成主粉 `#FB7299`** —— 沟槽色 `#F7B8C9` 是浅粉，只有在深粉底上才有层次；换主粉底后沟槽与底明度太近，会糊成一片白盘。这案是唯一「底色被图形绑死」的方案。

## 4. 小尺寸表现对照

| 方案 | 190px | 48px | 32px | 结论 |
|---|---|---|---|---|
| **★ 01 声波柱** | 清晰 | 清晰 | **清晰** | 全尺寸最佳 |
| **02 耳机** | 清晰 | 清晰 | **清晰** | 全尺寸最佳 |
| **03 音频环** | 清晰 | 清晰 | 可辨 | 全尺寸可用 |
| **04 黑胶** | 清晰 | 沟槽开始糊 | 退化为色块 | **仅大尺寸** |

**01 与 02 是仅有的两枚 32px 仍完全清晰的方案**，共同点是「单一闭合轮廓 + 无细碎内部结构」。03 的 32px 仍能看出是环+三角，属"可辨"；04 的沟槽在 32px 糊成一片，只剩一个白圆 —— 这是它唯一但也是致命的短板。

鸿蒙桌标常见显示尺寸约 48~72vp，应用商店列表还要更小。**04 在这个环节吃亏最明显**，如果最终选它，需接受"桌面小图看不到唱片纹理"。

## 5. 技术规范

| 项 | 值 | 说明 |
|---|---|---|
| 画布 | 1024 × 1024 | 与现有 `app_icon_fg/bg` 一致 |
| viewBox | `0 0 1024 1024` | 四案统一 |

| 描边 | 严格等比 | 仅 02 的头带使用描边（76），其余为纯填充 |

| 01 声波柱 | `#FB7299` |
| 02 耳机 | `#FB7299` |

1. 选一个方案（建议 01 或 02，见第 8 节）。
2. 把该案 `fg-0X-*.png` 复制成两份，覆盖：
   - `entry/src/main/resources/base/media/app_icon_fg.png`
   - `AppScope/resources/base/media/app_icon_fg.png`
3. 背景层用该案背景色生成一张 1024×1024 纯色 PNG，同样覆盖两处的 `app_icon_bg.png`。
4. `layered_image.json` **不用改**，它已经指向这两个文件。
5. 若同时更新 `app_icon.png`（非分层兜底），用 `icon-0X-*.png` 覆盖。
6. 回 DevEco 重新编译，在「主题」预览里分别看圆角方形 / 圆形 / 水滴三种遮罩下的效果。

## 7. 主题色决策（必须先定）

工程里有 8 套主题色（`common/ThemeColors.ts`：粉红橙黄绿青蓝紫）。但**桌面图标只能有一套** —— 系统不支持图标随应用内设置变化。

| 做法 | 效果 | 建议 |
|---|---|---|
| **固定品牌粉**（推荐） | 无论用户选什么主题，桌面图标都是粉 | 品牌一致性最好；界面内主题色照常生效 |
| 跟随当前主题 | 需要动态生成图标资源，鸿蒙不支持 | 不可行 |
| 提供多套图标包让用户选 | 需在设置页做"图标包"，工作量翻倍 | 除非做主题商店，否则不值得 |

**推荐固定粉**，理由：8 套主题是「界面配色」，图标是「品牌资产」，两者层级不同。用户不会期望换个界面配色就换 logo。

配套建议：在「关于页」或「启动页」用当前主题色渲染一次 logo，让用户感觉到"你的主题被尊重了"，而桌面图标保持品牌固定。

| 贴产品本质 | **01 声波柱** |

## 9. 禁止项

1. **不要使用 bilibili 官方小电视 logo** —— 那是注册商标，任何相似度都会带来风险。本套方案刻意不碰任何 B 站受保护图形。
2. **前景层不能带背景色块** —— 必须是透明 PNG。带底色会导致分层图标在系统遮罩下出现双层色块。
3. **不要自己画圆角** —— 圆角由系统按设备遮罩生成，自己画会在圆形遮罩下露出直角。
4. **不要在图标里加阴影、发光、外描边** —— 系统遮罩会把它们裁掉，且小尺寸下变脏。
5. **不要把 04 黑胶用在小尺寸位**（桌面、通知栏、市场列表）。
6. **不要把 04 的底色改成主粉**（见 §3 说明）。
7. **不要用 8 套主题色做 8 套图标** —— 桌面只能显示一套，多做只会让用户困惑。
8. **不要给自己画的图形加描边来"加粗"** —— 描边是**向外**扩张 stroke/2。03 音频环最初就踩过：三角描边 34 把图形撑到贴着圆环，尺寸全错。算外接框时必须把描边算进去。

## 10. 已淘汰的方案与被否掉的方向（供后续维护参考）

保留四案之外，本轮一共否掉了 6 个成型方案和 4 个方向。**下表编号均为重编号前的原编号**（与 `_archive/` 内文件名一致），与正文新编号无关：

| 尝试（原编号） | 结果 | 废弃原因 |
|---|---|---|
| 04 弹幕音符 | 已归档 | 元素最多、理解成本高；32px 时三条弹幕线会黏在一起 |
| 05 字母标 B | 已归档 | 策略保守、缺音乐直观感；与 06 同属"没有形状个性"一类 |
| 06 反白播放块 | 已归档 | 误读率最低，但也**最没有个性** —— 换成任何一家播放器都成立 |
| 07 扬声器 | 已归档 | **与系统音量图标高度相似**，作为品牌标识缺独占性 |
| 08 话筒 | 已归档 | 读作"录音 / 播客"，与"播放"有轻微错位 |
| 10 心形声波 | 已归档 | 可能被读作"社交 / 恋爱类"app；三根竖条在 32px 退化成一个点 |
| 07 径向声波（16 根放射条 + 中心圆） | 废弃 | 读作**太阳 / 爆炸**。放射状 + 中心圆是"发光"的经典构图，无论怎么调长度比都逃不掉 |
| 07 磁带（横向框 + 两个圆轮） | 废弃 | 读作**护目镜 / 两只眼睛**；加中心轴孔后**更像眼睛**（白眼球 + 深瞳孔） |
| 08 逐字歌词（三行横条） | 废弃 | 读作**三条杠 / 列表**；加字块缝隙后变成"加载进度条" |
| 10 迷你播放栏（横胶囊 / 圆角方块 + 圆盘 + 两线） | 废弃 | 胶囊读作**开关**，方块读作**相机 / 相册**（"圆 + 两线"是相机图标的固定语法） |

两条可复用的教训：

1. **隐喻要看"形状语法"是否被占用**，不只看语义是否贴切。"径向放射"已被"发光"占用、"双圆并排"已被"眼睛"占用、"圆 + 两线"已被"相机"占用 —— 语义再对也没用。这也是保留四案全部避开这些语法的原因。
2. **同族方案不要超过两个**。这轮里"带播放三角"的一度有 03 / 06 两案、"圆形盘面"有 03 / 04，"竖条"有 01 / 10 声波 —— 三组都控制在两个以内，否则第三个没有存在价值。

## 11. AI 批量生成时的提示词模板

若后续要基于这套风格批量出变体（节日版、活动版），用这段保持不漂移：

```
设计一个移动应用启动图标，画布 1024x1024，正视角、正面平铺、无透视、无阴影、无发光。

构图：单一主体居中，占画面 60~70%，四周留白均匀。
风格：极简几何、纯色平涂、边缘锐利、圆角统一（半径约为线宽的 0.5 倍）。
线条：不使用细线（最小线宽不低于画布宽度的 6%），保证 32px 缩略仍可辨。
配色：仅两色。背景 {BASE_COLOR}，主体 {MARK_COLOR}。禁止渐变、禁止第三色。
主体：{SUBJECT_DESCRIPTION}
禁用元素：文字、数字、阴影、高光、描边光晕、3D、拟物纹理、水印、外框。

输出要求：纯向量路径，可缩放，不依赖位图效果。
```

把 `{BASE_COLOR}` / `{MARK_COLOR}` / `{SUBJECT_DESCRIPTION}` 换成具体值即可。当前这套用：

- `{BASE_COLOR}` = `#C2185B` 或 `#FB7299`
- `{MARK_COLOR}` = `#FFFFFF`
- `{SUBJECT_DESCRIPTION}` = 例如「四根高度不同的圆头竖条，构成声波」

⚠️ AI 生成后必须审校三件事：路径是否闭合、线宽是否与既定值一致、是否偷偷加了渐变或阴影。
