## 0. 先划清边界

下载页是**二级页**（`HdsNavDestination`），从歌单页标题行右侧的 `DownloadsIconButton`（↓ 图标 + 角标）进入。
这不是「第四个 tab」——`DownloadsEntryRow` 已经删除，列表第一行不再有下载入口。

因此两个页面的**顶部结构天然不同**：

| | 歌单一级页（tab 页） | 下载页（二级页） |
|---|---|---|
| 顶部 | 根栏 `tabTitleRow`，无返回键 | HDS 标题栏，**有返回键 44vp** |
| 标题 | `歌单` + 副行「7 个歌单 · 271 首」 | `下载`，**无副行** |
| 右侧 | [↓][+][⋮] 三个 36×36 图标钮 | [选择][全部开始][全部暂停] **三个 13fp 文字胶囊** |
| 底部 | 悬浮页签胶囊 72vp | 无（列表末端 `contentEndOffset`） |
| 首屏 | 620 可用 / 84 行高 = **7.4 行** | 692 可用 / 84 行高 = **8.2 行** |

**首个结论（先破除一个常见误判）：下载页不是「太挤」，行数比歌单页还多 1 行。
它的问题全在「信息怎么说」，不在「能放多少」。**

## 2. 六个诊断

### D1 · 标题行是「另一个 App 的语言」（P0）

歌单页标题行已经是「20fp 标题 + 11fp 统计副行 + 三个 36×36 图标钮（含品牌实底主 CTA）」。
下载页还是「三个 13fp 文字胶囊」，且：

- **没有统计副行**：进页面看不到「一共几首、占多少空间、几个在下载」。这恰恰是下载页最该先回答的三个问题。
- **两个粉字按钮分不清能不能点**：`DlQueueActions` 的字色是**无条件品牌粉**（`:163 / :177`），可用性只由底色表达（浅粉 = 可用 / `bg_divider` = 不可用）。两个都是粉色 → 用户要试才知道哪个是死的。
- 三个文字胶囊实测宽度：`选择` 46 + `全部开始` 72 + `全部暂停` 72 + 间距 16 = **206vp**，占标题行可用宽度的 63%。

### D2 · 「下载中」那行必然被截，且截掉的正是最精确的进度（P0，实测）

按 13fp（中文 13.0 / 数字拉丁 7.2 / 空格 3.6）逐字算宽度：

| 文案 | 宽度 | root 360 可用 **216** | nested 360 可用 **188** | root 391 可用 **247** |
|---|---|---|---|---|
| `已完成  ·  320kbps  ·  8.4MB` | 169 | ✓ | ✓ | ✓ |
| `下载中 42%  ·  1.2 MB/s  ·  3.4MB/8.0MB` | **241** | **✗ 溢 25** | **✗ 溢 53** | ✓ |
| `下载中 100%  ·  1023.55 KB/s  ·  8.4MB/8.4MB` | **277** | ✗ | ✗ | **✗ 溢 30** |

- 可用宽度 = 360 − 16(左) − 64(封面) − 12(间距) − 44(⋯) − 8(右 pad)
- `maxLines(1)` + `Ellipsis` 会**从末尾裁**，而末尾是 `3.4MB/8.0MB` —— 被吃掉的正是「已经下了多少」。

**为什么一直没被发现**：当前真机是 391vp 档，典型情况 241 < 247 **刚好塞得下**，只在速度进到 KB/s 三位数（277）时才露出来；而 360vp 档（1080/3）的机器上，典型情况就已经溢出。

### D3 · 组头没有任何「可展开」的视觉（P0，真问题）

合集卡 / 歌单卡点一下就展开分 P 子行，但**整行找不到任何箭头、chevron 或其他暗示**。
现在的唯一区分是状态行开头的文字「3 个分P ·」/「5 首 ·」——既弱又和标题重复（见 D6）。

对比歌单详情页：一切可点开的区块都有 `chevron_forward` / `chevron_down`。这是全 App 唯一一个「能点开但看不出来」的列表。

### D4 · 多选态在 360 屏溢出（P1）

`DlSelectToggle` 的 5 个文字按钮（`:61-117`）：

```
完成 46 + 全选 46 + 重试 46 + 加入歌单 72 + 删除 46 + 间距 8×4 = 288vp
+ 返回键 44 + 左 padding 20 + 右 padding 16 = 368vp
```

| 屏宽 | 结果 |
|---|---|
| 360 | **✗ 溢 8vp**（标题已被清空到 0，仍不够） |
| 391 | ✓ 余 23vp（当前真机，所以没暴露） |
| 412 | ✓ 余 44vp |

而且标题被清成空串后，用户进入多选**完全不知道自己在哪一页**（歌单页是「已选 N」）。

### D5 · 空态是「三行说明文」，不是「行动指引」（P1）

歌单页空态：16fp 主文案 + 13fp 副文案 + **三个 260×44 按钮**（主 CTA 品牌实底）。
下载页空态：三行纯文字，其中两行折行贴边，且没有说清「去哪下、怎么下」。

### D6 · 组头文案有 bug：数字说了两遍、量词用错（P1）

`groupStatusText()`（`:966-999`）：

```js
const prefix = g.isCollection ? `${total} 个分P  ·  ` : (isPlaylistCard(g) ? `${total} 首  ·  ` : '');
if (c.done === total) {
  return `${prefix}已完成 · 共 ${total} 首`;
}
```

实际输出：

| 组类型 | 全部完成时的文案 | 问题 |
|---|---|---|
| 歌单卡（5 首） | **`5 首  ·  已完成 · 共 5 首`** | 「5」出现两次，「首」出现两次 |
| 合集（3 个分P） | **`3 个分P  ·  已完成 · 共 3 首`** | 分 P 用「首」量词错误，且「3」出现两次 |

「整张歌单下完」是最常见的场景，所以这是用户每次都会看到的一句。

未完成态同样重复：`5 首  ·  下载中 42%  ·  1.2MB/s  ·  已下载 2/5` —— 「5 首」和「2/5」是同一件事。

## 3. 设计原则：把「状态」从句子提成徽章

歌单页那一轮做的核心动作是**「来源」从句子提成徽章**：

```
改前：32 首 · 同步自 某某某的收藏夹        ← 来源藏在句子里、长 UP 名被省略
改后：[收藏夹] 32 首 · 2 小时 18 分       ← 来源 0.2 秒可辨
```

下载页要做的是**完全同构的一件事**：

```
改前：下载中 42%  ·  1.2 MB/s  ·  3.4MB/8.0MB     ← 状态词占 39vp，挤掉最精确的进度
改后：[42%]  1.2 MB/s · 3.4MB/8.0MB               ← 状态变徽章，副行只剩数据
```

这一条同时解决 D2（截断）、D3（组头无区分）、D6（文案重复）：
**状态进徽章后，「状态词 + 数字 + 量词」那串重复的话就不需要存在了。**

徽章与歌单页「收藏夹」徽章**同一套规格**（11fp / 高 18 / 圆角 9 / 左右 padding 6），所以两页并排看是一家人。

## 4. 方案 A · 信息层重构（零风险，不动任何几何）

### 4.1 标题行

```
┌─ HDS 标题栏（safeTop + 56）────────────────────────────────┐
│  ←   下载                        [⏸]  [☑]  [⋯]            │
│      23 首 · 1.24 GB · 2 个下载中                          │  ← 11fp 三级色
└────────────────────────────────────────────────────────────┘
```

| 元素 | 规格 | 与歌单页的对应 |
|---|---|---|
| 主标题 | 20fp Bold，不变 | 同 |
| **统计副行（新增）** | 11fp / `lineHeight(15)` / `text_tertiary` / `margin-top 1` | **与 `plSubtitle` 逐字同规格** |
| 队列启停 | 36×36 / 圆角 10 / `themeSurface` 浅底 + `themePrimary` 18 号图标 | 与 `PlTitleActions` 图标钮同规格 |
| 选择 | 同上，图标 `list_checkmark` | 同 |
| 更多 | 同上，图标 `more`，`bindMenu` | 同 |

**副行文案**：`${doneCount} 首 · ${sizeText} · ${activeCount} 个下载中`
- 后段仅在 `activeCount > 0` 时拼接
- 实测宽度（11fp）：`23 首 · 1.24 GB` = **78vp**；追加 `· 2 个下载中` = **143vp**
- 360 屏可用宽度 = 360 − 44(返回) − 20(左) − 124(3 图标+间距) − 16(右) = **156vp** → 143 塞得下（余 13）

> ⚠️ **`sizeText` 是新函数，不能复用 `mbText`**：`mbText` 固定输出 MB（`:95`），1.24GB 会显示成 `1269.8MB`。
> 新增：`< 1024MB` 用 MB（1 位小数），否则 GB（2 位小数）。
> ⚠️ **口径要说清**：这里是 `Σ totalBytes`（只算 `COMPLETED`），与设置页 `cacheText`（`DownloadSettingsPage:180` 用 `taskpool` 递归统计三个目录）**是两个不同的量**，不要互相替代——设置页那个是「临时缓存」，明说了「已下载歌曲不受影响」。

**队列启停做成二态单按钮**（解决 D1 的两个粉字分不清）：

| 队列状态 | 图标 | 底色 | 点击 |
|---|---|---|---|
| 有进行中 / 排队中 | `pause_fill` | `themeSurface`（可用） | 全部暂停 |
| 无进行中、有已暂停 | `play_fill` | `themeSurface`（可用） | 全部开始 |
| 两者皆无（全完成/全失败） | `play_fill` | `bg_divider` + 图标 `text_disabled` | 无 |

符号已在 `sysResource.js` 符号表核实：`pause_fill` ✓ `play_fill` ✓ `list_checkmark` ✓ `chevron_down` ✓。

**多选态**（解决 D4）：

```
←  已选 3                    [全选] [完成] [⋮]
```

- 标题改为 `已选 ${n}`（20fp Bold），不再清空
- 右键「重试 / 加入歌单 / 删除」收进 ⋮ 菜单（与 `PlTitleActions.selectMenuItems` 同款，`enabled` 门控：无选中置灰、无失败项「重试」置灰）
- 宽度：44 + 20 + 「已选 3」约 60 + 124 + 16 = **264vp** < 360 ✓ 余 96

### 4.2 行：状态进徽章

```
                                  改前                          改后
┌──────┬──────────────────────┐  ┌──────┬───────────────────────┐
│      │ 夜航星            ⋯  │  │      │ 夜航星          [42%] ⋯│
│ 封面 │ 下载中 42% · 1.2MB/s │  │ 封面 │ 1.2 MB/s · 3.4MB/8.0MB│
│      │ ━━━━━━░░░░░░░░░░     │  │      │ ━━━━━━░░░░░░░░░░       │
└──────┴──────────────────────┘  └──────┴───────────────────────┘
        文字区 241vp 溢出 25           副行 153vp 通过（余 35）
```

**徽章挂在标题行右端、⋯ 左侧**（不是副行里）。理由：徽章在标题行时，标题、状态、更多按钮构成一条视觉基线，副行整行留给数据；徽章在副行会打断「速度 · 体积」的阅读节奏。

| 状态 | 徽章文案 | 底色 | 字色 |
|---|---|---|---|
| 下载中 | `42%`（进度取整） | `themeSurface` | `themePrimary` |
| 已暂停 | `暂停` | `bg_divider` | `text_secondary` |
| 排队中 | `排队` | `bg_divider` | `text_tertiary` |
| 失败 | `失败` | `state_error` @ 12% | `state_error` |
| 已完成 | **不显示** | — | — |
| 文件丢失 | `丢失` | `state_error` @ 12% | `state_error` |

> 「已完成不显示徽章」是刻意的：下载页里 90% 的行是已完成，一屏 8 个绿色「✓」只会变成噪音。
> 默认态不装饰，异常态才突出——这与全局「灰阶三档、粉色只给大字与图标」的克制一致。

**副行文案**（改后，去掉状态词与重复数字）：

| 状态 | 副行 | 实测宽度（root 216 / nested 188） |
|---|---|---|
| 下载中 | `1.2 MB/s · 3.4MB/8.0MB` | 153 ✓ / ✓ |
| 下载中（最坏） | `1023.9 KB/s · 8.4MB/8.4MB` | 197 ✓ / **✗ 溢 9**（末尾体积被省略，可接受） |
| 已暂停 | `3.4MB/8.0MB` | 79 ✓ / ✓ |
| 排队中 | `等待开始` | 52 ✓ / ✓ |
| 已完成 | `320kbps · 8.4MB` | 116 ✓ / ✓ |
| 失败 / 丢失 | 错误文案（不变） | — |

**徽章的宽度成本**（原型渲染实测，不是估算）：

| 组合 | 标题可用宽度（root 216 起） |
|---|---|
| 只有状态徽章（`42%` 35vp + 间距 6） | **175** |
| 状态徽章 + 类型徽章 + 箭头（35 + 34 + 16 + 间距 12） | **150** |
| nested 子行只有状态徽章（188 起） | **147** |

16fp 标题从 13 个汉字降到 10–11 个字。**2 行的标题本来就会省略，这个代价值得**；真机验收时用最长真实标题（≥20 字）确认两行内可读。

### 4.3 组头：类型徽章 + 展开箭头（解决 D3 / D6）

```
┌──────┬───────────────────────────────────────┐
│      │ 夜航星 2026 精选集  [歌单]        ⌄  ⋯│
│ 封面 │ 已缓存 5 首 · 42.1MB                   │
└──────┴───────────────────────────────────────┘
```

| 元素 | 规格 |
|---|---|
| 类型徽章 | `歌单` / `合集`，与状态徽章同规格（11fp/18/9/pad6），中性底色 + `text_secondary` |
| 展开箭头 | `chevron_down` 16 号 / `text_tertiary`；收起态 `rotate({ angle: -90 })`，展开态 0°；`animation 200ms EaseOut` |
| 组状态行 | 重写 `groupStatusText`（见下） |
| 子行缩进 | 保持 left 44，**新增左侧 1.5vp 竖线**（`bg_divider`，从组头底部到末子行），让「从属关系」看得见 |

**`groupStatusText` 重写**（修 D6）：

```js
// 完成态：不再重复数字
if (c.done === total) {
  return g.isCollection ? `已缓存 ${total} 个分P · ${sizeText}` : `已缓存 ${total} 首 · ${sizeText}`;
}
// 未完成态：规模只在「已下载 x/N」里出现一次
const parts = [];
if (c.downloading > 0) { parts.push(`${pct}%`); if (sp > 0) parts.push(speedText(sp)); }
else if (c.pending > 0) { parts.push(this.queuePaused ? '已暂停' : '排队中'); }
else if (c.paused > 0)  { parts.push(pct >= 0 ? `已暂停 ${pct}%` : '已暂停'); }
parts.push(`已下载 ${c.done}/${total}`);
if (c.failed > 0) { parts.push(`${c.failed} 个失败`); }
return parts.join(' · ');
```

| 合集全完成 | `3 个分P · 已完成 · 共 3 首` | `已缓存 3 个分P · 28.6MB` |
| 歌单卡下载中 | `5 首 · 下载中 42% · 1.2MB/s · 已下载 2/5` | `42% · 1.2MB/s · 已下载 2/5` |

## 5. 方案 B · 未完成置顶（改一行比较器）

下载页的组序只有一条规则：`createdAt` 倒序（`buildGroups:836`）。于是「刚才失败的那首」和「三个月前下的」混在一列，只能靠滚。

**改法**（不动列表结构、不动 `onMove`、不动段标题）：

```js
groups.sort((a, b) => {
  const ua = (a.counts.downloading + a.counts.pending + a.counts.paused + a.counts.failed) > 0 ? 0 : 1;
  const ub = (b.counts.downloading + b.counts.pending + b.counts.paused + b.counts.failed) > 0 ? 0 : 1;
  if (ua !== ub) return ua - ub;                       // 未完成在前
  return b.tasks[b.tasks.length - 1].createdAt - a.tasks[a.tasks.length - 1].createdAt;
});
```

- **手动拖动序优先**：`manualGroupOrder.length > 0` 时跳过上面这段（用户显式排过的顺序不该被自动打乱）
- 段内仍「新在前」，符合原观感
- 零布局变化、零高度成本

> **为什么不加「正在下载 · 2」这样的段标题**：加段标题要在 `ForEach` 里插入非 `DownloadGroup` 的 `ListItem`，
> 而 `onMove(from, to)` 的下标是限定在 `this.groups` 内的（`:2299` 注释）——插段标题会让下标错位、拖动删错组。
> 收益（半行的视觉分隔）不值得这个风险。徽章 + 置顶已经足够表达。

## 9. 风险与红线

1. **ForEach key 是这页最脆的地方**（`:14-26` 文件头）。加徽章只改 `itemGenerator` 内部的渲染分支、**不新增 key 维度**：徽章内容完全由 `t.status` / `percent()` 决定，两者都已在 `rowKey` 里（`status` + 5% `bucket`）。**不要为了「徽章文案变」去动 key。**
2. **快照隔离**：副行统计（`dlSubtitle`）要读 `this.tasks`，而 `tasks` 是 `@StorageLink`，5Hz 快照会让**整页重排**。做法：副行只订阅 `totalBytes` 聚合值，且**用 `@State dlStatsText` 在 `applyTasksSnapshot` 里算好再赋值**（值没变就不赋值 → 不触发重渲染）。**绝不能在 `dlBar()` 里直读 `this.tasks` 做 `reduce`**——那会让标题行每 200ms 重算一次。
3. **多选态动画**：`DlSelectToggle` 的 5 按钮组带 `transition(OPACITY 250ms)`。换成 `⋮` 菜单后要保留同样的进/出场过渡，否则多选进出会「闪一下」。
4. **二态图标钮不能丢可用性表达**：`DlQueueActions` 现在靠底色区分可用/不可用，改成图标钮后**必须保留**（不可用时 `bg_divider` 底 + `text_disabled` 图标），否则用户会反复点一个不响的按钮。
5. **`chevron_down` 的旋转不要用 `visibility` 换图标**：换节点会中断过渡。用同一个 `SymbolGlyph` + `rotate({ angle: expanded ? 0 : -90 })` + `.animation(200ms)`。
6. **子行竖线不能进 `padding`**：用 `Row` 左侧一个 `Column().width(1.5).backgroundColor(bg_divider)` 作兄弟节点，放进 padding 里画不出线。
7. **`sizeText` 不要改 `mbText`**：`mbText` 在状态行里用得很多，改了会影响所有文案宽度（本轮所有宽度实测都是基于 `MB` 两位小数的）。
8. **徽章宽度是「标题宽度的减法」**：徽章 30–34vp 会让 16fp 标题少 2 个汉字。真机验证时**用最长的真实标题**（如「【合作】某某某 x 某某 - 夜航星（2026 Remaster）」）确认两行内可读，别用「夜航星」这种 3 字标题验收。
