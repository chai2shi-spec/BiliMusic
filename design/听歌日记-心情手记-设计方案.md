# 听歌日记 · 心情手记（主观记录）设计方案

> 对象：BiliMusic（HarmonyOS 手机端，`com.chai.bilimusic`）
> 定位：**`听歌日记-页面设计方案.md` 的续篇**。那份回答「听了多少」，这份回答「当时是什么心情」。
> 交付形态：**只做设计与规格，不改 App 代码**。
> 配套原型：`design/听歌日记-心情手记-原型.html`（三屏：折叠态 / 展开态 / 手记段；可切 8 套主题色 × 深浅）
> 继承令牌：色值、字阶、圆角、间距全部沿用主方案 §3，本文不重新定义。

---

## 0. 一句话

**手记不是表单，是"一句话的事"。** 默认只问三个问题（心情 / 场景 / 星级），三秒能填完；愿意多写的人，才展开歌词、听感、回忆与乐评。九项字段靠**渐进式披露**活下来，而不是靠一次全摊开。

---

## 1. 为什么不能直接往统计页里塞九个输入框

现有听歌日记的节奏是「情绪 → 事实 → 名字」：封面（感性钩子）→ 四个数字（客观事实）→ 榜单（具体对象）。它是一份**只读报告**，一屏一个信息层。

如果把九项表单塞进去，会同时破坏三件事：

| 破坏 | 后果 |
|---|---|
| 节奏 | 只读报告里出现输入框，用户会以为整页都要求填，滑到一半就退 |
| 密度 | 九项最少占 600vp，等于把「榜单 / UP 主 / 新面孔」三段全挤掉 |
| 语义 | 统计是"App 算给你看"，手记是"你写给自己的"，混在一起两边都不成立 |

**所以主观内容是"一页里的一套子结构"，不是"加几个字段"**：它有自己的入口、自己的输入面板、自己的展示形态、自己的聚合口径，只是挂靠在同一个周期上。

---

## 2. 三层结构（整个设计的骨架）

九项字段**不是平级的**。按「用户愿意付出多少」分三层，这是本方案所有取舍的来源：

| 层 | 字段 | 完成成本 | 默认可见 |
|---|---|---|---|
| **情绪层**（必答区，可只填这三项就保存） | 心情标签、场景、星级评分 | 3 秒 | ✅ 折叠态全露出 |
| **表达层**（想写才写） | 喜欢的歌词、听觉感受、联想回忆、简短乐评 | 30 秒–3 分钟 | ⛔ 折叠，点「再多写两句」展开 |
| **动作层**（顺手做，不算字段） | 加入收藏、待重听标记 | 0 秒 | ✅ 常驻底部动作条 |

> 判断依据：**情绪层是"点一下"，表达层是"打字"，动作层是"拨开关"**。三种操作成本差两个数量级，混在一个纵向表单里，用户会在第一个输入框就放弃。

## 3. 入口与时机（这一节决定有没有人真的写）

### 3.1 三条红线

1. **播放完成不弹窗。** 不弹「给这首歌打个分吧」。听完一首歌立刻被要求评分，是最典型的打扰型设计，而且会让"手记"从"我想记"变成"它要我记"。
2. **不催更。** 不出现「你今天还没记录」「已连续 3 天未写」这类打卡话术。手记的价值在回顾，不在连续天数。
3. **不做假开关。** 「加入收藏」必须真的写进 `LibraryStore`，「待重听」必须真的进重听清单。做成只改本地 UI 的假 toggle，比没有这个功能更伤。

### 3.2 入口清单

| 入口 | 触发 | 预填 | 备注 |
|---|---|---|---|
| 播放页 `⋯` 菜单 | 一级入口 | 当前曲目 + 今天 | 最自然的位置 |
| 歌曲长按菜单（列表 / 榜单） | 补记 | 该曲目 + 该行播放日 | 标「补记」 |
| 手记段「记一笔」 | 页面内 | 有在播曲目则带上，否则选「最近的播放」里的一首 | 无在播时先弹选歌 |
| 手记卡片点「编辑」 | 修改 | 该条全部字段 | 同日重复进入 = 编辑 |
| 播放页小圆点提示 | 提示 | — | 写完手记后，该曲目播放页右上角出现 6px 圆点，表示"这条已经记过"，**不写也不提醒** |

### 3.3 什么时候会有"当时"

手记的语义是**那一次听**，不是"现在写的时候"。所以归属日取 `startedAt` 的那一天，不是 `createdAt`：

- 当场记（播放中/刚听完）→ 归属今天，卡片显示 `23:41`。
- 补记（从历史播放进入）→ 归属那次播放的日期，卡片显示 `10月22日 · 补记`。
- 同一天同一首歌只保留一条：再次进入 = 编辑覆盖。理由：一天听同一首六次，写六条手记只会碎片化，用户真正想记的是"这一天我和这首歌"。

## 4. 写手记面板 · 折叠态（默认，占屏 62%）

**尺寸**：`bindSheet` 的 `MEDIUM` 档，高 **480vp**，上圆角 20，底 `bg_card`，顶部 1px `bg_divider`。背景页加 32% 黑遮罩。

**为什么是 480 而不是全屏**：折叠态必须**露出上半屏的封面**。封面是用户此刻正在听的歌，是手记的对象；遮住它，面板就变成了一个抽象表单。

```
┌ 拖拽柄 36×4 pill ────────────────────┐
│ 写手记                      今天 23:41   ✕ │   ← 18/SemiBold + 13/secondary + 44 关闭
│                                            │
│ 此刻的心情                     最多 2 个   │   ← 13/secondary + 11/tertiary
│ [平静][治愈][雀跃][上头][躁动]              │   ← chip 50×32，gap 8
│ [沉郁][怅然][怀念]                          │
│                                            │
│ 在做什么                                   │
│ [🚇 通勤            ][💻 工作            ]  │   ← 2×2，158×44，gap 8
│ [🌙 睡前            ][🚶 散步            ]  │
│                                            │
│ 这首歌                                     │
│ ☆ ☆ ☆ ☆ ☆              很爱               │   ← 星 24 图标 / 热区 44；右侧 13/themeDeep
│ ─────────────────────────────────────      │
│ 再多写两句 ›                                │   ← 13/themeDeep，44 高
│ ─────────────────────────────────────      │
│ ♡ 收藏      ↻ 待重听            [  保存  ] │   ← 动作条，44 高，常驻
└────────────────────────────────────────────┘
```

### 4.1 心情标签（Mood）

- **8 个预设词，全部两字**：平静 / 治愈 / 雀跃 / 上头 / 躁动 / 沉郁 / 怅然 / 怀念。
  - **这套词与情绪分析的 8 个锚点完全一致**（见 `听歌日记-情绪分析-设计方案.md` §2.2）。词表一旦分叉，"算法判定"与"你自己写的"就永远无法对照，而这个对照是整个功能最有价值的部分。
  - 上一版的「专注」「放空」已移出情绪表：它们是**认知状态**而非情绪，无法定位到 (V, A) 平面。这两个意思分别并入「场景」（工作 / 散步）与「听感」（氛围拉满）。
  - 统一两字是为了 chip 等宽（`13px×2 + 24 padding = 50`），5 个一行（`5×50 + 4×8 = 282 ≤ 324`）刚好不出现"一个字两头空"的难看排布。
- **最多选 2 个**：情绪复合是常态（"放松又怀念"），但选到 3 个就失去信号。已选 2 个时，未选中项降到 40% 不透明度，点击给 toast「心情最多选 2 个」。
- **样式**：未选 `bg_card` + 1px `bg_divider` + `text_secondary`；选中 `brand_surface` 底 + 1px `themePrimary` 30% 描边 + `themeDeep` 字。
  - **选中态不用品牌色实底**：13px 小字压在 `#FB7299` 上对比度只有 2.2:1，读不出来。这跟分段控件能压白字不冲突——分段是 32 高的整块，字号 13 但块面大、周边留白充足，这里 chip 更小更密。
- **不给情绪配 8 种颜色**（这是本方案最容易走偏的地方，见 §14 第一条）。

### 4.2 场景（Scene）

- **4 个，单选**：通勤（🚇）/ 工作（💻）/ 睡前（🌙）/ 散步（🚶）。图标取 `sys.symbol` 里语义最近的，16px，与文字间距 8。
- **2×2 网格**，每格 **158×44**。不用一行四列：四列每格只有 76 宽，塞不下 16px 图标 + 两字，且 76 宽的热区横向太窄。
- **智能预选**（这是"能自动采的别让人手填"）：按 `createdAt` 的本地时间给默认选中——`07:00–09:30` 预选通勤、`22:00–03:00` 预选睡前、其余不预选。预选值**不写库**，只作为 UI 初值，用户点别的就换掉，且**不预选时不给任何提示文案**（不要出现"猜你在通勤"这种自作聪明的句子）。
- 可留空。四个场景覆盖不全（做饭、健身、发呆），但补齐的收益远小于维护成本，留空比硬塞"其他"好。

### 4.3 星级评分（Rating）

- **5 颗整星，不做半星。** 半星意味着每颗星要拆成 22px 的两半，命中区远低于 44vp 的下限；改成滑动选择又会让"点一下"变成"拖一下"。
- **星 24px，热区 44×44**，5 颗共 220 宽，左对齐（不居中，居中会让左侧标签区错位）。
- **右侧跟中文档位**：`1 一般 / 2 还行 / 3 喜欢 / 4 很爱 / 5 神作`，13/`themeDeep`。
  - 这一步不是为了好看：纯星级有解读歧义（3 星是"中等"还是"还行"？），加一个词，聚合时也能直接说「这周 6 首你标了神作」。
- 已选星再点同一颗 = **取消评分**（回到未评），不弹确认。
- 未评分时右侧文案为「点一下评分」，`text_tertiary`。

### 4.4 动作条（收藏 / 待重听 / 保存）

固定在面板底部，高 44 + 底部安全区。三段：

| 控件 | 未选 | 已选 |
|---|---|---|
| 收藏 | `♡ 收藏` 13/`text_secondary` | `♥ 已收藏` 13/`themePrimary`（图标实心） |
| 待重听 | `↻ 待重听` 13/`text_secondary` | `↻ 待重听` 13/`themePrimary` + 图标加 1 圈描边 |
| 保存 | 右侧 pill，`132×44`，`themePrimary` 实底 + `themeOn` 16/Medium | — |

- **保存的可用性规则**：至少有一项非空（心情 / 场景 / 星级 / 歌词 / 听感 / 回忆 / 乐评任一）才可点，否则置灰 `bg_divider` + `text_disabled`。理由：空条目会污染聚合（"这周写了 12 条"，点开 8 条是空的）。
- 保存后：面板下沉 + 手记段新卡从 0 高度展开（不做整页跳转，用户不该被踢出当前上下文）。
- 已有手记时，右上角 `✕` 旁边多一个「删除」（13/`text_secondary`），删除需二次确认。

## 5. 写手记面板 · 展开态（全屏，`LARGE` 档）

点「再多写两句 ›」后升到全屏（**不是新页面**——退回到折叠态要能一键，页面跳转会让人以为已经离开了手记）。顶部固定一条**身份条**，滚动时始终可见：

```
┌ ‹ ──────────────────────────────────────┐  ← 44 高
│ [cover32] 夜行                           │  ← 16/primary
│           陈粒 · 4:02                    │  ← 11/tertiary
├──────────────────────────────────────────┤
│ 平静 · 睡前 · ★★★★ 很爱            改 ›  │  ← 情绪层收成一行，点击退回折叠态
├──────────────────────────────────────────┤
  喜欢的一句歌词                      从歌词选 ›
  ┃「我走过凌晨三点的街」
  ┃《夜行》· 03:12                        换一句
  ────────────────────────────────
  听觉感受                        最多 3 个
  [人声戳我][编曲很妙][鼓点很稳]
  [氛围拉满][低音扎实][录音干净]
  ────────────────────────────────
  写两句
  ┌────────────────────────────────┐
  │ 前奏一进来就知道是这首……        │  ← 主输入，3 行，有边框
  │                            42/300│
  └────────────────────────────────┘
  这首歌让你想起                  0/200
  三年前也是这样的雨夜，我在……
  ────────────────────────────────
│ ♡ 收藏   ↻ 待重听            [ 保存 ] │  ← 固定动作条
```

### 5.0 展开后，情绪层收成一行

展开态顶部（身份条下方）保留一条 **44 高的情绪摘要行**：`平静 · 睡前 · ★★★★ 很爱` + 右侧「改 ›」。

- 作用有三：① 让用户在打字时始终看得见自己刚才选了什么，不用滚回去确认；② 把 300vp 的情绪层压成 44vp，给表达层腾出空间；③ 点它退回折叠态 = 修改入口，比在顶部再放一个"返回"更符合直觉。
- 未选的项直接跳过（不显示占位符「未选」）；三星以下用 `★★☆☆☆` 的空心星表示，颜色 `text_tertiary`。
- 一个字段都没选时，这一行显示 `还没选心情 ›`（`text_tertiary`），点进去补。

### 5.1 喜欢的歌词（LyricQuote）

- **来源一（主）**：「从歌词选 ›」→ 打开歌词选择器（复用 App 已有三源歌词 `LyricsComponent` 的滚动列表），**当前播放位置那一行高亮**，点任意一行即选中，同时记下 `atMs` 与行号。
  - 这是本 App 独有的能力，也是手记里最有记忆点的一屏。用户不是"复制一句歌词"，而是"在这一首歌里指了一下"。
- **来源二（兜底）**：歌词未抓到时，选择器按钮禁用并提示「这首歌还没抓到歌词，先手打一句」；手打入口是同一个框，`maxLength 60`。
- **展示样式**：左侧 2px `themePrimary`（55% 不透明）竖线，文本 16/`text_primary`，全角引号 `「」` 包裹；下方 11/`text_tertiary` = `《歌名》· mm:ss`，右侧 13/`themeDeep`「换一句」。
  - **不用斜体**：中文斜体是浏览器/引擎伪斜体，字重与字面都会变形。
- 最多 2 行，超出省略（歌词本来就该被截，保留前两句足够）。

### 5.2 听觉感受（SoundNotes）

- **6 个预设，可多选，上限 3**：人声戳我 / 编曲很妙 / 鼓点很稳 / 氛围拉满 / 低音扎实 / 录音干净。
- 定义要卡死：**这是对"声音"的评价，不是对"歌"的评价**。心情层说的是"我"，听感层说的是"这首歌的制作"，两者不能混——所以文案都落在具体声部（人声/编曲/鼓点/氛围/低音/录音）上，不出现"好听""一般"这类整体判断（整体判断归星级）。
- 为什么不做成文本框：它会变成第三个输入框，而表达层已经有两个了。chips 让"只愿意点一下"的人也能留下有效信号。
- ⚠️ 若你想记的其实是**收听条件**（戴耳机 / 外放 / 音量 / 单曲循环），那是另一类元数据，**建议自动采集而不是手填**（`AudioRenderer` 的输出设备类型、音量档位）。本方案不把它们混进听感 chip，混进去会让这组语义散掉。

### 5.3 两个文本框：简短乐评 / 联想回忆

这两个字段最容易做成"两个一样大的框"，那就会变成填表。**用视觉重量区分**：

| | 简短乐评 | 联想回忆 |
|---|---|---|
| 语义 | 对这首歌说的话 | 这首歌勾起的自己的事 |
| 形状 | **有边框**（1px `bg_divider`，圆角 8），3 行起 | **无边框**，只一条上分隔线，2 行起 |
| 字阶 | 16/`text_primary` | 13/`text_secondary` |
| Placeholder | `说两句，给未来的自己看` | `这首歌让你想起…` |
| 上限 | 300 字，右下角实时计数 | 200 字，右侧实时计数 |
| 展示态 | 最多 4 行 + 「展开」 | 最多 3 行 + 「展开」 |

- 计数器**常驻显示**（不是超限才跳出来），格式 `42/300`，11/`text_tertiary`。
- 键盘弹起时整个滚动区上推，动作条跟随；**文本框不被遮**。

### 5.4 身份条为什么必须存在

全屏后背景页完全被盖住，用户会失去"我在给哪首歌写"的锚点。32px 小封面 + 歌名是最低的身份信息量，比只写标题「写手记」强得多。

## 6. 手记卡片（展示态）

一份手记在"回顾"里长这样。**三种密度**共用同一份数据：

### 6.1 完整卡（手记段 / 全部手记页）

```
┌────────────────────────────────────────────┐
│ [cover40] 夜行                       10/25  │  ← 16/primary + 11/tertiary
│           陈粒 · 23:41                      │  ← 13/secondary
│ ★★★★☆ 很爱   🌙睡前  平静 怀念             │  ← 星 16；chip 11 非交互
│ ┃「我走过凌晨三点的街」                      │  ← 引用，13/primary，最多 2 行
│ 人声戳我 · 氛围拉满                          │  ← 11/tertiary
│ 前奏一进来就知道是这首。三年前也是这样的雨夜… │  ← 13/secondary，3 行折叠
│ ──────────────────────────────────────────  │
│ ♥ 已收藏                       ↻ 待重听      │  ← 13，可点切换，行高 44
└────────────────────────────────────────────┘
```

- 卡片 `bg_card`，圆角 12，内边距 **14**，卡片间距 **12**，左右 16。
- 展示态的 chip 是**纯展示**（11px，高 20，`bg_page` 底 + `text_secondary`），不响应点击，避免和输入态混淆。
- 底部动作行：左「♥ 已收藏」（已收藏时 `themePrimary`，未收藏时 `♡ 收藏` `text_tertiary`）；右「↻ 待重听」（已标记时 `themePrimary`）。两个都是 44 高热区。
- 长按卡片 → 编辑 / 删除（`bindContextMenu`）。
- 点卡片正文区 → 播放该曲。
- 整卡读屏文案：「夜行，陈粒，10月25日，4 星很爱，场景睡前，心情平静与怀念，已收藏」。

### 6.2 紧凑行（列表页 / 搜索结果）

`[cover36] 歌名 16 / 副行「平静 · 睡前 · 4★」13`，右侧日期 11，高 64，无引用无正文。用于「全部手记」长列表与歌曲详情页的"这首歌你写过 3 条"。

### 6.3 一行摘要（播放页 / 歌曲详情页）

## 7. 手记段（嵌在听歌日记页内）

**位置**：`新面孔` 之后、底部「生成回顾卡片」之前。理由：整页以"你自己的话"收尾，再接分享按钮，情绪是往上走的；放中间会打断"数据 → 榜单 → 新面孔"的事实链。

### 7.1 段结构

```
手记                              全部 ›        ← 18/SemiBold + 13/themeDeep
┌ 这一周的心情 ──────────────────────────────┐  ← 聚合卡，brand_surface
│ 平静   ████████████  5                      │
│ 治愈   ███████  3                           │
│ 怀念   ████  2                              │
│ ─────────────────────────────────────────   │
│ 通勤 8    睡前 5    工作 3    散步 1         │  ← 四等分：18 数字 + 11 标签
│ ─────────────────────────────────────────   │
│ 平均 4.2 星 · 12 条手记 · 待重听 7 首       │  ← 11/tertiary
└─────────────────────────────────────────────┘
[ 完整卡 × 2 ]                                  ← 最近两条
        ＋ 记一笔                                ← 次级按钮，幽灵底
```

- **聚合卡用 `brand_surface`**（与"听歌节奏"图卡同底），形成"这两张是 App 算的"的视觉分组，和 `bg_card` 的"你写的"卡片区分开。
- 心情分布横条：**单色系，靠透明度分档**（第 1 名 100% / 第 2 名 55% / 第 3 名 32%），条高 8、圆角 pill、右侧跟数值 13/`text_secondary`。不给 8 种情绪配 8 种颜色（见 §14）。
- 场景四宫格只在**周 / 月 / 年**显示；日视图手记最多两三条，直接列卡片，不聚合。
- 「全部 ›」热区 44，距右边缘留 8。
- 「记一笔」：44 高、圆角 pill、**透明底 + 1px `bg_divider` + `text_primary`**。不用实底品牌色——本页底部还有一个实底主按钮（生成回顾卡片），两个实底会打架。

### 7.2 页面级入口：情绪摘要行

在「一句话」正下方加**一行极轻的摘要**（不足 30 高的视觉重量），点击滚动到本页手记段（`Scroller.scrollToIndex`，**不跳新页**）：

```
这一周的心情：多为平静 · 平均 4.2 星        ›
```

- 13/`text_secondary`，居中，`themeDeep` 的 `›`。
- 只在**本周手记 ≥ 3 条**时出现，否则不显示（写得太少时说"多为平静"是噪音）。
- 为什么放这儿而不是页面顶部：「一句话」本身就是"读完数据后的一句感慨"，顺势接一句"你的心情"，语义连贯；再往上就是封面，会抢视觉。

## 8. 数据模型与存储

### 8.1 模型

```ts
interface ListenNote {
  id: string;                  // `${trackId}@${day}` 天然去重
  trackId: string;
  day: string;                 // 'YYYY-MM-DD'，归属日（取 startedAt，不取 createdAt）
  // 快照冗余：歌可能被删/下架，手记不能因此变空白
  title: string; artist: string; upMid: string; coverUrl: string;
  mood: string[];              // ≤2，取自 MOOD_KEYS
  scene: string;               // '' | commute | work | bedtime | walk
  rating: number;              // 0–5 整数，0 = 未评
  lyric: { text: string; atMs: number; lineIndex: number } | null;
  sound: string[];             // ≤3，取自 SOUND_KEYS
  memory: string;              // ≤200
  review: string;              // ≤300
  favored: boolean;            // 写这条时是否在收藏夹里
  relisten: boolean;           // 待重听
  createdAt: number; updatedAt: number;
  backfill: boolean;           // 是否是事后补记（卡片显示「补记」）
}
```

### 8.2 存储

| 项 | 决定 | 理由 |
|---|---|---|
| 位置 | `filesDir/notes/YYYY-MM.json` | **绝不能进 Preferences**（8192 字节上限，十几条手记就撑爆整份设置） |
| 格式 | 每月一个 JSON 数组 | 手记要**改**（同日覆盖、长按编辑），JSONL 追加写对修改不友好；单月几百条约 150KB，全量读写可接受 |
| 加载 | 启动只读最近 2 个月，其余按周期懒加载 | 年视图才需要跨 13 个月 |
| 索引 | 内存 `Map<'trackId@day', ListenNote>`，O(1) 判断"这首今天写过没" | 播放页那个 6px 圆点靠它 |
| 兼容 | 与 `listen_log/YYYY-MM.jsonl`（会话日志）**分开放** | 会话日志只追加、量大、可丢；手记要改、量小、不能丢。混在一个文件里，任一写入失败会同时弄坏两边 |

### 8.3 聚合口径

| 指标 | 口径 |
|---|---|
| 心情分布 | 周期内所有手记的 `mood[]` **展开计数**（一条含两个情绪就算两次），按次数降序取前 3 |
| 场景分布 | `scene` 非空的手记按场景计数，恒定 4 列（值为 0 也显示） |
| 平均星级 | `rating > 0` 的手记求平均，保留 1 位小数；样本 < 3 条时显示「—」而不是数字 |
| 手记条数 | 周期内 `day` 落区间的手记数 |
| 待重听 | `relisten === true` 的手记数（跨周期全量，不受周期筛选） |

## 10. 空态与边界

| 场景 | 表现 |
|---|---|
| 整个周期 0 条手记 | 手记段换成引导卡：主行「还没有手记」16 + 副行「听歌时随手记一句，回头能翻到当时的心情」13 + 「记一笔」幽灵按钮。**不显示聚合卡的空壳** |
| 只有 1–2 条 | 聚合卡只显示心情分布，场景四宫格与底行隐藏（1 条的"平均星级"没有意义） |
| 手记全部字段为空 | 不可能存在（保存前置校验，见 §4.4） |
| 歌曲已失效 / 下架 | 卡片照常显示（走快照字段）；点播放 → toast「这首歌已经找不到了」；手记本身仍可编辑、可删除 |
| 歌词当时抓到、现在源失效 | 引用文本已落库，照常显示；「换一句」置灰 |
| 手记卡片里的封面加载失败 | `brand_surface` 底 + 居中 16px 音符图标 |
| 跨月边界 | 按 `day` 归档，不按 `createdAt`（23:58 写的算当天，00:02 补记的算前一天） |
| 时区/夏令时 | `day` 用设备本地时间格式化，不做 UTC 归一 |
| 单月文件超过 2MB（极端） | 该月切片按周再分文件，读取层对上层透明 |

## 11. 动效

| 元素 | 动效 | 时长 / 曲线 |
|---|---|---|
| 面板升起 | 从底部滑入 + 背景遮罩淡入 | 400ms `spring(1, 90, 20)` |
| 折叠 → 展开 | 高度过渡 + 身份条淡入 | 320ms `EaseInOut` |
| chip 选中 | 底色 150ms；缩放 0.96 → 1（仅自己） | 150ms `EaseOut` |

## 12. 触达与无障碍

- chip 视觉 32 高，**外套 44 高的透明容器**承接点击；星星 24 图标配 44×44 热区；场景格 44；动作条 44；「全部 ›」44 且距右边缘 8。
- 每组给 `accessibilityGroup(true)` + 组名（"此刻的心情"），读屏进入组时先念组名再念选项。
- chip 的 `accessibilityChecked` 必须跟随真实选中态；星星整体一个可读节点：`"4 星，很爱"`，不逐颗朗读。
- 输入框 `maxLength` + 实时计数；超限时**不截断正在输入的内容**，改为不让继续输入 + 计数器变 `themeDeep`。
- 键盘弹起：`expandSafeArea` + 滚动区 `padding-bottom` 追加键盘高度，动作条跟随上推。
- 系统「减少动效」开启时：面板直接到位、星星不做弹跳、卡片纯淡入。

## 14. 三条最容易做错的地方

### 14.1 不要给情绪配 8 种颜色

这是最诱人的错误：平静=蓝、雀跃=黄、治愈=绿、怀念=紫……在单主题稿里很好看，但：

1. App 有 **8 套主题色**，一套粉主题 + 8 种情绪色 = 9 个色相打架；
2. 深色模式下这 8 个颜色要全部重调一遍（否则在 `#121216` 上糊成一片），维护成本翻倍；
3. 违反既有铁律「品牌色只给大字与图标」——情绪 chip 是 13px 小字。

**正确做法**：情绪只靠**文字**区分，强调靠"是否被选中"（描边 + 极浅底）。8 套主题切换时，情绪区永远只有当前主题色一个强调点。

### 14.2 不要让"手记"变成打卡

一旦出现连续天数、徽章、"你已 3 天没记录"，用户就会从"想写"变成"被要求写"，然后开始敷衍（全选 5 星、只写"好听"），数据反而变脏。

本方案的所有入口都是**被动**的：不提醒、不弹窗、不显示"未完成"。手记段的空态只说一句"听歌时随手记一句"，不说"快来记一笔吧"。

### 14.3 收藏与待重听必须是真动作

`favored` / `relisten` 如果只写进 `ListenNote`，用户点「收藏」后去收藏夹找不到，这个功能就废了，而且比没有更伤信任。

- 「收藏」→ 调 `LibraryStore` 的真实收藏方法（与列表页 `♥` 同一个数据源），`ListenNote.favored` 只是**冗余快照**用于卡片展示；
- 「待重听」→ 需要一个真实清单（`notes` 里 `relisten=true` 的集合），Phase 1 至少在「全部手记」页提供筛选，Phase 2 再进收藏页做 Tab。
