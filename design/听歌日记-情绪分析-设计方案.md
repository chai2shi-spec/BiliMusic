# 听歌日记 · 情绪分析（从曲目推断感受）设计方案

> 对象：BiliMusic（HarmonyOS 手机端，`com.chai.bilimusic`）
> 前置：`听歌日记-页面设计方案.md`（客观统计）、`听歌日记-心情手记-设计方案.md`（主观手记）
> 交付形态：**只做设计与规格，不改 App 代码**
> 配套原型：`design/听歌日记-情绪分析-原型.html`（三屏：页面内情绪段 / 情绪详情 / 纠正面板）

---

## 0. 一句话

**不是猜你在想什么，是把"你听了什么、什么时候听、听完没有"翻译成一组可解释的情绪坐标。** 判定必须给依据、可被推翻、且推翻后仍保留原判。

---

## 1. 边界：这个功能能做什么、不能做什么

这一节必须写在最前面，因为情绪推断是最容易滑向"AI 读心"的方向。

### 1.1 能做的

从**本机已有的数据**（曲目元信息、B 站标签、已缓存歌词、播放会话、跳过与完播行为、时段）推断出**这一段时间听的东西整体偏什么情绪**，并用视觉化呈现。它是"音乐的情绪画像"，不是"你的心理诊断"。

### 1.2 不能做的（写死在产品里，不是能力不足而是不该做）

| 不做 | 原因 |
|---|---|
| 心理诊断词（抑郁、焦虑、孤独症、情绪障碍） | 语音/音乐情绪推断不具备临床效力，写出这些词就是把娱乐功能伪装成医疗判断 |
| 干预建议（"你最近情绪低落，建议多听轻音乐/找人聊聊"） | 越界。App 没有资格对用户的心理状态做建议 |
| 逐曲给"你此刻很难过"式断言 | 单曲不足以判人；只对**周期聚合**给结论 |
| 云端上传听歌记录做画像 | 隐私红线。全部计算在本机完成，不上传、不跨设备同步 |
| "监测到你有负面情绪，已通知…" | 绝不外发、绝不通知任何人 |

### 1.3 允许的表达上限

只描述**音乐与感受的关系**，句式限定在三种：

1. 陈述偏好：`这一周你大多在听安静的慢歌`
2. 描述轨迹：`周三之后明显亮了起来`
3. 邀请对照：`你写下的手记里，怀念出现得更多`

**不写**"你最近压力很大"这类从音乐跨越到人生的判断。

## 2. 情绪坐标系与 8 个锚点

### 2.1 两轴

用心理学里最稳的二维模型（Russell 环形模型），不发明新维度：

- **V 效价**（Valence）：`-1` 低落 → `+1` 愉悦
- **A 唤醒**（Arousal）：`-1` 平静 → `+1` 激烈

好处：任何一首歌、任何一个周期，最终都落在**一个点**上，可画、可比、可算距离。

### 2.2 8 个情绪锚点

| 词 | V | A | 直觉 |
|---|---|---|---|
| 雀跃 | +0.65 | +0.45 | 明亮、轻快、想跟着晃 |
| 上头 | +0.45 | +0.85 | 兴奋、单曲循环、音量拉满 |
| 躁动 | -0.35 | +0.80 | 坐不住、想甩掉什么 |
| 沉郁 | -0.80 | +0.15 | 压着、沉、不想说话 |
| 怅然 | -0.50 | -0.35 | 空、失落、说不清 |
| 怀念 | -0.10 | -0.55 | 往回看、旧事、慢慢走 |
| 平静 | +0.20 | -0.60 | 稳、无波、刚好 |
| 治愈 | +0.65 | -0.40 | 暖、被接住、松下来 |

**判定规则**：取周期点 (V, A) 到 8 个锚点的欧氏距离，最近的 1 个为**主情绪**，第 2 个为**次情绪**（距离 > 0.9 时不显示次情绪）。

- 只给两个词，不给"情绪百分比雷达图"——五维六维雷达在手机宽度下读不出差异，且会让用户以为每个维度都测得准。
- 8 个词**全部两字**，与手记的 chip 共用同一套词表（见 §7）。

## 3. 一首歌的情绪怎么算

三路信号，全部来自本机已有数据，**不联网**。

### 3.1 信号 A：曲目标签与标题（权重 0.45）

`Track` 已有 `title`、`artist`，B 站音乐区投稿自带分区与 tag（请求曲目详情时可取到，取不到就退化到标题关键词）。

内置**关键词组表**（每组命中即给一组 ΔV/ΔA，多组按命中词数加权平均）：

| 组 | 触发词（示例，实际约 120 个） | ΔV | ΔA |
|---|---|---|---|
| 燃 | 燃、热血、战斗、爆裂、电音、摇滚、鼓 | +0.15 | +0.75 |
| 甜 | 甜、恋爱、夏天、快乐、喜欢你、告白 | +0.70 | +0.30 |
| 静 | 慢、静、夜、月、钢琴、ambient、白噪音、纯音乐 | -0.05 | -0.70 |
| 暖 | 治愈、温柔、陪、晚安、抱、摇篮 | +0.60 | -0.40 |
| 伤 | 分手、遗憾、错过、别走、哭、断、散 | -0.70 | -0.10 |
| 念 | 从前、那年、旧、回忆、小时候、毕业 | -0.30 | -0.50 |
| 躁 | 烦、烂、逃、压力、世界、疯 | -0.40 | +0.60 |

### 3.2 信号 B：歌词情感（权重 0.35）

App 已有三源歌词并已做文件缓存（`LyricCacheStore`），直接读本地文本，**不需要重新请求**。

- **情感词典**：正向词约 220、负向词约 260（中文常见情感词，内置资源文件约 12KB）。
- **否定翻转**：词前 3 字内出现「不/没/别/未/无」→ 极性取反（`不难过` 判为正）。
- **程度副词**：`很/太/特别/超` ×1.5，`有点/稍微` ×0.6。
- 结果：`V_lyric = (pos - neg) / (pos + neg + 2)`，钳制 [-1,1]。
- **唤醒补充**：`A_lyric = 0.4 + 0.6 × 重复率`（重复率 = 出现次数最多的一行行数 / 总行数）。副歌反复 = 情绪强度高，这是最朴素也最稳的代理指标。
- **无歌词时**：该路权重整体让给信号 A（`wA = 0.80, wB = 0`），并在依据里注明「x% 的曲目没有歌词」。

### 3.3 信号 C：行为（周期级修正，不进单曲）

单曲算完再叠一层"怎么听"的修正，权重小但很关键——同一首歌，单曲循环和随手划过是两种情绪：

| 行为 | 公式 | 作用 |
|---|---|---|
| 深夜占比 | 会话落在 23:00–04:00 的时长 / 总时长 | `ΔV -= 0.30 × r`，`ΔA -= 0.20 × r` |
| 单曲集中度 | Top1 曲目时长 / 总时长 | 超过 0.25 后 `ΔA += 0.50 × (r - 0.25)` |
| 跳过率 | `ms < 30s` 的会话数 / 总会话数 | `ΔV -= 0.60 × r`，`ΔA += 0.40 × r` |
| 完播率 | `completed` 或 `ms ≥ 0.9×duration` 的占比 | `ΔV += 0.30 × (r - 0.60)` |

### 3.4 合成

```
V = Σ(w_i · ms_i · V_i) / Σ(w_i · ms_i) + ΔV_behaviour
A = Σ(w_i · ms_i · A_i) / Σ(w_i · ms_i) + ΔA_behaviour
```

- **按毫秒加权，不按次数**：听 40 秒的十首不该压过听满的半小时。
- 结果钳制到 `[-1, 1]`。
- 模型版本号写进结果（`model: 1`），版本变更强制重算——否则新旧结果混在一张图上无法解释。

### 3.5 权重表是起点，不是定论

0.45 / 0.35 / 行为和修正系数都需要用真实数据校准。设计阶段的要求只有一条：**所有权重集中在一个常量表里**，可整体调整，不散落在代码各处。

## 4. 置信度：什么时候不该给结论

情绪判定的可信度天差地别（听了 3 首和听了 90 首），所以必须给出**置信度**并在 UI 上体现：

```
conf = min(1, 有效会话数 / 12) × (0.60 + 0.40 × 歌词覆盖率) × (0.70 + 0.30 × (1 - 跳过率))
```

| conf | UI 表现 |
|---|---|
| < 0.40 | **不给结论**。卡片换成「这周的记录还太少，再多听几天」+ 罗盘显示为空心灰圈（不画点）。不显示任何情绪词 |
| 0.40 – 0.70 | 正常显示，但标题下加一行 11/tertiary「样本较少，仅供参考」 |
| ≥ 0.70 | 正常显示，无附加说明 |

**宁可什么都不说，也不要给一个低置信度的断言。** 一旦用户发现"它说我躁动，可我这周明明很好"，后面所有判定都不会再被信任。

## 5. 呈现

### 5.1 情绪罗盘（主视觉）

用圆点表达"你在情绪平面的什么位置"，是这套设计唯一需要读图的地方。

**规格**

| 项 | 紧凑版（页面内） | 完整版（详情页） |
|---|---|---|
| 尺寸 | 120 × 120 | 240 × 240 |
| 圆半径 | 40 | 86 |
| 轴 | 只画十字轴线（1px `bg_divider`） | 同左 + 外圈 1px |
| 刻度 | 8 个 2px 点，`bg_divider` | 8 个 2px 点 + 8 个词（11px，`text_tertiary`，落在圆周外 104 半径处） |
| 当前点 | 实心 6px `themePrimary` + 12px 18% 光晕 | 实心 7px + 18px 光晕 + **从圆心到点的 1px 虚线**（指示方向） |
| 上期点 | 不显示 | 空心 5px，`text_tertiary` 45%，与当前点之间一条 40% 虚线 |
| 中心文字 | 无 | 无——主情绪放在**圆下方** 24/SemiBold 居中（压在圆里会和方向虚线、当前点打架，且圆内已无空白可站） |

**为什么用罗盘而不是雷达图**：雷达图要求"每个维度都有值"，而我们的模型本来就只有一个点；硬拆成五维会凭空造出四个不存在的测量。

### 5.2 页面内情绪段（插在 KPI 与「听歌节奏」之间）

放在这里而不是页面末尾：**情绪是这一页的"结论"，事实是论据**。用户先看到 12.4 小时、186 次，紧接着一句"你这一周大多在平静和治愈之间"，逻辑才闭合。

```
这一周的情绪                              详情 ›      ← 18/SemiBold + 13/themeDeep
┌───────────────────────────────────────────────┐
│  ◯ 罗盘(120)   平静                             │  ← 24/SemiBold
│                偶尔 治愈、怀念                   │  ← 13/secondary
│                                                │
│  78% 在 22 点后 · 跳过 4% · 3 首慢歌            │  ← 11/tertiary，单行省略
└───────────────────────────────────────────────┘
```

- 卡底 `brand_surface`，圆角 12，内边距 14，高 **132**。
- 左罗盘 120，右侧文字列（主情绪 24 在基线、次情绪 13、依据 11）。
- 依据行**只放三个最强的信号**，用 `·` 连接，单行省略；完整依据在详情页。

### 5.3 情绪曲线（按天）

紧接在情绪段下方，与「听歌节奏」柱状图**共用同一横向节奏**，但画折线而不是柱：

- 高 **96**（SVG 64 + 轴标签 24 + 说明 8）。
- 纵轴是 V 值，`0` 轴为一条虚线（`bg_divider`），线上/线下不用颜色区分（避免红绿语义）。
- 折线 2px `themePrimary`，7 个点 3px 实心，**峰值点与谷值点各加一个 5px 白描边**（在任意主题下都能看到）。
- 横轴标签同「听歌节奏」：周一二三四五六日；月视图改「第1/3/5周」；年视图「1/4/7/10」。
- 卡底一行 11/tertiary：`虚线以上 = 偏明亮，以下 = 偏沉`。

为什么单独一条曲线而不是塞进柱状图：柱状图的纵轴是"时长"（绝对量），情绪曲线的纵轴是"效价"（有正负），两种量纲不能共轴。

### 5.4 情绪详情页

```
‹ 这一周的情绪

        [ 240 罗盘，8 词在圆周 ]
             平静
        偶尔 治愈、怀念

情绪构成
  平静  ████████████  42%
  治愈  ████████  28%
  怀念  █████  18%
  沉郁  ███  12%

算法说 / 你写的
  算法    平静 · 治愈
  手记    5 条里，怀念出现 3 次
  机器听到的是平稳，你写下的是舍不得。

  [ 我觉得这一周更像… ]      ← 幽灵按钮，44 高
```

- 情绪构成：4 条**单色横条**（透明度 100/70/45/25 分档），条高 8，左侧词 13/primary（宽 48），右侧百分比 13/secondary。
- 「算法说 / 你写的」只有在该周期**手记 ≥ 2 条**时出现；否则整块隐藏（不要用一个"你还没写手记"占位去提醒用户补）。

## 6. 判断依据：为什么必须写出来

一句"你这周很平静"如果没有任何依据，用户只会觉得"它在瞎猜"。给出依据，它就从断言变成**可讨论的观察**。

### 6.1 依据的生成规则

从命中的信号里取**绝对值最大**的 3–4 条，转成自然语言，不出现任何数字公式：

| 内部信号 | 文案模板 |
|---|---|
| 深夜占比 > 0.6 | `{n}% 的播放发生在 22 点以后` |
| 单曲集中度 > 0.35 | `{歌名} 循环了 {n} 次` |
| 跳过率 < 0.10 | `{n}% 的歌你都听完了` |
| 跳过率 > 0.30 | `有 {n}% 的歌没听够 30 秒` |
| Top3 都是「静」组 | `最常听的 3 首都是慢歌` |
| Top3 都是「燃」组 | `最常听的 3 首都在往前冲` |
| 歌词覆盖率 < 0.5 | `{n}% 的曲目没有歌词，判断偏粗` |

- 每条依据都是**可反查的**：详情页里点依据能展开成具体曲目列表（Phase 2）。
- 依据行永远不超过 3 条（页面内）/ 5 条（详情页）。多于此就变成技术报告。

### 6.2 「不准」必须有一个出口

详情页底部固定一个幽灵按钮「我觉得这一周更像…」→ 打开纠正面板（§8）。

**没有纠正入口的情绪判定，等于强迫用户接受一个错误的自我描述。** 这是本功能能不能被接受的分水岭。

## 7. 算法与手记的对照

两套数据放一起，这个页面的情感价值才出来：

| | 来源 | 特点 |
|---|---|---|
| 算法判定 | 曲目 + 歌词 + 行为 | 客观、全量、不给理由就不可信 |
| 手记 | 用户主动写的 | 主观、稀疏、但一定是他真正想说的 |

### 7.1 对照逻辑

只在同一周期同时存在「算法结果」和「≥2 条手记」时显示：

```
算法    平静 · 治愈
手记    5 条里，怀念出现 3 次
机器听到的是平稳，你写下的是舍不得。
```

- 第三行是**固定句式模板**，按两边词对是否相同分三种：

| 情形 | 文案 |
|---|---|
| 词对完全一致 | `这次你们想法一样。` |
| 有交集 | `机器听到的是 {算法词}，你写下的是 {手记词}。` |
| 无交集 | `机器听到的是 {算法词}，你写下的是 {手记词}——差的这部分，可能才是重点。` |

- **不做"你比机器更懂自己"这类讨好式文案**，保持中性叙述。

### 7.2 词表必须统一

手记的 8 个心情 chip 与算法的 8 个锚点**用同一套词**（平静 / 治愈 / 雀跃 / 上头 / 躁动 / 沉郁 / 怅然 / 怀念），否则对照无从计算。

> 上一版手记方案里的「专注」「放空」两个词被移出情绪表：它们是**认知状态**而不是情绪，无法定位到 (V, A) 平面上。这两个意思并入「场景」（工作 / 散步）与「听感」（氛围拉满）更准确。

## 8. 纠正：用户说了算，但原判不销毁

### 8.1 纠正面板

`bindSheet` MEDIUM 档，高 400：

```
这一周，你实际的感觉                ✕
机器判断：平静 · 治愈（置信度 72%）          ← 11/tertiary

[平静][治愈][雀跃][上头]                     ← 同一套 8 词
[躁动][沉郁][怅然][怀念]                     ← 最多选 2 个

想说一句（可选）
┌──────────────────────────────┐
│ 其实是舍不得，不是平           │
└──────────────────────────────┘

修正后仍会保留算法原判，可随时恢复            ← 11/tertiary

[        就用这个感觉        ]               ← 44 实底
```

### 8.2 修正后的表现

- 页面内情绪段的主情绪换成用户选的第 1 个词，次情绪用第 2 个。
- 卡片右上角加一个 11/tertiary 的 **`已修正`** 小标（不加图标，不加颜色）。
- 详情页的「算法说 / 你写的」中间多一行：`算法原判 平静 · 治愈`（`text_tertiary`，可点「恢复」）。
- 罗盘上**同时画出两个点**：实心点 = 用户选的位置，空心点 = 算法原判位置。两个点往往不在一起——这个画面本身就是设计的一部分。

### 8.3 存储

```
EmotionOverride {
  periodKey: string;        // '2026-W43' / '2026-10' / '2026' / '2026-10-25'
  mood: string[];           // ≤2
  note: string;             // ≤80
  createdAt: number;
}
```

存 `filesDir/emotion/override.json`（一个文件装全部周期，都很小）。**算法原始结果另存** `filesDir/emotion/cache.json`，修正只覆盖展示，不覆盖原判。

## 9. 计算时机与性能

| 项 | 决定 |
|---|---|
| 何时算 | 进入页面时读缓存；缓存过期（> 1 小时 或 新增会话 > 5）才重算 |
| 在哪算 | 单周期 ≤ 600 条会话时**主线程同步算**（实测量级 < 30ms）；超过则丢 `TaskPool`，UI 先出骨架 |
| 缓存 | `filesDir/emotion/cache.json`，按 `periodKey` 存 `{V, A, conf, top[], byDay[], reasons[], model}` |
| 失效 | `model` 版本变化、周期内会话数变化 → 重算该周期 |
| 不做的 | 不做后台预计算、不做定时任务（页面打开时才需要，没必要常驻耗电） |

⚠️ 歌词情感分析要读全部歌词文本，单首几千字 × 上百首 = 几 MB 字符串处理。**必须逐首算完就丢**（只留 `V_lyric` 与 `A_lyric` 两个数），不要把歌词全文留在内存里做二次遍历。

## 10. 空态与边界

| 场景 | 表现 |
|---|---|
| 会话数 < 6（conf < 0.4） | 情绪段换成「这周的记录还太少，再多听几天」+ 空心罗盘（只画圆和轴，不画点）；不显示任何情绪词、不显示曲线 |
| 有会话但全是 `ms < 30s` | 同上（跳过率 1.0 → conf 极低） |
| 歌词覆盖率 0（全没抓到） | 正常判定但依据里加一条「没有歌词，只按曲风和听法判断」 |
| 首周使用（无上期数据） | 罗盘不画上期空心点；「情绪构成」正常显示 |
| 用户修正过 | 主副情绪用修正值；罗盘点画两个；卡片标 `已修正` |
| 周期翻页到无数据周 | 不沿用当前周的情绪，直接走空态（**不能把上周结论留在屏幕上**） |
| 曲目已被删除 | 快照字段仍参与计算（会话日志里已冗余了 title/artist），但依据里的歌名不可点 |
| 时区变化 | 深夜占比按会话 `startedAt` 的本地时区重算，不缓存跨时区结果 |

## 11. 动效

| 元素 | 动效 | 时长 |
|---|---|---|
| 罗盘入场 | 从圆心向外画圆（scale 0 → 1，opacity 0 → 1） | 320ms `EaseOut` |
| 当前点落位 | 从圆心沿虚线滑到目标位置 | 420ms `spring(1, 86, 20)`，延迟 160ms |
| 上期点 | 淡入 | 200ms，延迟 300ms |
| 切换周期 | 点沿直线移动到新位置（不做淡出淡入） | 360ms `EaseInOut` |
| 情绪构成条 | 宽度 0 → 目标值，错峰 40ms | 300ms |
| 曲线 | 沿路径绘制（`strokeDashoffset`） | 500ms `EaseOut` |
| 纠正保存 | 罗盘实心点移到用户选的位置，原判变空心 | 420ms |

红线：不动 `width/height` 做动画（构成条用 `scaleX` + `transform-origin: left`，不用 `width`）；减少动效模式下全部直接落位。

## 12. 触达与无障碍

- 「详情 ›」「恢复」「我觉得这一周更像…」全部 ≥44 热区，距右边缘留 8。
- 罗盘整体一个可读节点，`accessibilityText` = `"情绪位置：偏平静，略偏沉。主情绪平静，次情绪治愈、怀念"`，**不逐刻度朗读**。
- 情绪构成条 `accessibilityText` = `"平静 42%，治愈 28%"`，单条一个节点。
- 曲线容器给一句汇总：`"周三最低，周六最高"`，不朗读每个点。
- 「已修正」小标必须能被读屏读到（不能用纯装饰的 `visibility` 隐藏）。
- 色觉无障碍：所有信息都不依赖颜色（词是文字、位置是坐标、百分比是数字），罗盘两点靠"实心/空心"区分而非颜色。

## 15. 与常见做法的差异

| 常见做法 | 本方案 | 原因 |
|---|---|---|
| 情绪标签云 / 词云 | 单点坐标 + 主次两词 | 词云看不出强弱关系，也不可比周与周 |
| 五维情绪雷达（能量/节奏/伤感/欢快/氛围） | 二维 (V, A) 单点 | 我们只有一路可用的信号源，硬拆五维是编数据 |
| "AI 分析你最近的心情" → 一段大模型文案 | 先算结构化坐标，再套固定句式模板 | 大模型写出来的句子无法验证；模板句每一句都能反查依据 |
| 只给结论，不给依据 | 依据 3 条 + 可纠正 | 不给依据的推断 = 玄学；不可纠正 = 强加自我认知 |
| 拿听歌数据做心理状态预警 | 明确拒绝，写进产品边界 | 越界且无临床依据 |
