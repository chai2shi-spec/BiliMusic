# 听歌日记 · 页面设计方案（AI 描述版）

> 对象：BiliMusic（HarmonyOS 手机端，`com.chai.bilimusic`）
> 交付形态：**只做设计与规格，不改 App 代码**。本文可直接作为提示词喂给 AI 或交给设计师/Figma 执行。
> 配套原型：`design/听歌日记-交互原型.html`（双击打开，可切 8 套主题色 / 深浅色 / 日周月年四周期）
> 依据：色彩与字阶逐条取自 `common/ThemeColors.ts`、`resources/{base,dark}/element/color.json`、`design/BiliMusic-设计规范.md`；数据字段取自 `model/MusicModels.ts` 的 `Track`。

---

## 0. 一句话

把「本机听歌行为」做成一份可以按日/周/月/年翻阅的私人数据报告：**上面是情绪（封面 + 一句话），中间是事实（4 个数字 + 节奏图），下面是名字（循环榜 / 常听 UP 主 / 新面孔）**。

## 1. 定位与边界

| 项 | 定义 |
|---|---|
| 页面名 | 听歌日记 |
| 性质 | 二级页（`NavDestination` push），非 Tab |
| 入口 | `RecentPage` 顶栏右侧「数据」图标；备选：设置页「我的数据」分组 |
| 出口 | 点歌曲 → 播放；「全部 ›」→ 完整榜单（Phase 2）；底部按钮 → 生成分享卡片（Phase 2） |
| 数据边界 | **只统计本机播放行为**，不拉 B 站云端听歌数据（B 站音乐没有开放听歌历史接口），文案不得暗示「账号数据」 |
| 不做 | 不做社交对比、不做好友排行、不做 AI 文案生成 |

⚠️ **前置能力（本页依赖，但不属于本页）**：现有 `Track` 只有 `playedAt`（最近一次播放时间）与 `lastPosSec`，**不足以算周维度的播放次数与时长**。需要先补一个播放会话日志（见 §5.1）。设计可以先做，落地前必须补。

## 2. 画布与骨架

- 画布 **360 × 780 vp**，左右边距 **16**，区块间距 **24**（卡片内外用 12/14）。
- 顶部沿用 `NavTitleRow`：安全区 + **56** 高，返回键 44 命中区 + 标题「听歌日记」20/Bold。**不加右侧按钮**（现有 `NavTitleRow` 无 action 槽位，加了会分叉）。
- 内容区为**单列滚动**，`Scroll` 而非 `List`（区块结构异构，不需要复用回收）。
- 底部避让 **160vp**（`SubPagePlayBar` 悬浮播放条 + 手势区，与 `FavSyncPage` 同口径）。
- 滚到顶部时标题栏不加模糊材质——本页没有长内容压顶需求，保持纯色 `bg_page`。

## 4. 逐区规格

### 4.1 周期分段（Seg）

- 尺寸 **268 × 32** 居中，背板 `bg_divider`，内边距 2，四等分。
- 选中项：实底 `themePrimary` + `themeOn` 13/Medium，圆角 6（背板内缩形成的视觉圆角，非新增档位）。
- 未选中：透明底 + `text_secondary`。
- 交互：点击即切，无动画位移，仅底色 + 字色 150ms 过渡。切周期时**保留滚动位置**（用户在榜单区切换，不应被弹回顶部）。

### 4.2 周期翻页（Pager）

- 高 44，左右各一个 44×44 命中区包 16×16 箭头（`text_tertiary`），中间日期范围 13/secondary。
- 文案：周 `10月19日 — 10月25日`；日 `10月25日 周六`；月 `2026 年 10 月`；年 `2026 年`。
- 右箭头在当前是本周时禁用（`text_disabled`，不可点）。

### 4.3 主视觉封面（Hero）

- **16:9 横图**，宽 328（360−32），高 152（裁切留 4% 余量），圆角 12，外阴影 `0 10 26 rgba(0,0,0,.26)`。
- 内容四层：封面图 → 底部 62% 黑色渐变遮罩（`rgba(0,0,0,.78)→0`）→ 左上角胶囊标签「本周封面」（11/Medium 白字，`rgba(0,0,0,.42)` 底 + 6 模糊；**标签随周期变**：今日封面 / 本周封面 / 本月封面 / 年度封面）→ 左下角标题 16/600 白字 + 副行 11 白 82%。
- 副行格式：`{UP 主} · {该周期播放次数} 次`。
- 下方 3 个小圆点（5px，选中拉长成 14×5 胶囊，`themePrimary`）：代表本期可看 Top3 封面，**左滑切换**（`Swiper` 3 页）。
- 为什么不是参考图的三卡出血：**B 站封面是 16:9 视频缩略图**，竖版裁切会把构图、字幕、人像全切掉；而在 360 宽上做三卡出血，两侧只剩 38px 的色条，读不出是封面。

### 4.4 一句话

- 13/secondary，居中，上下留白 12/0，单行优先、最多两行（`maxLines(2)`）。
- 句式库（按数据选一条，**不做 AI 生成**）：
  - 有明确 Top1：`这一周，你反复遇见了 3 首歌`
  - 天数偏少：`这一周你只来了 2 天，但每次都很专注`
  - 单曲特别集中：`43% 的时间都给了《夜行》`
  - 无数据：见 §7

### 4.5 四个数字（KPI Grid）

- 4 等分，数字在上、单位在下：`24/SemiBold` + `11/text_tertiary`（**单位不跟数字同行**，否则 4 位数会被挤爆：`8,932 次播放` 在 83px 列宽里贴死下一列）。
- 四格口径：**听歌时长**（小时）/ **播放次数**（次播放）/ **不同歌曲**（首歌曲）/ 第四格随周期变：周月年用**听歌天数**（天听歌），日用**UP 主数**（位 UP 主）。
- 数值格式化：≥ 10000 用 `1.2 万`；1000–9999 加千分位 `8,932`；时长一位小数 `12.4`，整数不补零。

### 4.6 听歌节奏（Chart Card）

- 卡底 `brand_surface`，圆角 12，内边距 14/14/8，上边距 16。
- 头部：左「听歌节奏」16/SemiBold，右提示 13/`themeDeep`，文案 = `周五最多` / `21:00 最多` / `第 3 周最多` / `9 月最多`。
- 图区高 92，柱状：
  - 柱数**随周期变**：日 24 根 / 周 7 根 / 月 5 根 / 年 12 根。
  - 柱宽随之收窄：7 根 14px、12 根 9px、24 根 6px；圆角 = pill（上下全圆），柱底对齐。
  - 峰值柱实底 `themePrimary` 100%，其余 24% 不透明度——**一根柱就能读出「哪天最多」**。
  - 最小值 4% 高度（保证 0 也有个点，不出现空白列）。
- 虚线：`themePrimary` 55% 不透明度，位置 = 平均值 / 最大值，横贯全宽。
- X 轴：11/text_tertiary，每根柱一个刻度位，**标签按密度抽稀**（24 根只标 0/6/12/18/23）。
- 卡底一行小字：`虚线 = 日均 1.8h`（11/tertiary）。**不把均值标注压在柱子上**——日在 18–23 点柱高，标签会盖住数据。

## 5. 数据口径（这一节决定页面能不能真的算出来）

### 5.1 需要补的采集能力

现有 `Track` 只有 `playedAt`（最近一次）与 `lastPosSec`（续播位置），**无法还原「一周内听了几次、听了多久」**。需要新增一份会话日志，与下载/收藏解耦：

```
PlaySession {
  trackId: string
  title: string
  artist: string
  upMid: string
  coverUrl: string
  startedAt: number     // 开始播放的 ms 时间戳
  ms: number            // 本次有效收听毫秒（不含暂停）
  completed: boolean    // 是否自然播完
}
```

- **写入时机**：`MusicPlayer` 的 4 个点结算——暂停、切歌、播放完成、App 退到后台（`onBackground` 是划卡杀进程前最后一个可靠时机）。
- **存储**：**不要进 Preferences**。`Preferences` 有 8192 字节上限，本周内几百条会话就会把整份设置挤坏。走文件：`filesDir/listen_log/YYYY-MM.jsonl`，每行一条 JSON，按月分片，保留 13 个月（年视图要跨年对比）。
- 只在 `ms ≥ 1000` 时落库，避免「点开就切」制造噪音。

### 5.2 指标定义

| 指标 | 口径 |
|---|---|
| 有效收听 | 单次会话 `ms ≥ 30000` 或 `ms ≥ duration × 50%` 计为 1 次 |
| 听歌时长 | 周期内所有会话 `ms` 求和（**不是** `duration` 求和，中途切歌不能按整首算） |
| 播放次数 | 有效收听次数 |
| 不同歌曲 | 有效收听里去重后的 `trackId` 数 |
| 听歌天数 | 周期内有 ≥1 次有效收听的自然日数 |
| 峰值 | 周期内按「日/周/月」分桶后时长最大的那个桶 |
| 循环榜 | 按播放次数降序，同次数按总时长降序，取 Top3 |
| 常听 UP 主 | 按 `upMid` 聚合时长降序；`upMid` 为空（音乐中心/已下载）时回落按 `artist` 聚合 |
| 新面孔 | 周期内有播放、且本机历史中**首次出现时间落在本周期内**的 UP 主 |
| 封面 | 取该曲 `coverUrl`（B 站 16:9 缩略图，请求时用 `@480w` 规格） |

### 5.3 周期边界

- 日 = 自然日 00:00–24:00（本地时区）。
- 周 = **周一起算**（中文习惯），到周日 24:00。
- 月 = 自然月；年 = 自然年。
- 跨零点的一首歌：按 `startedAt` 归属，**不拆分**（拆分会双计次数）。

## 7. 空态与降级（必须做，否则新用户看到一屏 0）

| 场景 | 表现 |
|---|---|
| 本周期无任何有效收听 | 保留封面位（换成 `brand_surface` 底 + 空心小电视图标）→ 一句话换「这周还没听歌」→ 四数字全 `0` → 图表画平轴 + 「暂无数据」→ 榜单/常听/新面孔三块**整块隐藏**（不显示空列表）→ 底部按钮换成 `去首页听点音乐 ›`（次级按钮，非实底） |
| 只有 1–2 首歌 | 榜单有几行显示几行；「全部 ›」隐藏；封面点指示器变 1/2 个点 |
| 上周/上月无数据（翻页） | 内容区整体降透明度到 60% + 居中「这一周你没有听歌记录」，**仍允许翻页**（不要禁用箭头，用户需要能翻回来） |
| 封面加载失败 | `brand_surface` 纯色底 + 居中 24px 音乐图标，不留白 |
| 时长统计缺失（会话日志未覆盖到该周期） | 该格显示 `—` 而不是 `0`（0 是"没听"，— 是"没统计到"，两者不能混） |

## 8. 动效（沿用 `设计规范 §6.2` 五档时长）

| 元素 | 动效 | 时长/曲线 |
|---|---|---|
| 切周期 | 数字滚动（旧值 → 新值）+ 柱子高度过渡 | 250ms EaseInOut |
| 柱子入场 | 从 0 长到目标高度，相邻错峰 30ms，**只做首屏可见的一屏** | 250ms + 30ms×i |
| 卡片入场 | 淡入 + 上移 8vp | 250ms EaseOut |
| 封面向左滑 | `Swiper` 跟手 | 系统曲线 |
| 按压反馈 | 卡片/行 `press_overlay` 叠色，**不做缩放**（本页无 `TrackItem` 的 scale 传统） | 100ms |

红线：容器只做淡入，位移交给子项；不动 `width/height`。

## 9. 触达与无障碍

- 「全部 ›」视觉 13px，命中区 **44×44**，与右侧屏幕边距之间留 **8vp** 缓冲（避免贴着边缘误触）。
- 分段每项宽 66，高 32 < 44——**在 32 高的胶囊外套 44 高的透明容器**承接点击。
- 播放条避让：内容末尾留 160vp，最后一块不被悬浮条压住。
- 对比度：正文 `text_secondary` 5.31:1、三级 4.62:1、`themeDeep` 5.81:1，均 ≥ AA；`themePrimary` 只出现在 ≥18px 或图形上。
- 读屏：封面 `accessibilityText` = 歌名 + UP 主；柱状图容器给一句汇总「本周日均 1.8 小时，周五最多」，不逐柱朗读。
- 系统「减少动效」开启时：柱子直接落位、数字跳跃、卡片纯淡入。

## 10. 可直接粘贴给 AI 的提示词

### 10.1 整页（首次生成用）


## 12. 与参考图的差异（为什么不照抄）

| 参考图 | 本方案 | 原因 |
|---|---|---|
| 三张竖版人像封面出血 | 单张 16:9 横版 + 圆点指示 | B 站封面是视频缩略图，竖裁会毁构图；360 宽下三卡出血只剩色条 |
| 「统计/总结」双 Tab 在顶栏 | 去掉，只保留「统计」 | App 顶栏 `NavTitleRow` 无 action 槽位；且「总结」= 同页更长文案，另开 Tab 是伪需求 |
| 数字与单位同行（36 小时） | 数字在上、单位在下 | 4 位数（8,932）同行会贴死下一列 |
| 歌手头像/姓名字段 | UP 主（`upMid`） | B 站音乐来自 UP 主投稿，聚合维度天然是 UP 主；`upMid` 为空才回落 `artist` |
| 固定 7 根柱 | 柱数与柱宽随周期变 | 选了「日」就是 24 个时段，固定宽度必然重叠 |
| 「观看本周回顾」视频入口 | 「生成回顾卡片」（Phase 2） | 本 App 无年度视频能力，做成可分享图片更实际 |
