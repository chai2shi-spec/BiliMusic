# 平板横屏播放页 · 封面舞台（Cover Stage）

> 目标版式：**大封面满幅铺满左半屏 → 右缘渐变溶解到歌词 → 控制区玻璃面板悬浮在封面之上 → 功能区紧贴面板之下**。
>
> 基线代码：`components/player/PlayerInfoComponent.ets`（1299 行）、`ControlAreaComponent.ets`、`LyricsComponent.ets`、`CoverDiscComponent.ets`。
> 参考机型：1280×800 vp（MatePad 类）、1024×640 vp（小平板）、1600×1000 vp（13.2" 大平板）。

---

## 1. 现状：平板横屏走的是「栅格分栏」，不是「封面舞台」

真平板横屏（`!isFoldFull && isLandscape && (lg | md)`）命中 `PlayerInfoComponent.build()` 第 1013–1128 行：

```
GridRow(12 列, gutter 24) {
  GridCol(span 5, offset 2) {      ← 左列：圆盘 + 标题块 + 控制区(SpaceBetween)
    CoverDiscComponent({ discSize: lgDiscSize })
    标题块（歌名/歌手/音质）
    ControlAreaComponent()          ← 在列底
  }
  GridCol(span 5, offset 2) {      ← 右列：歌词
    LyricsComponent({ isShowControl: false })
  }
}
```

四笔账（1280×800 实测口径）：

| 项 | 计算 | 结果 |
|---|---|---|
| 栅格内宽 | 1280 − 24×2(padding) − 24×11(gutter) | 944 |
| 单列宽 | 944 / 12 | 78.7 |
| 左列宽（span 5） | 78.7 × 5 + 24×4 | **490** |
| 左列左缘 x | 24 + 78.7×2 + 24×2 | **230** |
| 圆盘预算 | min(列宽 490, 800 − 48(顶栏) − 178(控制区) − 90(标题块) − 24(底边距)) | **460** |
| 圆盘实际占宽 | 460 / 1280 | **36%** |
| 圆盘实际占高 | 460 / 800 | **58%** |

**结论：屏幕上 0–230vp 是一整条空白，圆盘只占 36% 屏宽、58% 屏高。**「大封面」在现状里是不成立的。

另外三处结构性问题：

1. **控制区被 `SpaceBetween` 推到底**，与封面、标题块三者间距随窗口高度浮动（1600×1000 时封面与标题之间会拉开 100vp+），没有「一块整体」的感觉。
2. **两列之间只有 24vp 空白**，封面边缘是硬边、右列是同一张模糊底，视觉上是「并排两个面板」，不是「一张图延伸出去」。
3. **歌词列实际可用行宽很窄**：右列 490，`LyricsComponent` 在 lg 分支还套了一层 `COLUMN_LYRIC_LG = 7` 列的窄栅格（第 1481–1505 行），行宽被压到 **≈ 300vp**，长句频繁折行；而 `LrcView.ets:169/171` 的字号是硬编码私有字段 `20 / 24`，平板上和手机一样大。

```
┌─────────────────────────────┬──────────────────────────────┐
│ ←  ✕                        │  夜航星                 ♡  ⋯ │  ← 右半屏头部（y 72..176）

│      大封面 640 × 800        │     晚安 夜航星               │
│      （满幅 · Cover 裁切）    │   ◆ 沉入海底的第七个夜          │  ← 当前行 30fp
│                             │     我数着光年之外的            │
│                             │     一颗不肯熄灭的灯            │
│   ╭───────────────────────╮ │                              │

│    ♡    💬    ⬇    ☰    ⋯   │                              │  ← 功能区（面板之下）
└─────────────────────────────┴──────────────────────────────┘
 ←———— 640 ————→←———— 640 ————→
        封面右缘 220vp 渐变         右半屏实色 rgba(deep, .94)
```

层次自底向上（**这是实现顺序，顺序错了会出现色带/接缝**）：

| 层 | 内容 | 尺寸 / 位置 |
|---|---|---|
| L0 | 整页模糊封面 + 纵向压深（现有 `SurfaceLayers()`，不改） | 全屏 |
| L1 | 封面，满幅 `ImageFit.Cover`，圆角 0 | 640 × 800 @ (safeLeft, 0) |
| L2 | 封面右缘渐变：`deepRgb` 0 → 0.97 | 220 × 800 @ (640−220, 0) |
| L3 | 底部 scrim：`deepRgb` 0 → 0.34 | 640 × 280 @ (0, 520) |
| L4 | 右半屏实色 `rgba(deepRgb, 0.94)` | 640 × 800 @ (640, 0) |
| L5 | 右半屏内容：头部 104（y 72..176）+ 歌词 572（y 204..776） | 内边距 48 |
| L6 | 玻璃面板（进度 + 三键） | 560 × 168 @ (40, 554) |
| L7 | 功能区（9 项一屏，无分页） | 560 × 46 @ (40, 734) |
| L8 | 顶栏（退出），顶部 scrim 110 | @ (24, safeTop + 8) |

### 2.1 为什么封面用「满幅裁切」而不是「方形居中」

左半屏是 640×800，比例 0.8；方形封面放进去必然二选一：留 80vp 上下黑边，或左右各裁 10%。

**选裁切，因为右缘 220vp 本来就会被渐变吃掉**（占屏宽 17%），右侧裁掉的 10% 正好在渐变区里、肉眼不可见；实际可感知的裁切只剩**左缘 80vp**。而留黑边会让「占满左边半屏」这个前提直接不成立。

> 若某张封面的主体贴左边缘，退路是变体 B（圆形居中，见 §5）。

### 2.2 渐变接缝：必须让两侧「叠在同一张模糊底上」

右半屏是 `blur(cover)`，左半屏是 crisp cover，直接渐变会出现一条竖向亮边。做法是**左右两侧用同一个 flat 色压深**：

- 渐变末端 = `rgba(deepRgb, 0.97)` 叠在 crisp cover 上
- 右半屏底 = `rgba(deepRgb, 0.94)` 叠在 blurred cover 上

两者底下都是同一张封面（一个清晰一个糊），在 0.94+ 的不透明度下底层只贡献 3–6% 亮度差，**接缝 ΔRGB ≤ 3**，肉眼不可见。

⚠️ **不要**给右半屏用「模糊图 + 0.6 压深」这种半透做法——那会让接缝处出现最多 12% 的亮度台阶（亮封面尤其明显）。

### 2.3 控制区与功能区的顺序反转

现状 `ControlAreaComponent.build()` 是 **功能行 → 进度区 → 三键行**（第 1004–1125 行）。舞台要求 **进度 → 三键 → 功能行**，即：

```diff
- 功能行（Swiper 分页，每页 4）
- PlayerProgressArea()
- 三键行
+ PlayerProgressArea()      ← 面板内上
+ 三键行                     ← 面板内下
+ 功能行（9 项一屏，无分页）  ← 面板外下
```

反转有三个连带的必须处理项（见 §6 风险 2/3）：`bindSheet` 宿主挂在功能行 Swiper 上、`FUNC_ITEMS_PER_PAGE` 要按舞台改成 9、`onAreaChange` 实测回填的控制区高度不再被封面预算消费。

## 3. 尺寸账（逐行）

### 3.1 1280×800（主档）

```
视觉层满幅 H = 800（出血到状态栏下）
左半屏 L = 640，右半屏 R = 640

封面      640 × 800          （满幅，无内边距）
渐变带    220 × 800  @ x 420   （0.34L，clamp 160..280）
底部scrim 640 × 280  @ y 520   （= 面板顶 554 − 34 起渐隐）
面板      560 × 168  @ (40, 554)
          560 = 640 − 2×40（margin = 0.0625L）
          168 = 14(pad) + 52(进度) + 12(gap) + 76(三键) + 14(pad)
          554 = 800 − 20(底边距) − 46(功能行) − 12(间隙) − 168
功能行    560 × 46   @ (40, 734)
          46 = FUNC 按钮 46（H ≥ 720 取舒适档）
右头部    544 × 104  @ (688, 72)
          歌名 32fp/行高40（≤2 行）→ 歌手 15fp(+8) → 音质 12fp(+6)
歌词      544 × 572  @ (688, 204)
          544 = 640 − 96；行宽上限 640（1600 屏生效）
          当前行 30fp / 非当前 22fp / 行距 16
```

**首屏信息量对照**

| | 现状 | 舞台 |
|---|---|---|
| 封面占屏宽 | 38% | **50%（满幅）** |
| 封面占屏高 | 59% | **100%** |
| 歌词行宽 | ≈300 | **544（+81%）** |
| 歌词字号 | 20 / 24 | **22 / 30** |
| 功能项一屏可见 | 4（翻页） | **9（无翻页）** |
| 控制区位置 | 左列底部（随高浮动） | **固定悬浮面板** |

### 3.2 三档参数（同一套公式，只换密度）

```
L       = 窗口宽 / 2
H       = 窗口高（视觉层满幅，不扣 safeTop）
封面     = L × H（满幅）
渐变带   = clamp(0.34L, 160, 280)
面板宽   = L − 2 × clamp(0.0625L, 24, 60)
面板高   = 168（H ≥ 720）/ 152（H < 720）
功能键   = 46（H ≥ 720）/ 40（H < 720）
功能行高 = 功能键
底部边距 = 20（H ≥ 720）/ 16
```

| 机型 | L×H | 封面 | 面板 | 功能键 | 歌词行宽 | 歌词字号 |
|---|---|---|---|---|---|---|
| 1024×640 | 512×640 | 512×640 | 456×152 | 40 | 416 | 19 / 26 |
| 1280×800 | 640×800 | 640×800 | 560×168 | 46 | 544 | 22 / 30 |
| 1600×1000 | 800×1000 | 800×1000 | 680×178 | 46 | 640（限宽） | 22 / 30 |

### 3.3 9 项功能键的宽度验算

```
1280：9×46 + 8×12 = 510 ≤ 560 ✓
1024：9×40 + 8×12 = 456 = 456 ✓（正好，间距取 12）
1600：9×46 + 8×20 = 574 ≤ 680 ✓
```

现状 `FUNC_ITEMS_PER_PAGE = 4`，9 个功能项要翻 3 页；舞台下一屏 9 个、`funcPages()` 只返回 1 页，`funcPageCount() > 1` 恒 false → **双侧箭头条件渲染自动消失，零改动**。

> 9 是上限：`visibleFuncItems()` 会按开关过滤（倍速 / 限定进度 / 定时停止 / 在 B 站打开 / 进入 UP 主页），
> 实际可见数 ≤ 9。所以准确表述是「**平板横屏下功能行永不翻页**」，而不是「恰好 9 项」。
> 可见项少于 9 时 `justifyContent: SpaceBetween` 会把它们匀开——如果更希望聚拢，改成 `Start` + 固定 18 间距即可。

## 4. 关键决策（每条都有代码依据）

### 4.1 不改 `CoverDiscComponent` 的转场，只加一个 `fillMode`

`CoverDiscComponent.ets:144/175` 的 Image 挂着 `geometryTransition(GEOMETRY_ID_PLAYER_DISC)`，与 `PlayBar.ets:487` 的透明锚点配对（圆 28 → 全屏）。这是「一镜到底」的唯一入口，**新写一个铺满图会直接丢掉转场**。

做法：给 `CoverDiscComponent` 加 `@Prop fillMode: boolean = false`，true 时渲染 `width('100%').height('100%')` + `borderRadius(0)` + `ImageFit.Cover`，GT / 挂载守卫 / 兜底 / 切歌复位**一行不动**。

### 4.2 玻璃面板不能用 `systemMaterial`

`SubPagePlayBar.ets` 文件头的真机实测结论：`systemMaterial` 在自绘容器上**静默退化全透明**，只在 Navigation 标题栏 / Tabs TabBar 生效。

舞台面板压在**清晰封面**上（不是模糊底），所以必须真的把底层糊掉：

```ts
.backgroundColor('rgba(255,255,255,0.10)')
.backdropBlur(24)                                  // 主选
.border({ width: 0.5, color: 'rgba(255,255,255,0.16)' })
.shadow({ radius: 40, color: 'rgba(0,0,0,0.35)', offsetY: 12 })
```

**退路（真机 `backdropBlur` 对 Image 无效时）**：去掉 blur，把底改成 `rgba(255,255,255,0.14)` + 一层 `rgba(deepRgb,0.22)` 压深 —— 视觉上「半透明深色玻璃」，不依赖任何模糊能力。

### 4.3 封面风格（`coverStyle`）在舞台下二选一

现有设置「封面风格：唱片 / 方卡」在手机上差异很大（圆盘 vs 圆角方卡），但在**满幅出血**的舞台上两者都变成矩形，设置会失效。

决策：舞台下 `coverStyle` **改语义为舞台变体**——

| 设置值 | 舞台渲染 |
|---|---|
| `square`（默认） | **满幅出血**（主案，640×800，Cover 裁切） |
| `disc` | **圆盘居中**（变体 B，直径 `min(L−96, 面板顶 − 48)`，右缘渐变照旧） |

设置页那一项副标题补一句「平板横屏下：方卡 = 满幅铺满 / 唱片 = 居中圆盘」，避免用户以为设置丢了。

### 4.4 路由：只服务「真平板」，不动折叠屏展开横屏

新增判定，插在 `build()` 的 `isCompactLandscape()` **之前**：

```ts
private isTabletStage(): boolean {
  return !this.isFoldFull          // 折叠屏（含展开横屏）一律不进来
    && this.isLandscape
    && this.windowWidthVp >= 840   // md 横屏（600–840）左半屏放不下 9 键 + 面板
    && this.windowHeightVp >= 560; // 矮于此，面板+功能行占 39% 高
}
```

**为什么不接管折叠屏展开横屏（Pura X 1432×721）**：它现在走 `isCompactLandscape()`（`isFoldFull && isLandscape` 直进），版式已在真机验证过；一次改动同时动两类设备，出问题无法二分。第二版再评估。

**为什么卡 840**：600–840 的横屏窗口（如 800×600 折叠外屏横屏）左半屏只有 400，面板 360 宽放 9 个 40 键 = 360，零间距，不成立。

### 4.5 横屏下滑收起：不用处理（但别加回来）

`PlayerPage.dragDismissEnabled()`（第 105–113 行）已限定 `sm` 或 `isWideFoldFull`，平板横屏天然不启用 —— **悬浮面板在底部不会被下拉手势抢走**。这条是现状就对的，改动时注意别在舞台分支里重新挂 `.gesture`。

## 5. 变体 B：圆盘居中（`coverStyle = disc`）

```
封面直径 D = min(L − 2×48, 面板顶 554 − 2×24)  → 1280 档 = min(544, 506) = 506
居中于 (L − D)/2 = 67，上缘 24、下缘 530（正好压在面板顶 554 之上留 24 呼吸）
背景 = 模糊封面满幅（L0 已提供）+ 无右缘渐变（改由「模糊→实色」的 220 带过渡）
```

视觉上更接近现有手机版播放页、更保守；代价是封面占屏高从 100% 掉到 63%，且「渐变沿封面右缘走」变成了「沿一个看不见的边界走」，渐变的叙事弱一档。

## 6. 落地风险（按踩坑概率排序）

| # | 风险 | 症状 | 处理 |
|---|---|---|---|
| 1 | **`bindSheet` 跟着功能行搬家** | 队列按钮点了没反应 / 弹层从屏角弹出 | `ControlAreaComponent.build()` 第 1064 行的 `.bindSheet` 挂在功能行 Swiper 上。功能行移出面板后，必须把 `bindSheet` 一起挂到新宿主（或提到最外层 Column） |
| 2 | **控制区顺序反转动了布局属性** | 面板入场动画丢失 / 整树重排卡顿 | 现有入场只挂 `opacity/translate`（第 1126–1129 行注释明确「不动 width/height/padding」）。反转顺序是结构调整，**必须在分支外**，不能把 `.opacity/.translate` 拆到两处 |
| 3 | **`FUNC_ITEMS_PER_PAGE` 改 9 后箭头残留** | 单页仍显示左右箭头（opacity 0 但占位 2+2vp） | 箭头本身是 `funcPageCount() > 1` 条件渲染，改完自然消失；但 `Swiper` 的 `.index()` 受控 + 单页时 `loop(false)` 会有边缘回弹，舞台下建议直接换成 `Row`（无 Swiper） |
| 4 | **歌词字号放大后 Canvas 折行** | 长句被裁 / 副行（翻译）压到下一行歌词 | `LrcView.ets` 是 Canvas 手绘，`drawSingleLine/drawMultipleLine`（第 994–1033 行）按 `mNormalTextSize` 算 `lineHeight`。加大字号必须同时复核 `subHeight` 与 `lyricY` 推进量，行宽不变字号 +37% 必然多折一行 |
| 5 | **旋转后首帧错位** | 转屏瞬间封面小一号再弹回 | 现状 `lgDiscSize` 靠 `onAreaChange` 回填（首帧 0）。舞台尺寸是 `f(L, H)` **纯计算**，不依赖实测 → 天然无此问题；**别把面板高度也做成实测回填**（`H<720` 的档位判定用窗口高即可） |
| 6 | **渐变末端色值写死** | 切歌后渐变带与右半屏色差显现 | 两端都必须读 `deepRgb`（`buildRgba(this.deepRgb, α)`），不能用 `Color.Black`。切歌时 `deepRgb` 有个 600ms 颜色动画，渐变带要跟着走同一条 `animateTo` |
| 7 | **顶栏压在封面上不可辨** | 浅色封面时退出按钮看不见 | 顶部 scrim 96 高 `deepRgb` 0.35 → 0；顶栏 `.position()` 绝对定位（现状是常规流 `Row`，`TopAreaComponent` 第 93 行） |
| 8 | **安全区** | 折叠屏展开横屏/带挖孔平板左侧被切 | 封面 x 起点 = `safeLeft`，宽 = `L − safeLeft`；右半屏宽 = `R − safeRight`。平板横屏两值通常 0，但不能省 |
