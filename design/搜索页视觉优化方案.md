# 搜索页视觉优化方案

> 2026-10-26 · Figma 界面架构师（范格玛）
> 目标工程：`E:/BiliMusic/HarmonyOS-Phone`
> 范围：`pages/SearchPage.ets`（2271 行）+ `components/SearchTabBar.ets`（131 行，实际只含 `SearchInputBar`）
> **本文只出方案，不改代码。**
> 可视化原型：同目录 `搜索页视觉优化-交互原型.html` —— 现状 / 优化后并排、5 个状态切换、8 套主题逐个切换（验「chip 底 / 聚焦描边 / 段控选中块是否同步变色」）、浅色深色切换、改动标记开关。

---

## 0. 一句话结论

搜索页**不缺元素，缺的是层次**。当前一屏里有 6 处 13fp 灰色小字、3 种圆角胶囊、品牌色只出现 1 次 —— 结果是"什么都有、但没有主次"，而且换任何一套主题色，这一页看起来都一样。

本方案**不新增任何功能模块、不重构列表**，只做三件事：把 13fp 收敛成"11fp 分组标签 + 13fp 控件文字"两级；把三种胶囊用圆角与底色分工；给品牌色三个有语义的落点。全部改完后 13fp 从 6 处降到 3 处，视觉层次由"位置"转为"字号 + 色彩"。

### 1.3 ⚠️ 一处记忆纠正（先记下来，别再用旧结论）

项目记忆里写着「搜索页页签行仍是 **49.6**（`SearchTabsBar` 的 `height(49.6)` + `padding.top 17.6`），没有并入 44 体系」。

**这条已经过时**，实测：

- `SearchTabsBar` 全仓 **0 处引用**，组件已不存在（`components/SearchTabBar.ets` 这个文件名现在只装 `SearchInputBar`）
- 全仓 **无 `49.6`** 字面量
- 现在让位公式极简：`listStartOffset() = safeTop + NAV_TITLE_BAR_HEIGHT(56) + SEARCH_LIST_START_EXTRA_VP(12)`，被 5 处消费

所以"页签行几何调不动"那套推导对本页**已不适用**，改间距不会有连带风险。但也正因为那个 12 现在**同时承担落地页顶部间距和结果页列表首项占位**，两个场景需求不同却共用一个值 —— 这是本方案要拆的第一件事。

## 2. 七个问题（按影响排序）

### P1 · 顶部 12vp 太紧，且标题与搜索框同色同号

- 「常用搜索」= 13fp `text_tertiary` #8A8A90
- 搜索框 placeholder = 13fp `text_secondary` #6B6B70
- 两者距离仅 12vp

**后果**：标题读起来像"搜索框的第二行说明"，而不是一个新分组的开始。

### P2 · 13fp 在搜索页出现 6 次，16fp 只出现在词条

13fp：常用搜索标题、chip 文字、段控、右侧文字按钮、「UP主」/「视频」标签、搜索框
16fp：历史词条、热搜词条

**后果**：除了列表内容，所有东西都是 13fp 灰字，层级只能靠"上下位置"推断。

### P3 · 三种"胶囊"视觉语言冲突（本方案认为这是最该修的一条）

| 控件 | 圆角 | 底 | 描边 |
|---|---|---|---|
| 词 chip | 14 | `bg_card` 白 | 0.5 `bg_divider` |
| 分段切换器 | 背板 8 / 选中块 6 | 灰背板 + 选中实底 | 无 |
| 搜索框 | 18 | `bg_card` 白 | 0.5 `bg_divider` |

**后果**：chip 与搜索框**同底同描边**，只差圆角 14 vs 18（几乎看不出）→ 用户会把 chip 当成"缩小版搜索框"。而 chip 与段控圆角差 8，又不足以一眼区分"标签"和"切换器"。

### P4 · 品牌色几乎缺席

全页只有热搜前三名的序号用了 `themeDeep`。**换 8 套主题色，搜索页几乎无变化** —— 用户要求的"符合主题"这一条实际没做到。

### P5 · 「删除搜索记录」以 13fp 常驻在段控右侧

低频 + 破坏性操作，却与段控同排、同字号、同显眼度。既损害简约，也增加误触面。

### P6 · 空态只有一行字

`Text('没有找到相关内容，换个关键词试试')` + `margin-top: listStartOffset() + 48`

无图标、不回显关键词、无出口（不能一键清空重搜）、不给推荐词。

### P7 · 常用搜索的编辑态不可发现

长按 400ms 才进编辑态（词旁出现红 ✕），界面**没有任何提示**。功能存在但用户找不到 —— 这是需求缺口，不是美观问题。

## 3. 设计原则（三条）

1. **一屏之内，圆角只有两档语义**：可点的独立标签 = full 圆角实底；组内切换器 = 小圆角（8/6）。**靠圆角 + 底色分工，不靠加描边**。描边是"输入框"的专利。
2. **分组标签降为 11fp，而不是继续堆 13fp 灰字**。层级用"字号差 + 色彩差"表达，不靠上下位置。
3. **品牌色只出现在有语义的位置**：聚焦态、当前选中、热搜前三。不做装饰性铺色。

## 4. 具体方案

### 4.1 P0 · 拆开共用的 12vp，重建垂直节奏

| 位置 | 当前 | 建议 | 依据 |
|---|---|---|---|
| 结果页列表首项占位 | 12 | **16** | 列表紧接搜索框，12 偏挤、16 与 `NAV_H_PADDING` 同档 |
| 落地页顶部间距 | 复用上面的 12 | **24（新常量）** | 分组起始需要有"换气感" |
| 「常用搜索」标题 → chip 群 | 8 | 8（不变） | 标题与自己的内容必须紧贴 |
| chip 群 → 段控行 | 24 | **20** | 标题变小后整体收紧，24 显松散 |
| 段控行 → 列表首项 | 4 | **8** | 4 太贴，8 与"同级元素间距"一致 |

**实现要点**：新增 `SEARCH_STATE_TOP_VP = 24`，`CommonWordsSection` 的 `margin.top` 从 `listStartOffset()` 改为 `safeTop + NAV_TITLE_BAR_HEIGHT + SEARCH_STATE_TOP_VP`；`SEARCH_LIST_START_EXTRA_VP` 单独改 16，**只影响结果页与骨架**。

⚠️ 这两个量必须**分开成两个常量**。若继续共用一个，改落地页就会把结果页列表推下去 12vp。

### 4.2 P0 · 把 13fp 收敛成两级

| 元素 | 当前 | 建议 |
|---|---|---|
| 「常用搜索」 | 13fp `text_tertiary` | **11fp `text_secondary` + 字距 0.3** |
| 「UP主」/「视频」小节标签 | 13fp `text_tertiary` | **11fp `text_secondary` + 字距 0.3** |
| 「删除搜索记录」/「刷新」 | 13fp `text_tertiary` | **11fp `text_tertiary`** |
| chip 文字 | 13fp | 13fp（不变） |
| 分段切换器 | 13fp | 13fp（不变） |
| 搜索框输入/占位 | 13fp | 13fp（不变，框内空间约束） |
| 历史 / 热搜词条 | 16fp | 16fp（不变，这是内容主体） |

**为什么标签用 `text_secondary` 而不是继续用 `text_tertiary`**：11fp 已经是最小档，再叠最浅的灰会看不清。实测对比度：

- 浅色 `#6B6B70` on `#F5F5F5` = **5.31:1**
- 深色 `#ABABB5` on `#121216` = **8.21:1**

两者都稳过 AA。而如果保持 `text_tertiary` 11fp：浅色 4.62:1、深色 4.99:1 —— 也合规，但 11fp 小字压在 4.6:1 上边缘，观感偏虚。**所以降字号的同时必须提一档色**，这两件事不能只做一件。

### 4.3 P0 · chip 改用主题 surface 底，去掉描边

| 属性 | 当前 | 建议 |
|---|---|---|
| 底 | `bg_card`（白 / #1E1E24） | **`themeSurface`**（浅 #FFF1F5 / 深 #33222B） |
| 描边 | 0.5 `bg_divider` | **去掉** |
| 圆角 | 14 | **15**（chip 高约 30 → 视觉近 full） |
| padding | 12 / 6 | 不变 |
| 文字 | `text_primary` | 不变 |
| 按压态 | `press_overlay` | 不变 |

**三件事同时发生**：

1. **形成品牌色层级**：白底页面上一片淡粉 chip 群，不必用任何装饰图形就完成了"符合主题"。换主题色时 chip 跟着变 —— 这正好补上 P4。
2. **与搜索框彻底分开**：搜索框保留"白底 + 0.5 描边"（输入框语言），chip 变成"实底无描边"（标签语言）。此前两者同底同描边、只差圆角，本就是误读来源。
3. **密度下降**：去掉描边后 chip 群的横向视觉重量变轻，更简约。

**对比度实测**（`text_primary` on `themeSurface`）：

- 浅色 `#1A1A1A` on `#FFF1F5` = **15.9:1**
- 深色 `#F5F5F7` on `#33222B` = **13.7:1**

远高于 AA 7:1，**淡底不会牺牲可读性**。

⚠️ **技术前提**：搜索页当前只订阅了 `STORE_THEME_DEEP` / `STORE_THEME_PRIMARY` / `STORE_THEME_ON`，**没有 `STORE_THEME_SURFACE`**。必须新增 `@StorageProp(STORE_THEME_SURFACE) themeSurface: string = '#FFF1F5'`，否则只能用静态资源 `$r('app.color.brand_surface')` —— 那是构建期常量，**不跟主题切换**，等于没做到"符合主题"。

⚠️ 同一个 `themeSurface` 也给「＋」chip 用（两者目前同款式），保持成组一致。

### 4.4 P1 · 搜索框聚焦时才描边（品牌色落点之二）

| 状态 | 当前 | 建议 |
|---|---|---|
| 静态（未聚焦） | 0.5 `bg_divider` | **无描边**，仅 `bg_card` 底 |
| 聚焦 | 同静态（无反馈） | **1vp `themePrimary` 描边** |

**理由**：搜索页一进来就 `defaultFocus(true)` 自动聚焦弹键盘，静态态基本只在"用户主动收起键盘后"出现。把描边让给聚焦态，既省掉一条常驻线，又给品牌色一个**有功能含义**的落点（不是装饰）。

实现需新增 `@State inputFocused: boolean = false` + `.onFocus()/.onBlur()`。

⚠️ 描边宽度 0.5 → 1 会让搜索框内容宽度缩 1vp（左右各 0.5）。36 高的框内可忽略，但若严格对齐左缘，需把聚焦态 padding 由 12 调为 11.5，或改用 `.outline()`（不参与布局）。

### 4.5 P1 · 空态重做（信息 + 出口）

当前：一行 16fp 文字，`margin-top: listStartOffset() + 48`。

建议结构（整体在内容区垂直居中，不再用 margin 硬算）：

```
[放大镜图标 48fp, text_disabled]
[主文案 16fp text_primary]   没有找到「{keyword}」的相关内容
[副文案 13fp text_secondary]  试试更短的关键词，或检查有没有错别字
[推荐词 chip ×3]             取 commonWords 前 3，点击直接重搜
```

**四个改进点**：

1. **图标**给"这是空态"一个非文字信号，扫一眼就懂
2. **回显关键词**：用户能立刻发现自己是不是打错了字（当前版本连搜的是什么都没提）
3. **给出下一步**：不只有"换个词试试"，直接给三个可点词
4. **去掉 `+48` 的魔数**：垂直居中由布局决定，不跟 `listStartOffset` 耦合

### 4.6 P1 · 让「常用搜索」的编辑态可发现

在「常用搜索」标题行右侧加一个 **11fp `text_tertiary` 文字按钮**：

- 常态显示「编辑」→ 点击进编辑态
- 编辑态显示「完成」→ 点击退出
- 与段控行右侧「删除记录」同一套语法（11fp / tertiary / padding 8 横向 / 44 命中区）

长按手势**保留**（老用户习惯），但不再作为唯一入口。这是 P7 那个"功能存在但找不到"的直接修法，且不新增任何布局行。

### 4.7 P2 · 段控宽度 124 写死

现状 `width(124)`，注释里是自己算出来的（背板 4×2 + 「最近搜索」≈52+16 + 「热搜」≈26+16）。

**风险**：系统字体放大到 1.2x 以上时文字会截断。而 V2 分段按钮"给多大渲染多大（均摊各段）"，去掉宽度会塌成"玻璃细棍"。

**建议**：保留显式宽度，但给到 **132**（约 6% 余量），并在注释里写明"这是按 1.0x 字体算的，1.3x 以上会截断"。**这是已知限制，不是完美解** —— 真要自适应需要弃用 V2 自绘，代价大于收益，不建议。

## 5. 状态矩阵（改完后逐状态核对）

| 状态 | 顶部 | 主体 | 品牌色出现 |
|---|---|---|---|
| 刚进页（空历史） | 搜索框聚焦描边 | 常用搜索 + 热搜独占（无段控，显示「热搜」文字标签） | 描边 + chip 底 |
| 有历史 | 同上 | 常用搜索 + 段控（最近搜索）+ 列表 | 描边 + chip 底 + 选中块 |
| 切到热搜 | 同上 | 常用搜索 + 段控（热搜）+ 榜单（前三序号 themeDeep） | 描边 + chip 底 + 选中块 + 序号 |
| 搜索中（loading） | 描边 | 8 行骨架 | 描边 |
| 有结果 | 描边 | UP主标签 + 卡行 + 视频标签 + 列表 | 描边 |
| 无结果 | 描边 | 空态（图标 + 回显 + 推荐词） | 描边 + chip 底（推荐词） |
| 有 UP 无视频 | 描边 | UP主标签 + 卡行（不出现「视频」标签） | 描边 |
| 编辑常用词态 | 描边 | chip 旁红 ✕ + 标题行「完成」 | 描边 + chip 底 + error 色 |

**注意**：`chip 底` 在深色模式是 `#33222B`，与 `bg_page #121216` 的明度差很小（视觉上"深棕"）。这是**有意为之**——深色模式下用低对比实底代替描边，比浅色模式更依赖"亮度微差"，符合深色 UI 惯例。如果真机看下来太糊，退路是把深色态的 chip 底改为 `bg_card #1E1E24`（更像"浮起的卡"），但那样就失去了主题色倾向，不如前者。

## 6. 与既有五条铁律的一致性核对

| 铁律 | 本方案是否合规 | 说明 |
|---|---|---|
| ① 灰阶只用三档 | ✅ | 只用到 `text_primary` / `text_secondary` / `text_tertiary`，无新增灰 |
| ② 字阶只用六档 24/20/18/16/13/11 | ✅ | 只用到 16 / 13 / 11，**全部在档内**，未引入 12/14/15 |
| ③ 品牌色只用于大字/图标/实底 | ✅ | 三处用途：chip 实底、搜索框聚焦描边（图形）、段控选中块与热搜序号（既有权衡）。**没有一处是白底粉小字** |
| ④ 命中区 ≥44 | ⚠️ **需补** | 新增的「编辑/完成」文字按钮必须 44 命中区（当前「删除搜索记录」`padding left 8 / top 4 / bottom 4` 只有约 26 高，**本方案顺手修正**） |
| ⑤ 可点元素必须有按压态 | ⚠️ **需补** | 新增的推荐词 chip、「编辑」按钮必须带 `stateStyles(pressed: press_overlay)` |

第 ④ 条那个发现值得单独说：**当前「删除搜索记录」/「刷新」的命中区高度只有约 26vp**（13fp 字 + 上下各 4 padding），低于 44 铁律。这是一处既存违规，改的时候一并补上（加 44 高容器，视觉不变）。

## 7. 明确不做的六件事

1. **不加"共 N 条结果"** —— 搜索接口只返回 `numPages`，没有 total 字段（`searchTotalPages` 是页数不是条数）。要显示得额外请求或不准确计数，**违背简约，不做**。
2. **不把「常用搜索」改成横向滚动单行** —— wrap 换行虽然占高度，但一次能看到全部 8 个词，比"藏起来要横滑"更高效。用降字号 + 收紧间距解决占位问题即可。
3. **不动 UP 主卡片（156×184）** —— 它与首页快捷卡 `HomeQuickCards` 是同一套几何，**共享组件语言不能单方面改**，否则两页不一致。
4. **不重构为"搜索前/搜索后"两套顶栏** —— 现在搜索框在 HDS titleBar 里、`56` 锁高，是顶栏规范 v2 的既定结构。拆掉会牵动 `HdsTitleBarStyle` 与整个顶栏体系。
5. **不给搜索页加返回键改造 / 手势区调整** —— 返回键是 HDS 默认件，`NavTitleRow` 已统一，不属于本页问题。
