# 播放页 · iPod Classic 外壳方案

> 目标：把播放页做成**一台立着的 iPod Classic 实体**——不是给现有页面套一圈边框，而是让机身成为页面本身。屏幕里是正在播放，转盘是唯一的手势入口。
>
> 基准机型：iPod Classic 6th Gen（103.5 × 61.8 × 10.5 mm）。**所有尺寸由真实物理尺寸等比换算**，不靠目测。

---

## 一、为什么这个形态成立

三件事决定了它必须是「整机」而不是「皮肤」：

1. **屏幕是 4:3 横向的。** iPod 竖持时机身窄、屏幕宽——这块屏的横宽比是 1.333，和手机竖屏的长条完全相反。于是屏幕里天然就是「左封面 + 右信息」的横排构图，不可能退化成现在竖排的样子。**这个构图冲突正是新鲜感的来源。**
2. **转盘是圆的，且是页面里唯一的交互面。** 如果只画个圆不解手势，它就是装饰；一旦把「环形拖动」接上音量/寻轨，整页的操作逻辑就被重写了——而这正是 iPod 最值得继承的东西：**盲操不看屏**。
3. **机身高度装不满手机屏。** 358 宽的机身按真实比例只有 600 高，844 高的屏还剩 244。这块留白不做「拉伸机身」的蠢事，而是做成**舞台**：机身立在深色台面上，底下有投影和一层向上的环境光。留白反而给出了仪式感。

---

## 二、几何总表

基准：手机 390 × 844 vp，机身左右各留 16 → **机身宽 358**。
比例因子 `s = 358 / 61.8 = 5.79`。

| 部件 | 真实尺寸 | 换算值（vp） | 说明 |
|---|---|---|---|
| 机身 | 61.8 × 103.5 mm | **358 × 600** | 圆角 42 |
| 屏幕可视区 | 50.8 × 38.1 mm | **294 × 221** | 4:3，x=32，y=66 |
| 屏幕边距 | — | 上距机顶 66 / 左右 32 | 真实值 11.4 mm |
| 转盘（Click Wheel） | ⌀35.5 mm | **⌀206** | 圆心 y=442 |
| 转盘环宽 | — | **59** | (206 − 88) / 2 |
| 中心按钮 | ⌀15.2 mm | **⌀88** | Select |
| 屏幕底 → 转盘顶 | — | **52** 空白 | 印 `iPod` 字样 |
| 机底 → 转盘底 | 9.5 mm | **55** | |
| 机身上下留白 | — | 上 96 / 下 148 | 舞台区，非机身 |

> **留白刻意不对称**：下方比上方多 52，因为底部要放落地投影 + 底部环境光。做成上下等分，机身会像「浮在正中间的一张卡片」；下重上轻才像「立在台面上」。

> **不要把机身拉高去填满屏幕**。iPod 的比例一旦变形，一眼就假。空出来的地方交给舞台光。

## 三、机身外壳（材质分层）

从外到内 6 层，从下到上叠：

| 层 | 内容 | 参数 |
|---|---|---|
| S0 | 舞台底色 | `#08080A` 径向渐变，光源在机身正下方 |
| S1 | 落地投影 | `0 34vp 70vp rgba(0,0,0,0.72)` + `0 6vp 16vp rgba(0,0,0,0.50)` |
| S2 | 不锈钢侧边 | 1.5vp 描边，`linearGradient` 160°：`#D8D8DC → #8A8A92 → #E8E8EC → #6E6E76`（金属高光分四段） |

| S5 | 转盘 | 见 §5 |

**面板圆角 42vp**，四个角必须和屏幕/转盘都对齐到同一视觉重心——iPod 的圆角是机身尺度的，不是组件的。

## 四、屏幕内容（三态）

屏幕是 294 × 221 的 4:3 横屏，内边距 15。**屏幕玻璃反光是这台机器的灵魂**：一条 12° 斜向的 `rgba(255,255,255,.08)` 宽带从左下扫到右上，宽度占屏 45%，位置固定不随内容动。

### 态 1 · 正在播放（默认）

```
┌─ 294×221 ─────────────────────────┐
│ ▍正在播放                    ♪ ▮▮ │ 18  标题条 #141418
├───────────────────────────────────┤
│  ┌──────────┐  夜航星             │
│  │          │  不才               │
│  │ 104×104  │  《夜航星》         │
│  │          │  ▬▬▬▬▬░░░░░░░░░    │
│  └──────────┘  1:24      -2:48    │
└───────────────────────────────────┘
```

| 元素 | 参数 |
|---|---|
| 标题条 | 高 18，底 `#141418`，左 `▶ 正在播放` 7.5vp `#8C8C94`，右 `♪` + 电量 |
| 封面 | 104 × 104，x=15（内容区垂直居中，y≈65），圆角 2，1vp `#202026` 描边 |
| 曲名 | x=134，15vp Bold `#FFFFFF`，单行省略 |
| 歌手 | 11.5vp `#A0A0A6` |
| 专辑 | 10vp `#6E6E76`，书名号包裹 |
| 进度条 | x=134，宽 **145（整列宽）**，高 2.5，底 `#2A2A30`，已播放 `#4A90D9` |
| 时间 | 8.5vp `#7A7A82`，**独立一行、左右两端**（左已播 / 右剩余） |

> 进度条必须**整列宽、时间另起一行**。把「1:24 ▬▬ -2:48」塞进同一行，条只剩 60vp 宽，拖动时的手指精度全丢——这是第一版原型里最容易犯的错。

**为什么封面只有 104**：真实 iPod 的封面在 Now Playing 里就不大，它是「信息型」界面而非「图册型」。放大到 140 会挤掉右侧三行文字，破坏 iPod 的列表气质。

### 态 2 · 歌词

单屏只放 **3 行**（上一行 / 当前行 / 下一行），当前行 17vp Bold 白 + 底部 2vp 蓝色下划线，上下行 12vp `#5A5A62`。左右各留 26 内边距，行距 34。

> 3 行是刻意的：iPod 的屏只有 221 高，5 行会变成一团。滚动带 0.85 阻尼 + 80ms 延后，模拟机械感。

### 态 3 · 队列（Up Next）

经典 iPod 列表：每行 26 高，12vp 文字；**选中行用蓝渐变高亮条** `linearGradient(180°, #5AA9E6 → #2F6DB5)` + 白字 + 上下各 1vp `#9ACCFF` 亮线。右侧显示时长，序号列宽 26 右对齐。

## 五、Click Wheel 与交互映射

### 结构

```
        ⌀206 外环（可触摸区，环宽 59）
     ┌─────────────────────┐
     │        MENU         │  ← 12 点
     │   ╭─────────────╮   │
     │ ◀ │   ⌀88       │ ▶ │  ← 9 点 / 3 点
     │   │  Select     │   │
     │   ╰─────────────╯   │
     │        ⏯            │  ← 6 点
     └─────────────────────┘
```

- 外环：`#E7E3DB` 底，**四层阴影叠出「凹」**：`0 0 0 1vp rgba(0,0,0,.155)`（外缘分界）+ `inset 0 3vp 9vp rgba(0,0,0,.135)`（顶部内凹暗）+ `inset 0 -2.5vp 5vp rgba(255,255,255,.92)`（底部内凹亮）+ `0 1vp 1vp rgba(255,255,255,.6)`
- 中心按钮：`#F7F5F0`，比环略亮 + 一圈 `0 0 0 1vp rgba(0,0,0,.10)` 分隔槽——视觉上「凸起」，这是 iPod 手感的关键误读
- 四个符号：`#A8A49C`；MENU 11.5vp / 字距 2，方向键 15vp；下方 **0.5vp** 白影（不要用 1vp，放大后会成白色重影）
- 符号落在**环带中线 r=29.5**（不是「距外缘 22」这种会随直径漂移的写法）

### 手势 → 语义（核心设计）

| 手势 | 语义 | 视觉反馈 |
|---|---|---|
| 环上顺时针拖动 | 音量 +（每 3° 一档，可用 24 档） | 环上扇区高光跟手；屏幕标题条位置浮出「音量 ▮▮▮▮▯」1.2s 后消失 |
| 逆时针拖动 | 音量 − | 同上 |
| **按住环 600ms 后拖动** | 切换为「寻轨」模式 | 扇区转 `#4A90D9`，进度条加粗到 4vp 并高亮，松手 400ms 后复原 |
| MENU（上） | 短按：退一级（歌词 → 正在播放 → 收起播放页） | 屏幕内容右滑出 |
| ⏮（左） | 短按上一首；长按 500ms 快退 | 封面左滑入 |
| ⏭（右） | 短按下一首；长按 500ms 快进 | 封面右滑入 |
| ⏯（下） | 播放 / 暂停 | 封面 `scale 0.97` 回弹 180ms |
| 中心 Select | 循环切屏：正在播放 → 歌词 → 队列 | 横移 24 + 淡入，180ms |

**「按住 600ms 切模式」是这套方案最重要的一个决定。** 原版 iPod 要在 scrubber 上按 Select 才进寻轨模式；但那样需要两次操作 + 看屏。改成「按住即切」之后，一个环同时承载了两个连续量（音量 / 进度），且不需要任何视觉切换成本。

**方向键的判定**：环上触摸点角度落在 12/3/6/9 点的 ±22° 扇形内且**位移 < 10vp** → 判为按键；否则走连续拖动。按键在 `onAction`（抬手）时触发，拖动在抬手时结算。

### 扇区高光（不是光点）

环上有一段 **±13° 宽的弧形高光**，从环内缘一直亮到外缘，跟着触摸角度走：

```
conic-gradient(from 318deg, transparent 0deg, rgba(255,255,255,.85) 12deg,
  rgba(255,255,255,.35) 26deg, transparent 40deg)
+ mask: radial-gradient(circle, transparent 0 41%, #000 45% 96%, transparent 100%)
+ filter: blur(2.5px)
```

**为什么不做「一个 24vp 的光点」**：第一版原型就是光点，在白色环上完全看不见——白点落在白环上，等于没做。换成环形扇区之后，它天然贴合环带形状，读起来像「指尖下的一小片反光」，在白环和黑环上都成立。

iPod 原始产品没有这个，那是「隐藏触摸环」的设计代价：用户不知道手指碰到哪了。加上它，等于给 iPod 的盲操逻辑补了视觉确认，同时不破坏外壳的纯净。**寻轨模式下扇区换成 `#4A90D9`**，这是唯一的模式提示。

## 六、动效参数

| 名 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| 切屏 | 180ms | `cubic-bezier(.2,0,0,1)` | 横移 24 + 淡入，收尾干脆 |
| 曲目切换（封面） | 220ms | `cubic-bezier(.34,1.3,.64,1)` | `scale .96 → 1`，轻微过冲 |
| 播放/暂停 | 180ms | `cubic-bezier(.34,1.3,.64,1)` | 同上，幅度更小 |
| 扇区跟手 | 0ms | linear | **不允许插值**，插值就「粘手」 |
| 扇区消失 | 400ms | `easeOut` | 抬手后延迟 200ms 起淡 |
| 音量浮层 | 出入各 160ms | `easeOut` | 常驻 1.2s |

> 全页**没有一处弹性大动画**。iPod 的机械感来自「瞬时响应 + 极短收尾」，不是橡皮筋。

## 八、落码路径（在 BiliMusic 内）

### 新增文件

```
components/player/ipod/
  IpodShell.ets        // 外壳（材质分层 + 几何），约 260 行
  IpodScreen.ets       // 屏幕三态容器 + 切屏动效，约 300 行
  ClickWheel.ets       // 转盘 + 手势识别（角度累积 / 长按切模式），约 240 行
  IpodTheme.ets        // 白色 / 黑色两套令牌
```

### 复用边界（不重写）

| 能力 | 复用 |
|---|---|
| 封面数据源 | `PlayerInfoComponent.bgCover` / `currentTrack.coverUrl` 原样传入 |
| 播放控制 | `MusicPlayer` 单例（play/pause/next/prev/seek/volume） |
| 歌词行 | `LyricsComponent` 内部的 LrcView 行数据（只取「当前行 ±1」，不要整块复用） |
| 队列 | `PlayerQueueStore`（现有队列数据） |
| 字体 | `PlayerConstants.FONT_FAMILY_*` |

### 三种接入方式（按成本递增）

1. **作为新样式（推荐）**：`STORE_PLAYER_COVER_STYLE` 从两档扩到三档（`disc` / `square` / `ipod`），`PlayerInfoComponent.build()` 顶部加一个分支，`ipod` 直接整屏渲染 `IpodShell`，其余分支零改动。设置页加一个选项即可。
2. **作为独立页面**：`pages/IpodPlayerPage.ets`，从播放页右上角进入。适合先做实验。
3. **只做外壳不接交互**：纯视觉皮肤。**不建议**——不解手势的转盘是死的。

### 三个技术难点

1. **角度累积要处理「跨 0°」。** 相邻两次 `atan2` 求出角度后必须归一化到 `[-180,180]` 再算差值，否则从 179° 到 −179° 会被算成 358° 的跳变，音量瞬间打满。
2. **触摸点坐标要用中心相对值。** `onTouch` 的 `event.touches[0].x/y` 是相对**被触摸组件**左上角；转盘是 Circle，要减去 `⌀206/2 = 103` 才是圆心相对坐标。
3. **长按切模式需要「一次性标志」。** 600ms 内若已开始拖动就不该再切模式，用 `wheelModeLocked` 布尔在抬手时清，否则会出现「拖到一半突然变寻轨」。

### 验收标准

- 关机看：眯眼 / 离远一点，**必须一眼认出是 iPod**，不能是「圆形卡片 + 两个圆」。
- 上手摸：蒙住屏幕只靠转盘，能完成「调音量 → 切歌 → 暂停」三步。
- 转盘拖到任意角度松手，音量变化**线性且可逆**（正转 90° 再反转 90°，回到原值）。

## 九、和现有播放页的关系

| | 现有沉浸式播放页 | iPod 外壳 |
|---|---|---|
| 构图 | 竖排：顶栏 / 大封面 / 标题 / 控制区 / 歌词页 | 横屏 4:3 屏 + 圆形转盘 |
| 主交互 | 按钮 + 滑杆 + 手势 | 单一环形连续量 |
