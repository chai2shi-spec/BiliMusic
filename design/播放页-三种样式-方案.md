# 播放页 · 三种样式设计方案

> 2026-10-31 · 基于 `components/player/*` 真实代码
> 配套：`播放页-三种样式-原型.html`（4 屏）· `播放页-三种样式-预览.png`
> 前置必读：`memory/UI-LAYOUT.md`（UI 五条铁律 + 播放页冻结记录）· `播放页元素扩充方案.md`（已有元素盘点）

---

## 〇、一句话结论

**三种样式不是「三个播放页」，是同一副骨架的三种排版。**

内核（`MusicPlayer`）、状态（全部 `STORE_*`）、控制能力（功能行排序 / 倍速 / 定时 / 进度条三档）三种样式完全共享。
差异只在**三处**：① 封面占多大、在哪儿 ② 歌词是「第二页」还是「主角」 ③ 控制区是通长三行还是浮动条/卡片。

所以落地方式是 `PlayerInfoComponent` 的 SM 分支按 `layoutStyle` 三路分流，
**不是新建三个页面**——否则 GT 一镜到底、收起动画、歌词缓存全部要复制三份。

## 一、现状基线（必须先看清，否则会设计出做不到的东西）

### 1.1 SM 结构

```
PlayerInfoComponent (Stack, 背景面挂 GEOMETRY_ID_PLAYER_SURFACE)
├─ 背景面 Stack —— 模糊封面 + 渐变压深 + 噪点（按 coverStyle 分流，三层）
└─ Row
   └─ Stack(TopStart)
      ├─ Column
      │  ├─ Swiper (layoutWeight 1)          ← 受控 index=smIndex
      │  │  ├─ [页0] MusicInfoComponent      ← 圆盘/方卡 + 歌名/歌手/音质
      │  │  └─ [页1] LyricsComponent         ← 小封面+歌名头行 + LrcView
      │  └─ ControlAreaComponent             ← 固定：功能行 + 进度 + 三键
      └─ TopAreaComponent                    ← ⌄ 收起 + 投播
```

### 1.2 高度账（360×780，safeTop 32 / safeBottom 24 → 内容 724vp）

| 区块 | 高 | 说明 |
|---|---|---|
| TopArea | 48 | 只有 ⌄ 和投播，横向大片空白 |
| 控制区 | ~160 | 功能行 40 + 进度区 ~56 + 三键行 52 + 间距 |
| **Swiper 可用** | **516** | 724 − 48 − 160 |
| 封面页圆盘 | **328** | `min(列宽 328, 516 − 标题块 76)` = **宽度驱动** |
| 歌词页 LrcView | ~440 | 516 − 头行 76 |

> 圆盘是**宽度驱动**：瘦长屏上预算（440）大于列宽（328），所以取列宽。
> 这意味着**在标题块里减行不会让圆盘变大**，只会多出空白 —— 这一点决定了样式一不值得为省空间做取舍。

### 1.3 已经存在的「样式」维度（别重复造）

| 现有设置项 | 取值 | 作用域 |
|---|---|---|
| 播放页进度条样式 | 经典 / 流光 / 波点 / 频谱 | 只换进度条 |
| 播放页收起动画 | 柔退 / 柔退+手势 / 下滑 | 只换转场 |
| **播放页封面风格** | **disc 唱片 / square 方卡** | **只换封面形态**（`CoverDiscComponent` 内部分流） |

设置页「播放页」分组已经是**三个菜单式选择项**（当前档尾部 ✓），
所以新增「播放页样式」三选一**完全符合既有交互模式**，不需要新控件。

### 1.4 一条会打掉设计的硬约束

`SubPagePlayBar.ets` 文件头记着实测结论：

> `systemMaterial` 仅在 Navigation/NavDestination 标题栏或横向 Tabs 底部 TabBar 生效
> —— 自绘 Row 直接挂 `.systemMaterial()` **真机静默全透明**。

→ 样式二、三的「浮起控制条 / 卡片」**不能指望系统材质**。
只能用：半透明白（`rgba(255,255,255,.08)`）+ 0.5vp 高光边 + 阴影 + 背景本身已模糊。
这是 Spotify 的实际做法，观感够用，而且零风险。

## 二、三种样式

> 三种全部**同一张封面**（对比版式差异，不是对比图片）。
> 全部只在 SM（手机竖屏）生效 —— MD/LG/横屏沿用现有分栏，见 §4.3。

---

### 样式一 · 唱片 `disc`（现状加固）

**对标**：网易云音乐黑胶唱机、QQ 音乐经典唱片页

```
┌──────────────────────────────┐
│  ⌄                        ⧉  │  48
│        ╱                     │
│      ╱   ╭──────────╮        │  ← 唱针臂（从左上搭到盘面）
│     │    │  ●  圆盘  │        │     292
│          │  同心纹路 │        │
│          ╰──────────╯        │
│         夜航星               │  68  ← 标题块（居中）
│         某某某 · 176 kbps    │
│  ⎯⎯⎯●⎯⎯⎯⎯⎯⎯   1:23  3:45   │  160  ← 控制区三行
│  [模式][下载][收藏][列表]     │
│      ⏮      ⏯      ⏭        │
└──────────────────────────────┘
```

| 改动 | 规格 | 空间成本 |
|---|---|---|
| 唱针臂 | 5×74vp，圆角 2.5，`rgba(255,255,255,.55)`；播放 `rotate(-9deg)`、暂停 `rotate(-27deg)`，`transformOrigin` 在顶端，`animateTo(320ms, spring)` | **0**（Stack 叠加，不占布局） |
| 唱片纹路 | 3 圈同心圆 `rgba(255,255,255,.055)` 1vp + 右上 120° 高光弧 | 0 |
| 中心轴孔 | 直径 26 的深色圆 + 1vp 高光边（仅 disc 风格，square 不画） | 0 |

**为什么值得做**：现状是「圆形裁切的封面」，不是「唱片」。少了唱针这个符号，圆盘和「圆头像」在视觉上没有区别。这是三种样式里**唯一零风险**的一档。

**不做什么**：不动标题块行数、不动控制区、不减元素。因为 §1.2 已证明圆盘是宽度驱动，省下的空间只是变成空白。

**⚠️ 挂载位置**：唱针必须是 `CoverDiscComponent` 的**兄弟节点**、叠在 `MusicInfoComponent` 的 Stack 里，
**绝不能放进 `CoverDiscComponent` 内部** —— 那个组件的根节点挂着 `GEOMETRY_ID_PLAYER_DISC`，
把唱针塞进去会让它跟着做一镜到底飞行（迷你栏小唱片旁边飞出一根唱针）。

### 样式二 · 沉浸歌词 `lyric`（歌词是主角）

**对标**：Spotify Playing View 歌词态、汽水音乐、Apple Music Sing

```
┌──────────────────────────────┐
│ [44封] 夜航星            ⧉   │  64   ← 信息带（顶栏并入，省 48）
│        某某某                │
│                              │
│        海面倒映着            │       ← 暗 60%
│        星光照进海底          │
│    ▸   夜航星 沉入海   ◂     │  548  ← 当前行 22fp / 亮 100%
│        我还在等一个回答      │
│        潮汐带来你的消息      │
│                              │
│  ⎯⎯●⎯⎯⎯⎯⎯⎯⎯  1:23 / 3:45   │  20   ← 细进度（2vp，拖动 4vp）
│  ╭──────────────────────╮    │
│  │  ⏮    ⏯    ⏭     ≡  │    │  76   ← 浮动胶囊
│  ╰──────────────────────╯    │
└──────────────────────────────┘
```

| 项 | 现状 | 样式二 |
|---|---|---|
| Swiper | 封面↔歌词双页 | **取消**，歌词常驻单页 |
| 歌词可视高 | 440 | **548（+108，约 +25% 行数）** |
| 顶栏 | 独立 48 | 并入 64 信息带（封面 44 + 两行 + 投播） |
| 控制区 | 通长三行 160 | 细进度 20 + 浮动胶囊 76 = **96** |
| 功能行 4 键 | 常驻 | **收进「≡」→ 复用现有 `showQueueSheet` 同款 sheet** |
| 背景压深 | 现有档位 | 加深到 0.72（歌词可读性优先） |

**为什么值得做**：歌词现在是「第二页」——用户要滑一下才看得到。而对「边听边看词」的人，歌词才是主界面。省下的 108vp 全部给歌词，是三种样式里**唯一真正提升信息量**的一档。

**代价（必须写清）**：功能行 4 键（模式 / 下载 / 加入歌单 / 列表）从「一眼可见」变成「多点一次」。
`STORE_FUNC_ITEM_ORDER` 的排序页也随之只剩「≡ 里的顺序」，价值下降。

### 样式三 · 编辑卡片 `editorial`（信息优先）

**对标**：Apple Music「接下来播放」、YouTube Music

```
┌──────────────────────────────┐
│                          ⧉   │  48
│  ╭──────╮  夜航星            │
│  │ 96方 │  某某某            │  120  ← 封面偏左上，信息左对齐（不再居中）
│  │ 封面 │  176 kbps · 无损   │
│  ╰──────╯                    │
│  接下来播放            队列 › │  32
│  [28] 海底                2:58│
│  [28] 起风了              3:12│  224  ← 队列预览 4 条（可点即播）
│  [28] 夜空中最亮的星      2:41│
│  [28] 光年之外            3:24│
│                              │  ← 弹性留白 132（卡片贴底）
│  ╭──────────────────────────╮│
│  │ ⎯⎯●⎯⎯⎯⎯⎯  1:23   3:45  ││  196  ← 控制卡片（圆角 24）
│  │ [模式] [收藏] [歌词] [≡] ││
│  │    ⏮      ⏯      ⏭      ││
│  ╰──────────────────────────╯│
└──────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 封面 | **96×96 方卡**，圆角 12，左上；不再是居中海报 |
| 信息 | 歌名 18fp Bold 最多 2 行 / 歌手 13fp / 音质 11fp，左对齐、与封面顶对齐 |
| 队列预览 | 4 条 × 56vp：小封面 28 + 歌名 14fp + 时长 11fp；数据源 `STORE_QUEUE`（已存在，`PlayBar` 已在订阅） |
| 控制卡片 | 圆角 24，`rgba(255,255,255,.08)` + 0.5vp `rgba(255,255,255,.14)` 边 + `0 8px 28px rgba(0,0,0,.35)`，内 padding 16 |
| 歌词入口 | 卡片内「歌词」键 → `bindSheet` 半屏歌词（高 70%），**不新建页面** |
| Swiper | 取消 |

**为什么值得做**：这是唯一能回答「接下来听什么」的样式。在专辑 / 歌单连续听的场景里，用户 80% 的操作是「跳过这首」——而跳过之前想知道「下一首是什么」。现状要看下一首必须点开列表弹层。

**代价**：最大。① 新增 `UpNextPreview` 组件（~120 行）；② 歌词要进 sheet（`LyricsComponent` 的 `pageActive` 传 `true`，避免不滚动）；③ 封面从 328 缩到 96，「看封面」的价值基本放弃 —— 这是明确取舍，不是遗漏。

## 三、三种样式的差异一眼看清

| | 唱片 `disc` | 沉浸歌词 `lyric` | 编辑卡片 `editorial` |
|---|---|---|---|
| 第一眼看到 | 圆盘 + 唱针 | 当前歌词行 | 封面 + 歌名 + 接下来播 |
| 封面尺寸 | 328（圆/方） | 44（方） | 96（方） |
| 歌词 | 第二页（440） | **主舞台（548）** | 半屏 sheet |
| 控制区 | 通长三行 160 | 浮动胶囊 96 | 卡片 196 |
| 功能行 4 键 | 常驻 | 收进 ≡ | 收进卡片 |
| 队列可见 | 弹层 | 弹层 | **常驻 4 条** |
| 适用 | 默认 / 大封面审美 | 边听边看词 | 专辑连续听 |
| 改动量 | 小 | 中 | 大 |
| 风险 | 极低 | 中 | 中高 |

## 四、落地约束（不满足就会出事）

### 4.1 两条 GT 必须三种样式全保留

打开动画是「迷你栏 → 全屏」的一镜到底，靠两组 `geometryTransition` 配对：

| 配对 | id | 挂在哪 |
|---|---|---|
| 背景面 | `GEOMETRY_ID_PLAYER_SURFACE` | 背景面 Stack 根 |
| 封面 | `GEOMETRY_ID_PLAYER_DISC` | `CoverDiscComponent` 根 |

**三种样式的根结构都必须是「Stack(背景面 + 内容层)」**，不能改根。
样式二/三封面缩到 44 / 96，GT 两端尺寸差更大 —— 系统本来就做尺寸插值，没问题；
但**同一个 id 全树只能有一处**，样式三若在队列预览里也用小封面，**不能挂这个 id**。

另：根层**不许挂整块 opacity / translate / scale**（`PlayerInfoComponent.build` 注释已警告）——
一旦挂上，共享元素的目标框会按动画中途值算，封面落位后再弹一下。

### 4.2 竖向零和，但只有一种样式需要重算

`recomputeDisc()` 预算 = `min(列宽, 列高 − 标题块 − 控制区)`，三项都是 `onAreaChange` 实测回填。

- 样式一：结构不变 → **直接复用**，一行不改
- 样式二：**没有圆盘**，预算函数不适用 → 新增 `recomputeLyricHeight()`（或干脆 `layoutWeight(1)` 吃掉剩余，不需要实测）
- 样式三：封面固定 96 → **不需要预算函数**，删掉这套计算

→ 结论：**样式二、三反而更简单**（不需要实测回填的圆盘预算），样式一才需要。

### 4.3 范围声明：本期只做 SM

MD/LG/横屏/折叠展开是另一套分栏（`GridRow` + 双列），三种样式在那些形态下的语义不清晰
（横向两列时分「封面列/歌词列」已经固定，样式二/三无从谈起）。
→ 三种样式**只作用于 SM 分支**（`else` 那条 + `isWideFoldFull` 穿透）；
MD/LG/横屏保持现状，设置项在这些形态下**显示但标注「仅手机竖屏」**。

### 4.4 切换必须两段式

样式切换会换掉整个内容骨架（Swiper ↔ 单页 ↔ 头部+队列），
如果同帧既改骨架又让 `animateTo` 驱动尺寸，封面会跳、GT 会漂。

正确顺序（参考 `UI-LAYOUT.md` 里 miniBar 的教训「不在请求侧抢跑写全局态」）：

```
① 内容层 180ms EaseIn 淡出（复用现有 contentFade 机制）
② 写 STORE_PLAYER_LAYOUT_STYLE → 骨架重挂载
③ 下一帧内容层 220ms EaseOut 淡入
```

**且播放页打开中（TRANSITIONING）时不允许切换** —— 与下拉手势同一互斥门。

### 4.5 Swiper 消失的短路点

样式二/三没有 Swiper，以下四处要按样式短路，否则是无效操作或死代码：

| 位置 | 代码 | 处理 |
|---|---|---|
| `onContentExit()` | `this.smIndex = 0` / `smAnimDuration = 0` | 保持赋值（安全，无害），但**注释标明仅 disc 有效** |
| Swiper `.index/.duration/.onChange` | 受控绑定 | 不挂载 |
| DotIndicator | `indicator(...)` | 不挂载 |
| 歌词 `pageActive` | `smIndex === 1` | 样式二恒 `true`；样式三 sheet 打开时 `true` |

### 4.6 coverStyle 与 layoutStyle 的关系（必须现在定，否则 6 种组合失控）

现有 `coverStyle`（disc / square）只切换封面形态。若再乘三种 layoutStyle，就是 6 种组合，
其中「沉浸歌词 + 圆盘小封面」「编辑卡片 + 圆盘」在视觉上都说不通。

**决定**：

| layoutStyle | coverStyle 是否生效 |
|---|---|
| `disc` | **生效**（圆盘 / 方卡，保留现有设置项） |
| `lyric` | 忽略，封面强制 44 方卡 |
| `editorial` | 忽略，封面强制 96 方卡 |

设置页「封面风格」项在非 `disc` 样式下：**置灰 + 副标题「仅『唱片』样式生效」**（不隐藏 —— 隐藏会让人以为设置丢了）。

### 4.7 三种样式都要遵守的 UI 铁律

- 灰阶三档：主文 `#FFF` / 次文 `rgba(255,255,255,.55)` / 弱文 `rgba(255,255,255,.38)`
- 粉色只给大字与图标：`#FB7299` 只出现在播放键、当前歌词行、选中态，正文不用
- 命中区 ≥ 44vp：队列条 56 高 ✓；浮动条图标 48 ✓；唱针**不可点**（纯装饰，不参与命中）
- 必给按压态：`BounceIconButton` 已有缩放，新增的队列条、歌词键都走它
- **文字色随背景明暗切换，不跟随系统深浅色**：播放页背景由封面取色（`STORE_PLAYER_BG_DARK`），
  落在浅色封面上时必须切到 `rgba(0,0,0,.55)` 一档（`qualityText` 已有这个分流可参照）。
  所以三种样式的原型**只出深色** —— 播放页没有「浅色模式」这个概念，别去给它做一套。

## 六、可直接粘贴的 AI 提示词

### 先做样式一（最小闭环，验证分流管道）

## 七、验收清单

**通用（三种样式都要过）**
- [ ] 从迷你栏点开 → 一镜到底正常：背景面从胶囊长到全屏、封面从迷你唱片飞到目标位
- [ ] 收起（三种动画风格逐个试）→ 无残影、无跳帧
- [ ] 快速连开连关 10 次 → 无闪烁、无 GT 漂移
- [ ] 歌曲无封面 / 封面加载失败 → 兜底图正常，取色降级不崩
- [ ] 切歌 → 背景色 600ms 过渡、歌词换源、唱针不抖

- [ ] 唱针播放摆入 / 暂停摆出，起点在盘面外、终点轻搭盘缘

- [ ] 歌词可视行数比现状多（约 +25%）

## 八、建议的落地顺序

```
第 1 步  样式一（disc）        —— 新增 layoutStyle 维度 + 唱针纹路，验证分流管道通了
第 2 步  样式二（lyric）       —— 最大收益档（歌词 +25%），ControlAreaComponent 加 floatingMode
第 3 步  样式三（editorial）   —— 最重，需要新组件 + 歌词 sheet
```

每步独立可编译、独立可真机验证。**第 1 步的真正目的不是唱针，是把 `layoutStyle` 这条分流管道建起来** —— 管道通了，二三步才只是「加分支」而不是「改架构」。
