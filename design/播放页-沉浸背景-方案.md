# 播放页 · 封面沉浸式背景方案

> 工程：`E:/BiliMusic/HarmonyOS-Phone`
> 目标：让超大封面「没有边界」—— 背景不再是一张垫在下面的图，而是封面的延续。
> 基准确认：390 × 844 vp（safeTop 32 / safeBottom 24）；封面 390 满幅出血 @ y104；控制区 174 @ y646。

---

## 一、先说结论：问题不在模糊，在取景框

现状代码（`components/player/PlayerInfoComponent.ets` → `SurfaceLayers()`）三层：

```ts
Image(this.bgCover)
  .width(StyleConstants.FULL_WIDTH)     // 100% → 390
  .height(StyleConstants.FULL_HEIGHT)   // 100% → 844
  .objectFit(ImageFit.Cover)
  .opacity(0.5)
// + deepRgb 竖向压深 .05 → .45
// + noise_texture 0.05
```

`ImageFit.Cover` 在 **390×844** 的容器里，会把正方形封面按高度放大 **2.16 倍**再居中裁切，
于是背景只显示了封面**中间 46%** 的画面。

而封面本身是 390×390 的正方形，显示的是**整幅**画面。

> 结果：封面下缘的画面是「暗山」，背景同一高度却是「海面亮带」。
> 两条完全不同的画面贴在一起 → 必然出现一条阶跃。**再怎么调 blur 半径和透明度都救不回来。**

这也是为什么这个问题一直「看着别扭但说不清」：深色封面上，中段海面恰好是一团柔光，
看起来像「氛围」，把错误掩盖了；一旦换到**底部明亮**的封面（白底 / 暖色 / 有大面积浅色），
下缘立刻出现一条亮带，才暴露出来。

### 判定方法（30 秒）

随便找一张「底部是亮色」的封面播放，看封面下缘：
- 下缘外面比里面**亮** → 取景框不一致（本方案要解决的问题）
- 下缘外面和里面**一个色** → 才是真的连续

**上缘单独验一次**：把顶栏文案临时隐藏，看封面上缘有没有一条横线。
有的话不是取景框问题，是顶部压暗只压了背景、没压到封面（见 §四）。

## 二、正确做法：背景 = 封面的「同心放大副本」

不要用「覆盖全屏」的图，要用**和封面同心同比例的正方形**，只是边长放大 k 倍。

```
封面：390 × 390，左上角 (0, 104)，中心 (195, 299)
背景：390k × 390k，边长按 k 放大后，中心仍落在 (195, 299)
      k = 1.14 → 444 × 444，左上角 (-27, 77)
```

这样背景与封面是**纯相似变换**关系，封锁边缘两侧的像素来自图像的相邻区域，
天然连续，**不需要任何遮罩、渐变条、羽化层**。

### 为什么 k 必须 ≥ 1 + 2·blur/边长

模糊会把图片边缘变成半透明（羽化宽度 ≈ 3σ ≈ 3×blur）。若 k 不够，方图的边缘会落在
屏幕里，露出一条「模糊到头」的软边。

```
k_min = 1 + 2 × blurPx / 封面边长
blur 31、封面 390  →  1 + 62/390 ≈ 1.16
```

所以 **k = 1.14~1.20** 是甜区：够遮住羽化，又不会让画面放大得太夸张。

### k 也有上限：注册误差

封面边缘处，背景显示的是图像 `0.5 + 0.5/k` 的位置：

| k | 边缘处显示 | 与封面边缘的差 | 观感 |
|---|---|---|---|
| 1.14 | 93.9% | 6.1% | 无感 |
| 1.20 | 91.7% | 8.3% | 无感 |
| 1.30 | 88.5% | 11.5% | 轻微「错位感」 |
| 1.60 | 81.3% | 18.7% | 能看出背景不是同一帧 |

> **k 超过 1.3 就开始露出马脚。** 想要「画面铺得更满」，正确做法是**把渐隐起点往下推**（见 L2），
> 而不是把 k 调大。

## 三、三套配方

同一套 5 层结构，只换参数。三屏同图同布局的对照见原型。

### B1 · 注册式（默认推荐）

```
L1 方图  k = 1.14，blur 31，saturate 1.10，brightness 1.04，opacity 0.94
L2 渐隐  180°，0 @52% → .62 @66% → 1.0 @82%
```
画面占总屏约 62%，下半屏交给实色。**最稳、最省、任何封面都不出错。**

### B2 · 铺满

```
L1 方图  k = 1.60，blur 36，opacity 0.96
L2 渐隐  180°，0 @62% → .78 @76% → 1.0 @86%
```
画面占到 76% 才转实色，沉浸感最强。代价是注册误差 19%，**只适合画面色调统一的封面**
（大面积同色系、无明显主体边界）。

### B3 · 双色漂移

```
L0 双色底  主色 → 深辅色，160° 线性
L1 方图    k = 2.20，blur 38，brightness 1.30，opacity 0.24（只当纹理）
L2 渐隐    180°，0 @54% → .70 @73% → 1.0 @84%
```
颜色由双色底决定，图片只贡献噪点与起伏。**杂色封面 / 高饱和封面的唯一解**，
也是唯一「换歌时色相变化可控」的一套。

## 四、层结构（5 层，零额外 blur）

| 层 | 内容 | 参数 | 职责 |
|---|---|---|---|
| L0 | 基色实底 | `deepRgb` 纯色 | blur 失败兜底，绝不白块 |
| L1 | 注册方图 | 390k × 390k，同心 | **决定连续性**，唯一必须做对的一层 |
| L2 | 下方渐隐 | 180°，52% → 82% | 画面过渡到实色，同时把白字对比度锁到 4.5:1 |
| L3 | 顶部压暗 | **z 高于封面**，0.34 → 0 @196vp | 状态栏/顶栏可读，且不破坏上缘连续 |
| L4 | 噪点 | 128 平铺，op 0.05 | 去塑料感（保持不变） |
| *(B3)* | 双色底 | 160° 线性 | 仅 B3 使用，替换 L0 |

**没有任何一层需要新的 blur 计算**：L1 复用换歌时生成的那一份 `bgCover` PixelMap，
L2/L3/L4 都是纯渐变与平铺。摊到每帧成本为 0。

### 上缘必须和下缘同等对待

这是最容易漏的一处。顶部压暗如果按常规做法只铺在**背景层**，会出现一个**反向阶跃**：

```
y < 104（封面之上）  背景 × (1 - 0.19)    ← 被压暗
y > 104（封面之内）  封面 × 1.00          ← 没被压暗
```

上缘于是出现「外面暗、里面亮」的接缝，比下缘那条更扎眼，因为它出现在纯深色区域，
反而对比更锐利。

**做法：把顶部压暗抬到封面之上**（图层顺序上盖住封面），让封面与其上方背景
吃**同一条渐变**。这样两侧的压暗量在任意 y 上都相等，阶跃在数学上恒为 0。

```ts
// 放在页面根 Stack 里、封面组件之后（后渲染 = 在上层）
Column()
  .width('100%').height(196)
  .linearGradient({ angle: 180, colors: [
    ['rgba(0,0,0,0.34)', 0.0],
    ['rgba(0,0,0,0.13)', 0.40],
    ['rgba(0,0,0,0)',    1.0]
  ]})
  .hitTestBehavior(HitTestMode.None)   // 不吃点击
```

代价是封面顶部约 100vp 会被压暗 10~34%。这对「顶栏可读」是必要的，各家播放器
（Apple Music / Spotify / QQ 音乐）都这么做；且因为是平滑渐变，看不到边界。

> 判据：压暗层的 z 必须 **大于封面、小于顶栏与标题**。任何「只压背景不压封面」的层
> 都会在封面边缘制造接缝。

### 参数对照

| 项 | 现状 | 建议 | 作用 |
|---|---|---|---|
| 取景 | 全屏 `Cover` | 方图 1.14× | 与封面同帧 |
| 对齐 | 屏幕居中 | **封面中心** | 同心才不错位 |
| 模糊半径 | 15 | 31 | 消掉可辨认结构 |
| 不透明度 | 0.50 | 0.94 | 背景即延续，不必压暗 |
| 转实色起点 | — | y 52% | 底部交给控制区 |
| 转实色终点 | — | y 82% | 白字 4.5:1 |
| 封面描边 | 0.5px 白 | **去掉** | 那条线本身就是硬边 |
| 封面投影 | 46 扩散 | **去掉** | 投影 = 在背景上画了一圈边框 |
| 噪点 | 0.05 | 0.05 | 不变 |

> 现状那两条边（`0 0 0 .5px` 白描边 + `0 16px 46px` 投影）是「硬边」的第二来源。
> 即使取景修对了，留着它们也还是能看见一圈轮廓。

## 五、两种封面样式都要同心

- **方卡（`PLAYER_COVER_STYLE_SQUARE`）**：中心 = 方块中心，边长 = 方块边长
- **唱片（`PLAYER_COVER_STYLE_DISC`）**：中心 = **圆盘中心**，边长 = **圆盘直径**

圆盘模式下背景依然是方形图（专辑封面本来就是方的），只是以圆盘为基准缩放。
两种样式共用同一套 `centerX / centerY / side`，只是取值来源不同。

## 六、闸门：浅色封面与杂色封面

背景方案的风险不在深色封面，而在两个极端。

```
若 deepRgb 亮度 L > 0.62        → 浅封面分支
     · L2 起点提前到 62%（更早转实色）
     · L1 brightness × 0.52，saturate × 0.82
     · L0 改为暖中性深色（不跟着封面走纯白）

若 主色饱和度 S > 0.55 且 主/辅色相差 > 120°   → B3
     · L1 opacity 压到 0.22（只留纹理）

其余                                          → B1
```

三条分支共用同一套层结构，只换参数，**不需要三份 UI**。

## 七、ArkUI 落地

只改 `SurfaceLayers()` 一个 `@Builder`，布局 / 封面 / 控制区全部不动。

```ts
@Builder
SurfaceLayers(): void {
  Stack() {
    // L0 基色
    Column().width('100%').height('100%')
      .backgroundColor(buildRgba(this.deepRgb, 1))

    // L1 注册方图：正方形，中心与封面重合
    if (this.bgCover !== '') {
      Image(this.bgCover)
        .width(this.bgSide).height(this.bgSide)      // 封面边长 × k
        .objectFit(ImageFit.Cover)
        .opacity(0.94)
        .position({
          x: this.coverCenterX - this.bgSide / 2,
          y: this.coverCenterY - this.bgSide / 2
        })
    }

    // L2 下方渐隐
    Column().width('100%').height('100%')
      .linearGradient({ angle: 180, colors: [
        [buildRgba(this.deepRgb, 0),    0.00],
        [buildRgba(this.deepRgb, 0),    0.52],
        [buildRgba(this.deepRgb, 0.62), 0.66],
        [buildRgba(this.deepRgb, 1),    0.82]
      ]})

    // L4 噪点（原样保留）
    Column().width('100%').height('100%')
      .backgroundImage($r('app.media.noise_texture'), ImageRepeat.XY)
      .backgroundImageSize({ width: 128, height: 128 })
      .opacity(0.05)
  }
  .width('100%').height('100%')
  .clip(true)                    // 方图溢出屏幕的部分裁掉
}
```

顶部压暗**不在** `SurfaceLayers()` 里 —— 它必须盖在封面之上，所以放在页面根 `Stack` 中、
封面组件之后：

```ts
// pages/PlayerPage 或 PlayerInfoComponent 的根 Stack 内，紧跟封面之后
Column()
  .width('100%').height(196)
  .linearGradient({ angle: 180, colors: [
    ['rgba(0,0,0,0.34)', 0.00],
    ['rgba(0,0,0,0.13)', 0.40],
    ['rgba(0,0,0,0)',    1.00]
  ]})
  .hitTestBehavior(HitTestMode.None)
```

三个派生量：

```ts
const k: number       = 1.14;                          // 1 + 2*blur/coverSide 左右
const bgSide: number  = coverSide * k;                 // 444
const coverCenterX    = coverX + coverSide / 2;        // 195
const coverCenterY    = coverY + coverSide / 2;
```

### 注意点

1. **`clip(true)` 必须加**，否则放大的方图会溢出到相邻页面。
2. **不要用 `mask`**。这套方案的连续性来自几何对齐，加遮罩只会把「修对了」又糊回去。
3. **顶部压暗的 z 顺序**：大于封面、小于顶栏 / 标题 / 控制区。放在背景 `Stack` 里
   （和 L0~L4 同层）会在上缘留下反向阶跃。
4. **换歌动画**：`imageColor` 已有 `animateTo`，L0 / L2 跟着动；L1 图片瞬时替换
   （0.94 透明度下看不出跳变，因为新旧背景都在同一明度区间）。
5. **横屏 / 平板**：方图边长按 `min(w, h)` 定，仍与封面同心；L2 角度改 90°，
   让右侧歌词区落在实色带里。

## 八、兜底

| 情况 | 表现 |
|---|---|
| blur PixelMap 生成失败 | 只留 L0 + L2 + L3 + L4 → 仍是「有主题色的深色页面」，不出现白块 |
| `bgCover` 为空（首帧 / 换歌瞬间） | 同上，L0 已经是新歌的 deepRgb |
| 网络封面加载失败 | `onError` 摘掉 L1，其余层不受影响 |

## 九、验收

> 把屏幕亮度调到最低、**眯眼**看：
> - 看不出封面从哪开始、到哪结束 → 对了
> - 还能看出一块方块 → 说明方图仍没和封面同心（或描边/投影没去掉）

**上缘单独验一次**（最容易被忽略）：把顶栏文案临时隐藏，只留画面，看封面上缘有没有
一条横线。若有，几乎一定是顶部压暗还在背景层里，没盖到封面上。

再补一条更狠的：**找一条明亮底色的封面**播放，看封面上下缘。
深色封面能骗过眼睛，浅色封面骗不过。

## 附：一句话总结

**背景不是「封面的模糊版」，是「封面的下一帧」。**
取景框对齐了，边缘自己就没了；取景框没对齐，加多少层渐变都只是把一条直线糊成一条宽带。
