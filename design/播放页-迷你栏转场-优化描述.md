# 迷你栏 → 播放页 转场优化 · AI 执行描述

> 只读代码分析，**未修改任何源码**。所有行号基于 2026-11-07 的 `HarmonyOS-Phone` 工作区。
> 交付物用途：可直接粘贴给 AI 编码助手执行的优化需求。

---

## 0. 一句话结论

现在的转场是「**一块圆角矩形从迷你栏长大到全屏，内容在后半段淡入**」，总落定 **780ms**。
三个可感知的问题：**点了之后前 400ms 屏幕上没有任何信息**、**迷你栏的歌名被背景面"吃掉"而不是退场**、**底层首页全程静止所以像"色块在变大"而不是"新页面盖上来"**。

优化方向不是换转场形式（GT 一镜到底本身是对的），而是**把时间轴压短并前移内容、给源容器一个体面的退场、给底层一点压暗**。

## 2. 诊断（症状 → 根因 → 位置）

### D1｜前 400ms 屏幕上只有一块背景在长大

- **症状**：点完，看着一块模糊色块从底部弹开占满屏幕，然后文字才陆续出现。像"页面在长"，不像"页面在出现"。
- **根因**：几何飞行 0→700ms，但最早的内容层（控制区）**400ms** 才开始淡入，且用 `EaseOut` 从一个看不见的位置开始。前 400ms 画面里没有任何可读信息。
- **位置**：`LAYER_DELAY_CONTROL/INFO/TOP` 三个常量。

### D2｜总落定 780ms 偏长

- **症状**：完整界面出现要等将近 0.8 秒，第二次点会感觉"这次怎么这么慢"。
- **根因**：700ms 几何 + 530ms 延迟 + 250ms 淡入 = 780ms。参照 Apple Music 全屏播放约 500ms。
- **位置**：`PLAYER_TRANSITION_MS`。

### D3｜迷你栏的歌名是"被盖住"的，不是"退场"的

- **症状**：封面先飞走了，歌名/歌手/播放键还留在原地，然后一块面板长过来把它们吃掉。**同一个容器里，一个元素飞走、其余元素被吃掉** —— 这是整条动画里最容易被察觉的破绽。
- **根因**：`bodyVisible()` 只看 `expanded` 和 `animPhase`，**不看 `playerOpen`**。所以打开播放页时 Body 照常渲染，等背景面盖住。而封面因为 `if (!this.playerOpen)` 被摘除参与 GT。
- **位置**：`PlayBar.ets:333-340`（bodyVisible）+ `592-595`（Disc 挂载守卫）。

### D4｜底层首页全程静止，缺少空间层次

- **症状**：背景面长大时，下面是完全明亮、完全静止的首页。读起来是"一块色块在放大"，没有"新页面浮上来"的体感。
- **根因**：`phoneShell` 与 overlay 之间没有压暗层。
- **位置**：`Index.ets:1690-1710`（根 Stack 子节点顺序）。

### D5｜页签图标淡出 700ms，会与背景面"赛跑"

- **症状**：页签在覆盖过程中以半透明状态从背景面边缘透出来，边缘发脏。
- **根因**：`.opacity(this.playerOpen ? 0 : 1)` 落在 700ms 的 `animateTo` 作用域内 → 700ms 淡完。但背景面约 350ms 就盖住底栏区域，剩下 350ms 是「已经看不见的东西还在淡」。
- **位置**：`Index.ets:1364`。

### D6｜圆角起点 28vp 与胶囊真实圆角不符

- **症状**：起飞瞬间四角"不够圆"，能看到一点方角外凸。
- **根因**：迷你栏是胶囊，圆角应 = 槽位高 / 2（56 → 28，64 → 32）。硬编码 28 只在 56 高时正确。
- **位置**：`Constants.ts:234`。HDS 不暴露槽位高，无法动态算。

### D7｜点击到起飞之间有感知空窗

- **症状**：冷启动首次打开最明显 —— 抬手后"亮回来一下"，然后停顿一瞬，才开始飞。
- **根因**：`stateStyles` 的抬起是瞬切；`OVERLAY_MOUNTED` 到 `onAppear` 之间要过一次重渲染 + 懒加载取件（首次可能动态 import）。
- **位置**：`PlayBar.ets:643-646` + `396-414`。

## 3. 优化规格

### 3.1 新时间轴（总落定 440ms）

```
                   0    110   180   240        310   380   440
几何飞行     ████████████████████████████████████████████████  0 → 520
底层压暗     ████████████████████████████████████████████████  0 → 520
页签淡出     ██░░                                          0 → 160
迷你栏内容   ███░                                          0 → 120
控制区           ██████                                      110 → 310
标题块                ██████                                 180 → 380
顶栏                      ██████                            240 → 440
```

**三条原则**

1. **内容不早于被覆盖**：某层开始淡入时，它所在的屏幕区域必须已被背景面盖住。用 `cubicBezier(0.32,0.72,0,1)` 在 520ms 上推算，控制区 110ms 起（背景已覆盖底部约 62%）、标题 180ms 起、顶栏 240ms 起。
2. **全部在几何飞行内收尾**：顶栏 440ms < 520ms。最后一层落定与飞行停住同时发生，观感是"一起停"，不是"页面停了内容还在动"。
3. **源容器先退**：迷你栏内容 120ms、页签 160ms，都在背景面盖到它们之前就消失干净。

### 3.2 P0 · 必改（收益最大，改动最小）

| 编号 | 改动 | 位置 | 旧 → 新 |
|---|---|---|---|
| **P0-1** | 几何飞行总时长 | `Constants.ts:246` | `PLAYER_TRANSITION_MS 700 → 520` |
| **P0-2** | 内容层延迟 | `InteractionConstants.ets:46-50` | `CONTROL 400→110` / `INFO 470→180` / `TOP 530→240` |
| **P0-3** | 分层入场时长（新增常量） | 同上，新增 | `LAYER_ENTER_DURATION_MS = 200`，**三个组件改用它**（`ENTRANCE_DURATION_MS=250` 全局列表共用，绝不能改） |
| **P0-4** | 迷你栏内容在打开时淡出 | `PlayBar.ets` | Body / 圆环 / 直线进度 加 `playerOpen` 门控，`120ms EaseOut` 到 opacity 0 |
| **P0-5** | 页签淡出独立时长 | `Index.ets:1364` | 新增 `@State tabFade` + `@Watch` 起 160ms `EaseOut` `animateTo` |
| **P0-6** | 底层压暗层 | `Index.ets` 根 Stack，`SubPagePlayBar` 之后、`playerOverlayMounted` 之前 | 新增 `Column`，`#000`，`opacity 0→0.26`，520ms 同曲线 |

**P0-4 的执行要点（最容易做错）**

- 用 **opacity**，不要用 `if` 卸载 —— 卸载会重排 HDS 槽位（见 `PlayBar.ets:646-649` 的警告）。
- Body 现在已有 `if (bodyVisible())` + `transition(OPACITY, 400ms)`。**不要动那两层**，在 Body 根节点上再叠一个 `.opacity(this.playerOpen ? 0 : 1)`，配 120ms 显式动画。两个 opacity 叠加，语义不冲突：一个管"收起/展开"，一个管"进播放页"。
- 圆环进度与直线进度同处理（它们也是"被盖住"的那批）。

**P0-6 的两个禁令**

- **不要给 `phoneShell` 加 `scale` / `translate`**。GT 的起点是按源锚点被祖先变换后的视觉包围盒算的，壳一缩，封面和背景面的起飞点就跟着漂 —— 会飞出"从半路起飞"的错位。只允许纯 `opacity` 层。
- 压暗层要 `.hitTestBehavior(HitTestMode.None)`，且在 `playerOverlayMounted` 为假时也要随 `playerOpen` 归零（收起动画中）。

### 3.3 P1 · 建议

| 编号 | 改动 | 做法 | 风险 |
|---|---|---|---|
| **P1-1** | 圆角起点改成真胶囊 | `PLAYER_SURFACE_RADIUS_START_VP 28 → 999` | 中。ArkUI 会把超过一半的圆角钳到 `min(w,h)/2`，理论上任意槽位高都是真胶囊。**需真机看起飞首帧四角**；若不生效就回退 28 并按断点分档（SM 28 / MD·LG 32） |
| **P1-2** | 「待命」光环消除点击空窗 | 新增 `STORE_PLAYER_ARMING`；`openPlayer` 置 true，`playEnterTransition` 闭包内置 false。PlayBar 的 `Disc()` 里加一个**不参与 GT** 的兄弟层（`border 2vp themePrimary`，`borderRadius = discSize/2`），`opacity 0→1 @90ms` | 低。不参与 GT、不改布局。**不能给 GT 源节点或其祖先加任何 transform** —— 那是硬约束 |
| **P1-3** | 抬手恢复不要瞬切 | `stateStyles` 的 `normal` 恢复改 90ms 显式 `EaseOut` | 低。但注意 opacity 会进入 GT 的透明度交叉，恢复务必在起飞前完成（≤90ms 足够） |

### 3.4 P2 · 不建议动

- **封面飞行曲线**：GT 的起点/终点插值曲线由那唯一一条 `animateTo` 决定，无法给封面单独一条（GT 必须同帧配对）。想让封面"变大更柔和"只能改全局曲线，会连累背景面，得不偿失。压短时长已经解决了 90% 的观感问题。
- **触觉反馈**：项目里没有震动封装，需要新增 `vibrator` 模块。可作为独立需求，不混进本次转场优化。

## 6. 风险清单

| 风险 | 说明 | 兜底 |
|---|---|---|
| 内容抢跑露底 | 110ms 时背景面只覆盖底部 62%，若控制区落点偏上会露底 | 真机看控制区首帧；露底就把 CONTROL 提到 130 |
| GT 起点漂移 | 任何祖先 transform 都会让起点框按变换后计算 | 压暗层只用 opacity；壳层禁止 transform |
| HDS 槽位塌陷 | 在 HDS 托管内容里由布局/挂载变化回写 @State | P0-4 只用 opacity，不卸载 |
| 收起变太"急" | 520ms 收起 + 340ms 内容柔退，尾部可能有 180ms 空等 | 若显急，把 `LAYER_EXIT_DELAY_*` 压到 0/50/100 |
| 圆角 999 不生效 | 部分版本对超半圆角钳制行为不一致 | 回退 28 / 按断点分档 |
