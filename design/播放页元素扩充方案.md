# 播放页元素扩充方案

> 2026-10-16 · 基于 `components/player/*` 与 `components/PlayBar.ets` 的真实代码盘点
> 配套必读：`memory/UI-LAYOUT.md`（UI 五条铁律 + 播放页冻结记录）、`player/MusicPlayer.ts`（可用能力清单）

---

## 〇、一句话结论

**播放页不缺「花哨元素」，缺的是「已经算出来、却没地方显示」的东西。**
内核里有 6 项能力完全没有 UI 出口（睡眠定时、队列长度、下载状态、下一首插队、听歌时长、收藏），
数据模型里有 3 个字段从未上过播放页（播放量 / 发布时间 / UP 主）。
所以第一档方案**不新增任何状态、不改布局骨架**，只是把已有数据接出来。

同时有一条**硬约束**决定了「加在哪里」：播放页竖向空间是**零和**的（见 §1.3）。

## 一、现状盘点

### 1.1 当前元素清单（SM 断点 = 手机）

```
┌─ 顶栏 TopAreaComponent ─────────────────────┐
│                                    [投播▣]   │  ← 左侧整片空白
├─ Swiper 双页（封面页 / 歌词页）──────────────┤
│ 【封面页 MusicInfoComponent】                │
│        ◯ 圆形大封面（20s/圈旋转 + 光晕）      │
│        《歌名》1 行                          │
│        歌手 1 行                             │
│        176 kbps · Hi-Res 无损（可选行）       │
│  【歌词页 LyricsComponent】                  │
│        [小封面] 歌名 / 歌手                  │
│        LrcView（平滑滚动 + 渐隐遮罩）         │
├─ 控制区 ControlAreaComponent（两页共用）────┤
│  行1：[模式]        [下载][加歌单][列表]      │  ← 4 个功能键
│  行2：进度条 Slider + 当前/总时长             │
│  行3：[上一曲]  [播放/暂停]  [下一曲]         │
└─────────────────────────────────────────────┘
```

- **顶栏只有 1 个元素**（右侧投播），宽度完全浪费。
- **控制区功能行 4 个键**：播放模式轮换 / 下载当前 / 加入歌单（menu）/ 播放队列（sheet）。
- **没有任何手势**（`CoverDiscComponent` 0 个 onClick，`PlayerInfoComponent` 0 个）。
- **没有「返回」按钮**：返回只靠系统侧滑 + `onBackPressed` 的一镜到底。

### 1.2 内核已有、UI 无出口的能力（本次方案的主要来源）

| 内核能力 | 位置 | 当前 UI 出口 | 缺口 |
|---|---|---|---|
| `setSleepTimer(minutes)` | `MusicPlayer:2225` | 只有**设置页**入口 | 开了定时后离开设置页就再也看不到剩余时间 |
| `STORE_SLEEP_TIMER_END` | `Constants:127` | 播放页**未订阅** | 全局态白放着 |
| `STORE_QUEUE` | `Constants` | 播放页未订阅（`PlayBar:146` 订阅了） | 队列键无数量角标 |
| `completedLocalPath(musicId)` | `DownloadManager:331` | 无处调用 | 下载键不区分「已下载 / 未下载」，点已下载的会 toast「已在下载队列或已下载」 |
| `playNext(track)` | `MusicPlayer:2108` | **零消费点** | 没有「下一首播放」插队入口 |
| `toggleLike(track)` | `MusicPlayer:2254` | **零消费点** | 收藏功能内核完备、界面全无 |
| `accumulateListenTime` / `flushListenTime` | `MusicPlayer:2006/2038` | 无 | 听歌时长已在算，没地方显示 |
| `setVolume` / `setMuted` | `MusicPlayer:2197/2205` | **已按用户决策删除** | ⚠️ 红线，见 §2 |
| `setShuffle` | `MusicPlayer:2193` | 由 `SHUFFLE` 模式覆盖 | 无需单独出口 |

⚠️ **`toggleLike` 零消费点这件事要单独说明**：`Track.isLiked` / `likedAt` 字段齐全、`LibraryStore` 侧逻辑齐全、`MusicPlayer.toggleLike` 实现完整，但**全仓没有任何 UI 调用它**（`TrackItem` 里也搜不到 `isLiked`）。也就是说「收藏」这条线是**半成品**：内核能存，用户没入口。

### 1.3 硬约束：竖向空间是零和的

`MusicInfoComponent.recomputeDisc()`：

```
圆盘边长 = min(列宽, 列高 − 标题块高 − 控制区高)
```

`titleH` / `ctrlH` 都是 `onAreaChange` 实测回填的，**在标题块或控制区里新增任何一行，大封面就会同比缩小**。

由此得到「加在哪里」的优先级（越靠前越安全）：

| 位置 | 空间成本 | 说明 |
|---|---|---|
| ① 顶栏右侧/左侧 | **0** | 横向整片空白，加图标不挤压任何东西 |
| ② 弹层（sheet / menu / dialog） | **0** | 不常驻，不参与布局 |
| ③ 长按 / 手势 | **0** | 无视觉节点 |
| ④ 控制区功能行（图标变多） | **0** | 行高不变，只是横向排布变密 |
| ⑤ 歌词页 | **低** | 歌词区 `layoutWeight(1)` 能吃下少量缩水 |
| ⑥ 封面页新增常驻行 | **高** | 直接缩封面，**非必要不用** |

**设计原则：能用 ①②③④ 就别用 ⑥。**

## 三、候选元素清单（按「价值 ÷ 成本」排序）

### 第一档 · 纯露出（零新增状态，推荐先做）

#### A1. 定时停止倒计时胶囊 —— **推荐度 ★★★★★**
- **是什么**：顶栏左侧出现一枚小胶囊「⏱ 28:14」，仅当 `STORE_SLEEP_TIMER_END > 0` 时渲染；点击可直接取消或重设。
- **为什么值得**：这是当前**最真实的缺口**。用户在设置页开了「30 分钟后停止」，之后完全没有任何反馈——不知道还开着、不知道剩多久、想取消还得回设置页翻。
- **数据就绪**：✅ 完全就绪。`STORE_SLEEP_TIMER_END`（绝对时间戳）已在全局；`SettingsPage:513` 已有「剩余 ms → 文案」的现成算法可复用。
- **落地要点**：`PlayerInfoComponent` 顶栏加一个 `@StorageLink(STORE_SLEEP_TIMER_END)`；1s 心跳只在这个胶囊内部（`setInterval`，`aboutToDisappear` 清理），**不要把心跳挂在整页**。
- **空间成本**：① 顶栏 → **0**

#### A2. 队列数量角标 —— **推荐度 ★★★★☆**
- **是什么**：控制区「播放列表」图标右上角一个 12×12 的数字角标，显示 `STORE_QUEUE.length`。
- **为什么值得**：现在点列表键之前完全不知道队列里有多少首；队列是 `playAll` / 列表菜单「加入队列」悄悄攒起来的，用户容易忘记自己攒过。
- **数据就绪**：✅ `STORE_QUEUE` 已在全局（`PlayBar` 都订阅了）。
- **落地要点**：角标数字用 `$r('app.color.*')` 语义 token，字号 11（铁律②允许的最小档）；**命中区仍走 `BounceIconButton` 的 40vp，不因角标变小**。
- **空间成本**：④ 控制区功能行 → **0**

#### A3. 下载键状态回显 —— **推荐度 ★★★★☆**
- **是什么**：当前曲已下载时，下载图标从「↓ 下载」换成「✓ 已下载」（并降低不透明度）；点击时 toast「已下载到本地」而不是走 `requestDownload`。
- **为什么值得**：现状是**点了才知道**——而且反馈文案「已在下载队列或已下载」把两种状态混在一起说了。已下载的曲目本该一眼看出来（对「仅 WiFi」「离线」场景尤其重要）。
- **数据就绪**：✅ `DownloadManager.completedLocalPath(musicId)` 已在；且 `Track.localFilePath` 非空本身就是「已下载」的直接证据（`Playbar` 链路已在用），**优先读它、避免同步查库**。
- **空间成本**：④ → **0**

#### A4. UP 主 + 播放量 / 发布时间行 —— **推荐度 ★★★☆☆**
- **是什么**：歌名/歌手下方的第二行小字：`UP名 · 12.3万播放 · 2023-05-12`，UP 名可点进主页。
- **为什么值得**：数据全在 `Track` 里（`upMid` / `playCount` / `pubdate`），却从未在播放页出现；`FollowsPage` 的 UP 主页已实现，链路是通的。用户「听到一首想看看是谁投的」是自然动作。
- **数据就绪**：✅ 三个字段齐；`playCount` 需要 `1.2万` 这类格式化（项目里已有类似实现可参考）。
- **⚠️ 代价**：这是**封面页新增常驻行**（⑥），会缩小大封面。若采用，建议**只在 LG / 折叠展开**显示，SM 上收进弹层。

#### A5. 歌词点击跳转 —— **推荐度 ★★★☆☆**
- **是什么**：点歌词任意一行 → `player.seek(该行时间)`。
- **为什么值得**：主流播放器标配，错过一段想重听时的第一反应。
- **数据就绪**：⚠️ `LrcEntry` 已有 `lineStartTime`，但 `LrcView` 是**自绘滚动视图、当前 0 个 onClick** → 需要给它加行级命中（`onTouch` + 行高反推索引）。属**中成本**，不算纯露出。
- **空间成本**：③ 手势 → **0**

### 第二档 · 小成本新能力（需要少量内核/组件改动）

#### B1. 倍速播放 —— **推荐度 ★★★★★**
- **是什么**：`0.5× / 0.75× / 1.0× / 1.25× / 1.5× / 2.0×`，当前值显示为胶囊「1.5×」。
- **为什么值得**：**这是当前播放页唯一一项「主流播放器都有的刚需、我们完全没有」的能力**。播客 / 长音频 / 听课时刚需。
- **缺口**：`MusicPlayer` 里搜不到任何 `playbackRate` / `setSpeed` —— **内核完全没有**。
- **落地要点**：
  1. `MusicPlayer` 加 `setSpeed(rate)` → `player.setSpeed(rate)`（`media.AVPlayer` 原生支持）；
  2. **切源后必须重设**：`switchSource*` / `ensurePlayer` 走完要重新 apply，否则换源即悄悄回到 1.0×（**这是本项目「换源」类缺陷的高发区，见 `PLAYER-KERNEL.md`**）；
  3. 新增 `STORE_PLAYBACK_SPEED` 做全局态 + 持久化，`PlayBar` 无需感知；
  4. 入口建议：**控制区功能行第 5 个图标**（④，空间成本 0），或顶栏胶囊。
- **风险**：低。唯一注意点是「变速后进度回传 / 歌词时间轴」不受影响（`STORE_PROGRESS` 走 500ms 轮询，天然无碍）。

#### B2. 屏幕常亮 —— **推荐度 ★★★★☆**
- **是什么**：播放中保持屏幕常亮（**默认关**，可在设置页或播放页开关）。也可做成纯自动：播放中常亮、暂停/退出恢复。
- **为什么值得**：全仓搜不到任何 `setWindowKeepScreenOn` —— 现在**看着歌词会自己熄屏**。
- **落地要点**：`window.getLastWindow().setWindowKeepScreenOn(bool)`；跟随 `STORE_IS_PLAYING`，`aboutToDisappear` 必须恢复（离开播放页不该继续常亮）。
- **空间成本**：0（无 UI，或设置页一个开关）。

#### B3. 「下一首播放」插队 —— **推荐度 ★★★☆☆**
- **是什么**：在队列弹层里给每条非当前曲加一个「↓ 下一首播放」次级操作。
- **为什么值得**：`MusicPlayer.playNext(track)` **已实现但零消费点**——能力白放着。
- **落地要点**：`QueueSheet` 里 `ListItem` 已有一个「✕ 移除」（28×28），可改为「右滑出两个操作」或长按菜单；注意铁律④（40vp 命中区、8vp 缓冲）。
- **空间成本**：② 弹层 → **0**

#### B4. 分享当前曲 —— **推荐度 ★★☆☆☆**
- **是什么**：复制 `https://www.bilibili.com/video/{bvid}` 到剪贴板（或调系统分享面板）。
- **为什么值得**：`bvid` 已在 `Track` 里，成本极低；「这首好听，发给你」是自然动作。
- **注意**：全仓**无任何 Share 实现**（唯一命中是歌单导入的 `ShareShortLink`，同名不同事），要用 `@ohos.systemShare` 或 `pasteboard`。建议**先做「复制链接」**，最省。
- **空间成本**：② 弹层 → **0**

### 第三档 · 体验增强（中高成本，看取舍）

#### C1. 手势体系 —— **推荐度 ★★★★☆**
- 双击封面 → 播放/暂停（标配）
- 长按封面 → 2.0× 快进（松手复原）
- 左右滑 → 切歌（⚠️ 与 Swiper 「封面页↔歌词页」的左右滑**冲突**，需明确优先级：建议滑动手势只在**封面页内部**判定为切歌，或干脆不做）
- 下滑 → 收起播放页（返回）
- **空间成本**：③ → 0。**但冲突分析必须先做**，Swiper 已在消费横向手势。

#### C2. 进度条增强 —— **推荐度 ★★★★☆**
- **缓冲进度**：底轨上叠一条浅色「已缓冲」层（`AVPlayer` 的 `bufferedDuration`）——网络差时用户能看出「是在加载还是卡了」。
- **拖动气泡**：拖动时在上方浮出「3:24」大字（现在只有左右两端时间在跳）。
- **章节/分 P 标记**：多 P 合集（`DownloadTask.partNo/partTotal` 已有）在进度条上打刻度。
- **空间成本**：④/① → 0。注意 `ControlAreaComponent` 用的是 `Slider`，而 `UI-LAYOUT.md` 明确「`SeekBar.ets` 一律自绘、不要退回 Slider」——**改之前要先确认这条铁律是否适用于播放页这个 `Slider` 实例**（播放页当前用的是内联 Slider，与 `SeekBar` 组件不是一回事，见 §6 待确认项）。

#### C3. 歌词页增强 —— **推荐度 ★★★☆☆**
- **翻译 / 音译双行**：`LyricsApi` 侧若有 `tlyric` / `romalrc` 可一并取（网易云接口常有，需核对）。
- **字号调节**：歌词大小三档。
- **歌词来源切换**：`LyricCandidate[]` 已存在 → 允许「换一个匹配」。
- **空间成本**：⑤ 歌词页 → 低。

#### C4. 听歌时长显示 —— **推荐度 ★★☆☆☆**
- **是什么**：播放页角落显示「本次已听 23 分钟」；或做成「本周听歌 4.2 小时」入口。
- **为什么可行**：`MusicPlayer.accumulateListenTime` / `finalizeListenSegment` / `flushListenTime` **已经在算并落盘**，数据现成。
- **空间成本**：①/⑥ → 0 或高。

#### C5. AB 循环 —— **推荐度 ★★☆☆☆**
- 小众但专业用户喜欢（练琴/记台词）。需在进度条上做 AB 两个把手 + 内核循环判定。**成本明显高于价值**，列在此备选。

#### C6. 动态封面 / 律动
- 视频背景（B 站是视频站，`videoUrl` 现成）或封面随节拍呼吸（需 FFT 分析音频）。
- **成本高、耗电、与「克制」的既有动效风格冲突**（大封面已经是 20s/圈的旋转）。**不推荐**。

## 五、三个必须先确认的问题

### 5.1 「收藏」到底要不要？
`MusicPlayer.toggleLike` 已实现、`Track.isLiked`/`likedAt` 已落盘、`LibraryStore` 侧逻辑齐全，但**全仓零 UI 调用**；而控制区注释写「按用户决策不引入收藏 / 静音按钮」。
→ **二选一**：① 维持无收藏（那 `toggleLike` 是死代码，可考虑标注）；② 加回来（成本极低，控制区功能行加一个红心即可）。
**这是本方案里唯一「有现成能力但可能被明确否决」的项，必须先问。**

### 5.2 「更多 ⋯」弹层能否以新形态回归？
第二档/第三档的元素加起来有 6~8 个，**功能行塞不下、顶栏也塞不下**。业界通用解法就是**一个「更多」底部弹层**——而那正是被删掉的结构。
→ 建议：**不是恢复旧的（模式四选一 + 音量），而是新建一个内容不同的弹层**（倍速 / 定时 / 常亮 / 分享 / 歌词字号 …）。但既然形态撞上了被删物，**需要先确认**。

### 5.3 播放页「冻结」是否正式解除？
`UI-LAYOUT.md` 记着「播放页全家桶用户明确要求不动」。本次扩充必然要动 `components/player/*`。

## 六、待核查项（落地前必须验证，勿凭记忆下判）

1. **`media.AVPlayer.setSpeed` 在 API 26 的可用性**与取值范围（`0.125 ~ 4.0` 需查 d.ts 确认）。
2. **`setWindowKeepScreenOn` 的调用时机**：必须在 `window` 就绪后，且 `aboutToDisappear` 恢复；需确认与 `ignoreLayoutSafeArea` 共存无副作用。
3. **播放页那个 `Slider` 是否算「进度条铁律」的适用范围**：`UI-LAYOUT.md` 说的是 `components/SeekBar.ets`（自绘），而播放页用的是**内联 `Slider`**。两者是不同实现 → 改进度条前先确认，别误伤。
4. **`playCount` / `pubdate` 的覆盖率**：`Track` 注释说「音乐中心结构里没有 mid」「`pubdate` 0 = 未知（音乐中心、升级前存量）」。→ 若做 A4，**必须处理 0 值不显示**，否则会出现「0 播放」。
5. **切源后倍速是否被重置**：这是本项目换源链路的老坑，B1 落地后必须真机验证「换源 → 倍速是否还在」。
6. **`LyricsApi` 是否返回翻译/音译**（决定 C3 是否可行）。
