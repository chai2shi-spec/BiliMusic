# 播放页进场动效优化方案（2026-10-03 · **方案 A 已实现并编译通过**）

> 需求：优化「点击 PlayBar 进入播放页」的动画。
> 本文所有参数都取自真实代码，方案里的每个数值都标了出处。
> 相关分册：`PLAYER-KERNEL.md`（播放内核）、`UI-LAYOUT.md`（底栏与播放页结构）。

---

## 一、现状核实：现在其实是**三套动画在同时跑**

点展开态的 PlayBar 条目 → `PlayBar.gotoPlayer()`（`components/PlayBar.ets:217`）：

| # | 动画 | 实现 | 时长 | 曲线 |
|---|---|---|---|---|
| ① | 路由推进 | `animateTo` 闭包内 `pushPath('Player')`，驱动 **geometryTransition** | `PLAYER_TRANSITION_MS` = **300ms**（`Constants.ts:51`） | `EaseInOut` |
| ② | 整页升起淡入 | `PlayerPage.customTransition`（`pages/PlayerPage.ets:88`）：`translate y 128 → 0` + `opacity 0 → 1` | `ENTER_DURATION` = **360ms** | `Curve.Friction` |
| ③ | 封面旋转延迟 | `STORE_PLAYER_TRANSITIONING` 置位，转场结束后复位（`PlayerPage.ts:66`） | 300ms | — |

共享元素 id：`GEOMETRY_ID_PLAYER_DISC = 'player_cover'`（`Constants.ts:49`），
挂在 `PlayBar.ets:238/286` 与 `CoverDiscComponent.ets:146`。

### 四个真问题（都能从参数直接算出来）

1. **时长不一致 → 落位错位 60ms**
   封面 300ms 到位，页面 360ms 才落 → 有 60ms「封面已经停住、整页还在往上飘」的窗口，
   视觉上像**两个东西没对齐**。
2. **曲线不一致 → 起步手感打架**
   ① 用 `EaseInOut`（两端慢中间快），② 用 `Friction`（起步快、落位慢）。
   两者叠加，起步与收尾的加速度都对不上。
3. **整页位移会污染共享元素的起止位置**
   页面初始 `translate y = 128`，意味着**封面的目标框也在下方 128vp**。
   于是封面从迷你条位置飞到「下方 128vp 的目标位」，再随整页上移 128vp 归位 ——
   运动轨迹是**先下后上**的弧线，而不是直线。这是最容易让人察觉「哪里不对」的一处。
4. **进场有动画、返回没有**
   返回走 `onBackPressed`（`PlayerPage.ts:108`）→ `animateTo` + `pop(false)`，
   **只有封面缩小，页面没有任何位移/淡出** → 进出不对称，返回像「突然消失」。

另有一个隐患：`gotoPlayer()` **没有重复点击防护**（`STORE_PLAYER_TRANSITIONING` 只用于旋转延迟），
连点可能 push 两次。

### 两条进入路径要分清
- **折叠态**点迷你条封面 → `onExpandRequest` → `applyMiniBarStyle(EXPAND)`（先展开，不进播放页）
- **展开态**点条目 → `gotoPlayer()` → 进播放页 ← **本轮优化的对象**

## 二、方案 A · 时序对齐 ✅ 已实现（CompileArkTS Finished / BUILD SUCCESSFUL，ERROR 0）

**思路**：不增加新元素，只把上面三套动画**收成一套**——统一时长与曲线、把整页位移压小、返回补上对称动画。

| 项 | 现状 | 改为 |
|---|---|---|
| 页面进场时长 | 360ms（`ENTER_DURATION`） | **300ms**，与 `PLAYER_TRANSITION_MS` 一致 |
| 页面进场曲线 | `Curve.Friction` | **`Curve.EaseInOut`**（与 ① 一致） |
| 整页位移 `ENTER_RISE` | 128vp | **48vp**（够读出「从下往上的方向」，又不至于让共享元素轨迹弯成弧） |
| 页面透明度 | 0 → 1 | 保持（淡入是廉价且有效的） |
| 返回 | 只有封面缩小 | 加**同参数的镜像**：页面 `translate y 0 → 32vp` + `opacity 1 → 0`，240ms，EaseInOut |
| 重复点击 | 无防护 | `gotoPlayer()` 开头判 `STORE_PLAYER_TRANSITIONING`，为真则直接 return |

**改动文件**：`pages/PlayerPage.ets`（`ENTER_RISE` / `ENTER_DURATION` / 返回分支）、`components/PlayBar.ets`（点击防护）。

**风险**：低。全部是既有属性调参 + 一个返回分支。
**注意**：`ENTER_DURATION` 改了以后，`scheduleTransitionEnd()` 里那个 `PLAYER_TRANSITION_MS` 的定时器
要与实际进场时长一致，否则 `STORE_PLAYER_TRANSITIONING` 复位晚了，封面旋转会被多压 60ms（能感觉到「转完才开始转」）。

## 三、方案 B · 分层错峰 ✅ 已实现（CompileArkTS Finished / BUILD SUCCESSFUL，ERROR 0）

**思路**：页面整体只做**淡入**（位移交给元素自己），内部 5 个子组件按层级依次浮现。
播放页本来就拆得很干净（`TopAreaComponent` / `CoverDiscComponent` / `MusicInfoComponent` /
`ControlAreaComponent` / `LyricsComponent`），错峰不用新增容器。

**进场时序**（`animateTo` + `delay` 驱动，参数直接复用工程现成的错峰体系
`InteractionConstants.ets` 的 `ENTRANCE_OFFSET_VP=10` / `ENTRANCE_DURATION_MS=250` / `ENTRANCE_STAGGER_MS=35`）：

| 层 | 元素 | 延迟 | 动作 |
|---|---|---|---|
| 0 | 沉浸背景（主色 + 模糊封面） | 0ms | 纯淡入 0 → 1，**不位移** |
| 1 | 大圆盘封面 | 0ms（与 geometryTransition 同步） | 只做缩放 0.92 → 1，不动 translate |
| 2 | 歌名 / 歌手 | 封面落位后 **+90ms** | translate 10vp → 0 + 淡入 |
| 3 | 进度条 + 时间 | +150ms | 同上 |
| 4 | 控制区（播放/上下曲/收藏） | +210ms | 同上，末位最多不超过 300ms |
| 5 | 歌词页（Swiper 第二页） | 滑动到才动 | 保持现状（Swiper 自身动画） |

**返回**：**逆序**退场（控制区先退 → 进度条 → 歌名 → 封面最后缩小），总时长压到 240ms，
比进场快（进场 300ms / 退出 240ms 是常见节奏，退出更利落）。

**为什么值得做**：现在整页一起淡入，5 个元素「同时出现」，信息没有先后；
错峰之后视线自然按「封面 → 歌名 → 进度 → 控制」的顺序落位，和用户的信息优先级一致。

**改动文件**：`PlayerPage.ets`（整页改为纯淡入）+ `PlayerInfoComponent.ets` 及其 4 个子组件
（各自加 `@State` 起始位移/透明度 + `aboutToAppear` 触发）。
⚠️ **必须注意 ArkUI 的两条硬规则**（都踩过）：
- 子组件的动画状态要用 `@State`（普通成员只在创建时初始化一次，父组件重渲染不再赋值）；
- `translate` / `opacity` 只能动 transform 系属性，**不许改 width/height/padding**（触发整树重排）；
- `CoverDiscComponent` 上已挂 `geometryTransition` 与 `rotate`，**不要再往同一节点叠 translate**
  （会与共享元素转场抢）→ 错峰要加在**它的父容器**上。

**风险**：中。主要是「共享元素 + 父子动画」的叠加顺序需要真机逐层调。
**收益**：明显。这也是唯一能让「播放页看起来像精心设计过」的一档。

## 四、方案 C · 形变替代（视觉最强，风险最高）

**思路**：不再让整页升起，而是**让迷你条所在位置「展开」成全屏**——迷你条变成页面底板，
封面从迷你圆盘放大到中心大圆盘（保留 geometryTransition），其余内容在板到位后淡入。

实现要点：
1. 播放页根节点用一个**从迷你条位置出发的圆形/圆角矩形遮罩**做 clip-path 或 scale 展开
   （起点取 `STORE_SAFE_BOTTOM` 与胶囊位置的连线，见 `UI-LAYOUT.md` 的底栏几何）；
2. `geometryTransition` 保留（封面仍是一镜到底的核心）；
3. 内容层去掉所有位移，只做 120ms 淡入；
4. 返回反向收回。

**为什么没把 C 排第一**：
- 迷你条在**底栏 HdsTabs 融合胶囊内**（左半区），它不是一个独立浮层，
  「展开成全屏」要么动底栏（锁定区，`UI-LAYOUT.md` 明令不许改），要么做一层假的遮罩
  —— 后者会与真实底栏在转场瞬间「重影」；
- 展开动画与 `geometryTransition` 都会改封面几何，处理不当会出现**封面先被遮罩盖住再飞出**。

**风险**：高。收益是三者里视觉最强的，但性价比最低。
**建议**：等 A、B 落地并真机验证稳定后，再评估要不要做 C。

## 五、推荐投递顺序

1. **方案 A**（时序对齐 + 返回对称 + 点击防护）→ 编译 + 真机。**这一档就能消掉「错位 60ms」和「返回突然消失」两个最扎眼的问题**。
2. **方案 B**（分层错峰）→ 需要逐层调 delay，建议一次只加 2 层（先 2+3，再 4），真机确认不抢共享元素。
3. **方案 C** 暂不做，除非 A/B 都稳了且你想要更强的视觉冲击。

## 六、真机必须验的 5 项（编译过 ≠ 看着对）

1. **轨迹是不是直线**：盯着封面从迷你条飞到中心大圆盘，途中不该有「先往下再往上」的拐弯。
2. **落位是否同帧**：封面停住的那一帧，整页也该停住（现在差 60ms，是最明显的破绽）。
3. **返回是否对称**：返回时页面应有轻微下沉淡出，而不是「封面缩小 + 页面瞬间消失」。
4. **连点**：快速连点 PlayBar 三次，只应进一次播放页。
5. **旋转衔接**：封面到位后唱片开始转的时机要跟手（`STORE_PLAYER_TRANSITIONING` 复位过早/过晚都会显得「转早了/转晚了」）。

### 三个「当时不确定、只能真机验」的地方（已实施，等你反馈）
1. **`pop(false)` → `pop()` 是本轮风险最高的一处**。`false` 会把**页面自己的 customTransition 一起关掉**
   （自定义转场顶替的就是系统默认转场），所以原先 POP 分支根本不会执行，整页「瞬间消失」。
   改成 `pop()` 后退场由自定义转场接管。**若真机上出现「返回时封面不动 / 转场卡住」，
   第一嫌疑就是这里** —— 回滚点：把 `pop()` 改回 `pop(false)`，同时删掉 customTransition 的 POP 分支。
2. **退场动画为什么不能写在 `onBackPressed` 里**：`pop()` 之后页面立即销毁，手写的退场动画来不及显示；
   而 `animateTo` **没有 finish 回调**（SDK 签名只有 `(value, event)` 两个参数），无法「等动画完再 pop」。
   → 只能交给 `customTransition` 由系统在页面存活期间驱动。
3. **连点防护复用了 `STORE_PLAYER_TRANSITIONING`**：它在进场（`aboutToAppear` 置位）与返回
   （`onBackPressed` 置位）期间都为真，正好覆盖「转场中」这个窗口，不需要额外状态。

### 真机验证（对着上一节的 5 项，第 1、3 项重点看这轮的变化）
1. 封面轨迹是**直线**（位移从 128 降到 48 的直接效果）；
2. 封面与整页**同帧落位**（时长统一到 300ms 的效果）；
3. **返回是镜像下沉淡出**（新加的 POP 分支，若没生效就是第 1 条那个回滚点）；
4. 连点 PlayBar 三次只进一次；
5. 封面到位后唱片起转的时机（`scheduleTransitionEnd` 已与 `ENTER_DURATION` 对齐）。

## 落地记录 · 方案 B（2026-10-03 21:57）

编译：`CompileArkTS Finished after 18.8 s` + `BUILD SUCCESSFUL`，ArkTS ERROR 0。

### 实施前的两处计划修正（与上一节写的不同，以这里为准）
1. **封面层不参与错峰**（原计划写「只做缩放 0.92 → 1」）。
   原因：`CoverDiscComponent` 的 `geometryTransition` 挂在内部 `Image` 上，若给父 `Stack` 叠 scale，
   转场目标框会按**动画中途的缩放值**计算 → 封面落位后还会「再弹一下」。
   封面的形变交给 `geometryTransition` 独占，分层从「歌名」开始。
2. **返回不做子组件逆序退场**（原计划写「逆序」）。
   原因：逆序需要页面把「正在退出」广播给 4 个子组件（多一份状态同步），
   而整页淡出时子组件本来就会跟着一起淡 —— 收益小、复杂度高。
   退场仍由 A 方案的整页下沉淡出（240ms）负责。

### 实际分层
| 层 | 组件 | 延迟 | 动作 |
|---|---|---|---|
| 0 | `TopAreaComponent`（投播） | 0ms | **只淡入**（顶栏上下位移会像「掉下来」，与整页方向相冲） |
| — | `CoverDiscComponent` | — | **不参与**，形变归 `geometryTransition` 独占 |
| 1 | `MusicInfoComponent` 的标题块（歌名/歌手） | 90ms | 位移 10vp → 0 + 淡入 |
| 2 | `ControlAreaComponent` | 210ms | 位移 10vp → 0 + 淡入 |
| — | 整页 | 0 | `ENTER_RISE` 48 → **0**，只保留淡入 |

位移/单层时长复用既有 `ENTRANCE_OFFSET_VP`(10) / `ENTRANCE_DURATION_MS`(250)；
三个延迟常量新增在 `common/constants/InteractionConstants.ets`（`LAYER_DELAY_TOP/INFO/CONTROL`），
集中定义便于真机微调。

### 落点选择（都是「封面之外的容器」）
- 标题块：`MusicInfoComponent` 里包 `this.MusicInfo()` 的那个 `Column`（本来就为了测高包了一层）；
- 控制区：`ControlAreaComponent` 的根 `Column`；
- ⚠️ 两个入场状态都用 `@State`（普通成员只在创建时初始化一次，父组件重渲染不重新赋值）；
- 延迟统一用 `animateTo({ delay })`，**不用 setTimeout**（少一个要清理的定时器）；
- 只挂 `opacity` / `translate`，不动 width/height/padding。

### 真机验证（重点看这三条）
1. **封面轨迹是纯直线**（`ENTER_RISE=0` 的直接效果，方案 A 的 48 也已把弧度压小）；
2. **三个层次是否看得见**：封面先落 → 歌名 → 控制区。若某层「抢戏」（提前出现或跳变），
   把它的 `LAYER_DELAY_*` 调 0 或摘掉即可（常量集中，改一行）；
3. **封面落位后有没有「再弹一下」**——若出现，说明误在 `CoverDiscComponent` 上加了动画
   （本轮没加，若你手改过优先回查这里）。
