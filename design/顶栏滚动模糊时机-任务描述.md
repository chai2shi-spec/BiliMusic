## 一、问题（用户原话）

> 「条目要**移出**屏幕后，顶部导航栏才开始渐进模糊。有没有办法**当条目向上移动到顶部导航栏时就开始模糊**？」

期望观感：列表条目**顶边刚触到标题栏底缘那一刻**，顶栏就该开始出雾；
再往上滑一点点（列表页 20~30vp 量级）就完全显影。而不是「条目已经滑过去/看不见了才出雾」。

## 二、现状事实（已核实到行号，**别凭印象改**）

### 2.1 顶栏样式是集中配置的

`entry/src/main/ets/utils/HdsTitleBarStyle.ets` 的 `HdsTitleBarStyle.styleOptions(): TitleBarStyleOptions`
是**全站唯一**的标题栏样式来源，8 个已迁移子页都从它取：

```
AboutPage:284 / FollowsPage:554 / LoginPage:382 / PlaylistDetail:635 /
RecentPage:340 / SmsLoginPage:622 / UpSpacePage:1104 / WatchHistoryPage:1122
```

它分两条路：

| 分支 | 触发条件 | 现在设了什么 |
|---|---|---|
| **沉浸档**（主路） | `MaterialCompat.supportsImmersiveMaterial() === true` | `scrollEffectOpts{ enableScrollEffect:true, scrollEffectType: IMMERSIVE_GRADIENT_BLUR }` + `thermoCtrl:true` + `systemMaterialEffect{ IMMERSIVE, EXQUISITE }` |
| **兜底档** | 不支持 / 探测异常 | `scrollEffectOpts{ ..., scrollEffectType: GRADIENT_BLUR }` + `thermoCtrl:true` + `originalStyle{ backgroundStyle{ backgroundColor: header_glass_tint, blurRadius:40 } }` + `scrollEffectStyle{ 同上 }` |

### 2.2 ⚠️ 两个决定性参数**全仓一处都没设**

```
grep -rn "blurEffectiveStartOffset\|blurEffectiveEndOffset" entry/src/main/ets   → 0 处
```

→ 全部走 SDK 默认值。SDK 注释（`sdk/default/hms/ets/api/@hms.hds.hdsBaseComponent.d.ets`，
`ScrollEffectOptions` 段）原文：

- `blurEffectiveStartOffset`：**default is `LengthMetrics.vp(0)`**
- `blurEffectiveEndOffset`：*"When the content area's total scroll offset exceeds this value,
  the title bar's dynamic style transition finishes."* 默认值按类型分：
  - `COMMON_BLUR` → **8vp**
  - `GRADIENT_BLUR` → **8vp**（6.0.0(20) 起）
  - `GRADUAL_BLUR` → **56vp**
  - `IMMERSIVE_GRADIENT_BLUR` → **56vp**（6.1.0(23) 起）
  - 另：*"If the value is set to be less than blurEffectiveStartOffset, it will be processed
    according to the default value."*

### 2.3 ⚠️ 沉浸档**没有** `originalStyle` / `scrollEffectStyle`

只有兜底档设了这两个「滚动前 / 滚动后」的样式端点。沉浸档只设 `scrollEffectOpts` +
`systemMaterialEffect` —— 也就是说：**动态样式线性过渡没有显式端点**，端点由 HDS 内部决定。

### 2.4 让位方式（决定几何关系，别乱改数值）

| 页面类型 | 让位做法 |
|---|---|
| 列表页（Recent / PlaylistDetail / UpSpace / WatchHistory / Follows） | `List.contentStartOffset(barTotalHeight())` |
| `Scroll` 页（About / Login / SmsLogin） | `Scroll.padding({ top: safeTop + NAV_TITLE_BAR_HEIGHT })` |
| 非列表分支（骨架 / 空态 / 失败态） | `padding({ top: barTotalHeight() })` |

`barTotalHeight()`（以 `RecentPage:53` 为例）：
```
safeTop + NAV_TITLE_BAR_HEIGHT(56) + (条带高度，如 RECENT_ACTIONS_ROW_HEIGHT = 44)
```
→ **「条目顶边从静止位置走到标题栏底缘」所需的滚动距离**
`delta = barTotalHeight() − (safeTop + 56)` ＝ **条带高度**：
- 单行栏页（About / Login / SmsLogin / Settings 类）→ **delta = 0**
- RecentPage（有按钮行）→ **delta = 44vp**
- PlaylistDetail / UpSpace（有封面/资料头部条带）→ delta = 头部条带高度（可能上百 vp）

### 2.5 其它已知点

- 全部 8 页都已 `.bindToScrollable([scroller])`（绑定本身没问题）。
- **全仓没有一处 `clip(false)`**（`grep clip(` 可复核）。
- 真机结论（写在 `AboutPage:274-283` 注释里）：`avoidLayoutSafeArea: true` 必须开；
  **`enableComponentSafeArea: true` 会杀掉材质**（内容被推出栏外、栏后无内容可采样），已禁用。
- 当前**无真机**（`hdc list targets` 为空）。

## 三、官方口径（改造前先对齐语义）

华为开发者官方博客《让 HdsNavigation 标题栏实现毛玻璃效果的技巧》原文要点：

> `blurEffectiveStartOffset` 和 `blurEffectiveEndOffset` 这两个参数控制模糊效果的**触发区间**：
> - `blurEffectiveStartOffset`：内容从这个位置开始触发模糊
> - `blurEffectiveEndOffset`：内容滚到这个位置时，模糊效果完全生效
>
> 单位用 `LengthMetrics.vp()` 来设。比如 **start=0, end=20** 意味着内容一滚动就开始模糊，
> 滚 20vp 后完全模糊；**start=0, end=80** 则是一个更缓慢的过渡过程。
>
> 调参建议：
> - **列表型页面：end 给 20~30vp，快速响应**
> - 图文型页面：end 给 60~80vp，缓慢过渡更有质感
> - 不确定给多少：先给 40vp，跑起来看效果再调

同文「踩坑记录」：
> - 坑一：模糊效果没生效 —— 最常见的原因是**忘了设 `clip(false)`** 或者忘了 `bindToScrollable`。
>   两个都设了，模糊才会生效。
> - 坑二：滚动时标题栏闪烁 —— 如果 `originalStyle` 与 `scrollEffectStyle` 的背景色差异太大
>   （比如从完全透明到纯白），某些设备上会闪烁。建议初始背景用**半透明色**
>   （如 `#10FFFFFF`，几乎透明但有一点底色）而不是完全透明。

⚠️ 官方博客还称「`enableComponentSafeArea` 要设成 true，否则内容区会从标题栏底部开始、
没有穿透的机会」—— **这与本工程真机结论冲突**（见 2.5）。**不许盲改**，见第五、六节。

## 四、根因假设（按可能性排序，**每条都要能验证**）

### H1（最可能）：过渡窗口没和几何对齐 + 沉浸档没给样式端点

- 默认 `end = 56vp` 是「从滚动起点算的滚动距离」，而本工程用 `contentStartOffset` 让位，
  **静止时条目根本不在栏下**，要滑 `delta` vp 才够到栏底缘。
- 沉浸档又没给 `originalStyle` / `scrollEffectStyle`，HDS 用自己的内部端点 —— 于是「什么时候开始出雾、
  出到什么程度」都不在我们手里，观感就变成用户描述的「条目都过去了才出雾」。
- **验证**：见第五节 Step 1 的 offset 日志 + 录屏对照。

### H2：`clip(false)` 缺失导致内容没真正「穿透」到标题栏之下

- 官方明确把 `clip(false)` 列为「模糊不生效」的第一大原因；本工程一处没设。
- 若内容在栏底缘被裁掉，标题栏内部就没有可采样的内容 → 模糊只能在更晚的时候才「有的可糊」。
- **验证**：在内容容器（`HdsNavDestination` 内的根 `Stack` / 列表父容器）加 `clip(false)`
  后真机对比同一段滚动距离下的出雾程度。

### H3：`blurStrategy` 未显式指定

- 默认 `ADAPTIVE`（由系统策略决定），可能造成「有时糊有时不糊」「起糊点漂移」。
- `BlurStrategy.ENABLE = 0 / DISABLE = 1 / ADAPTIVE = 2`。可试 `ENABLE` 看是否更确定。
- **验证**：切 `ENABLE` 对比。

### H4：`contentStartOffset` 是否影响 scroller 上报的初始 offset

- 若 HDS 用的「内容区滑动距离」不是原始 offset、而是「内容没入标题栏的深度」，
  那正确做法是让 `start` 取 `delta`（条带高度），而不是 0。
- **验证**：Step 1 的日志里同时打印 `currentOffset().yOffset` 与肉眼起糊时刻，反推 HDS 用的是哪个量。

## 五、改法（描述，不写实现）

### Step 1 —— 先加可观测性（**必须先做，不许跳过**）

在 `HdsTitleBarStyle` 相关页面绑定的 scroller 上，于滚动回调里打日志：

```
[TopBar] page=Recent offset=<currentOffset().yOffset> state=<ScrollState>
```

（`console.info` 即可，真机用 `hdc shell hilog | grep TopBar` 检索。）
慢速手滑，**录屏**，事后对照帧找出「肉眼开始出雾」的那一刻对应的 offset 值，记下 `X`。
对照几何量 `delta`：
- 若 `X ≈ 0` → 过渡窗口本身没问题，问题在 H2/H3（穿透或策略）。
- 若 `X ≈ delta` 或更大 → 就是窗口对齐问题，按 Step 2 设参数。
- 若 `X` 远大于 56vp → 说明 HDS 用的不是原始 offset（H4），需要按「没入深度」重算。

### Step 2 —— 在 `HdsTitleBarStyle.styleOptions()` 里显式给出全部四个字段（**两条分支都要**）

目标口径：

```
blurEffectiveStartOffset = LengthMetrics.vp(start)
blurEffectiveEndOffset   = LengthMetrics.vp(start + span)
```

- **`start`** = 「条目顶边触到标题栏底缘」那一刻的滚动距离。
  - 若 HDS 用原始 offset（H4 不成立）：`start = delta`（条带高度；单行栏页为 0）。
  - 若 HDS 用「没入深度」：`start = 0`。
  - **以 Step 1 实测为准**，不要猜。
- **`span`** = 完全显影所需距离。按官方建议：
  - 列表页（Recent / PlaylistDetail / UpSpace / WatchHistory / Follows）→ **20~30vp**
  - `Scroll` 图文页（About / Login / SmsLogin）→ **40~60vp**
- 沉浸档**必须补上** `originalStyle` / `scrollEffectStyle`（现在完全没设）：
  - `originalStyle.backgroundStyle.backgroundColor` 用**半透明色**（官方坑二：别用全透明，会闪烁），
    例如现有 token `header_glass_tint` 或 `#10FFFFFF` 量级；
  - `scrollEffectStyle.backgroundStyle.backgroundColor` 用较实的玻璃底色；
  - 两者差异**不要太大**。
- 兜底档本来就有这两个样式，只需补上 `start` / `span`。
- 建议同时把 `blurStrategy` 显式设为 `BlurStrategy.ENABLE` 做对比实验。

### Step 3 —— 参数矩阵真机对照（每次只改一个变量）

| 组 | start | span | 目的 |
|---|---|---|---|
| A | `delta` | 20 | 目标形态（列表页） |
| B | `delta` | 8 | 更快响应 |
| C | 0 | 20 | 对照：是否 HDS 用原始 offset |
| D | `delta` | 20 + `clip(false)` | 验证 H2 |
| E | A + `blurStrategy: ENABLE` | — | 验证 H3 |

每组都录屏，记录「起糊时刻的 offset」与「完全显影时刻的 offset」，与几何量对齐后选定。

1. **BUILD SUCCESSFUL**，ArkTS ERROR = 0（编译方法见第八节）。
2. **真机**慢速手滑：条目顶边**刚碰到标题栏底缘**时开始出雾，再滑 ≤30vp 完全显影；

## 七、红线（不许做的事）

- ❌ **不改 `contentStartOffset` / `barTotalHeight()` 的数值** —— 那是布局让位，
  改了首项会被标题栏遮住（历史上踩过：`contentStartOffset` 初值必须为 0 + 列表挂载门控）。
- ❌ 不给标题栏加纯色背景 / 不链式覆盖 `backgroundColor`（会盖掉材质）。
- ❌ 不做「为了出雾效果把 `enableComponentSafeArea` 打开」的尝试**除非单独一批验证**：
  本工程真机复现过它会杀材质，官方博客却说要开 —— 属**已知冲突**，谁对只能各自真机复现，
  且必须有回退。
- ❌ 不删兜底分支，不动 `MaterialCompat.supportsImmersiveMaterial()` 的探测逻辑。
- ❌ 不一次性全量改 8 个页面 —— 先在 `RecentPage`（有 44vp 条带，几何量最典型）验证，
  再铺开；`AboutPage`（纯 `Scroll`、delta=0）作为第二个对照。
- ❌ 不同时改多个变量（参数、`clip`、`blurStrategy` 要一组一组试）。
